# 테스터 업데이트 안내 양식

이 파일은 실제 배포 기록이 아닙니다. 앱 배포 때 테스터에게 보낼 업데이트 안내(패치노트) 초안을 쓰는 양식과 규칙입니다.
[배포 절차](../release-process.md#배포-준비)에 따라 배포 담당자가 초안을 쓰고, 사용자 승인을 받은 문구를 후보 기록의 `테스터 안내` 절([배포 기록 양식](TEMPLATE.md#테스터-안내))에 남깁니다.

보낼 곳은 셋이며 양식은 둘입니다.

| 보낼 곳 | 양식 |
| --- | --- |
| 오픈채팅방 | [오픈채팅방 공지](#오픈채팅방-공지) |
| TestFlight '테스트할 내용'(What to Test) | [스토어 짧은 안내](#스토어-짧은-안내) |
| Play 출시 노트 | [스토어 짧은 안내](#스토어-짧은-안내) |

## 오픈채팅방 공지

순서는 고정입니다. 해당 항목이 없는 절(예: 새로 생긴 것 없음)은 통째로 뺍니다.

```text
[허투루 X.Y.Z 업데이트 안내] YYYY-MM-DD

🆕 새로 생긴 것
- (CHANGELOG `추가` 항목, 한 줄씩)

🔧 고친 것
- (CHANGELOG `개선`·`수정` 항목, 한 줄씩)
제보 감사합니다 🙏

📲 업데이트 방법
- Android: Play 스토어에서 허투루 → 업데이트
- 아직 안 보이면 몇 시간 뒤에 다시 확인해 주세요.

💬 사용하면서 불편한 점이나 좋았던 점이 있으면 이 방에 편하게 남겨 주세요!
```

- 날짜는 공지하는 날(KST)입니다.
- CHANGELOG `개선` 항목도 `🔧 고친 것`에 넣습니다. 절을 더하지 않습니다.
- "제보 감사합니다 🙏"는 `🔧 고친 것` 절에 테스터 제보로 고친 항목이 하나라도 있을 때만, 그 절 끝에 한 번 둡니다.
  제보는 오픈채팅방 제보와 팀 피드백 시트 줄을 모두 포함합니다.
- 오픈채팅방에는 Android 테스터만 있습니다. 그래서 `📲 업데이트 방법`에는 Android 줄만 두고,
  `[iOS]`만 붙은 항목은 넣지 않습니다. 줄 끝에 플랫폼 표시를 붙이지 않습니다.
- iOS만 배포할 때는 오픈채팅방 공지를 하지 않습니다.

## 스토어 짧은 안내

TestFlight '테스트할 내용'과 Play 출시 노트에 같이 씁니다.

```text
X.Y.Z 업데이트
- (가장 눈에 띄는 변화)
- (그다음 변화, 필요하면 두 개를 한 줄로 묶음)
- (그다음 변화)
```

- 제목 줄을 포함해 2–4줄입니다. 변화가 많으면 묶거나 덜 눈에 띄는 것을 뺍니다(뺀 내용은 오픈채팅방 공지에 있습니다).
- 이모지·"제보 감사합니다"·업데이트 방법·제보 안내는 넣지 않습니다. 스토어 화면 자체가 업데이트 화면입니다.
- 두 스토어에 같은 문구를 씁니다. 단, 한 플랫폼에만 해당하는 항목은 그 플랫폼 안내에만 넣습니다.

## 변환 규칙

원본은 [변경 이력](../../CHANGELOG.md)에서 해당 버전의 `## 앱 X.Y.Z` 절 하나입니다. `미배포`나 다른 버전 절에서 가져오지 않습니다.

넣을 것

- 테스터가 앱에서 보거나 느낄 수 있는 변화: 새 메뉴·화면, 바뀐 동작, 고쳐진 오류.

뺄 것

- `[서버]` 항목. `## 앱 X.Y.Z` 절에는 원래 서버 항목이 없습니다(서버는 `backend-…` 절).
  앱 항목이 서버 변경에 기대는 경우에도 앱 항목 문장만 쓰고 서버 절은 보지 않습니다.
- 서버만 바뀌었지만 테스터가 느끼는 변화. 앱 업데이트 없이 이미 반영된 변화라 업데이트 안내와 맞지 않습니다.
- 내부 정리, 화면 낭독기 이름처럼 대부분의 테스터가 느끼지 못하는 변화.
  단, 화면 낭독기·글자 크기 관련 변화가 그 항목의 핵심이면 한 줄로 쉽게 씁니다.
- 이슈 번호, 팀 시트 번호, 응답 코드(404·413 등), 파일·패키지 이름, 디자인 수치(17px 등), 영어 서버 문구 원문.
- 아직 제공되지 않는 기능, 그 플랫폼에 해당하지 않는 항목.

문체

- 해요체로, 한 항목을 한 줄(길어도 두 줄)로 씁니다. 테스터가 화면에서 보는 이름은 작은따옴표로 씁니다(예: '최근 다시 본 콘텐츠').
- "…문제를 고쳤어요", "…가 생겼어요", "…로 바뀌었어요"처럼 결과를 씁니다. 원인·구현 설명은 쓰지 않습니다.
- CHANGELOG에 없는 내용을 새로 지어 넣지 않습니다.

## 글자 제한

2026-11-14에 조회했습니다.

| 자리 | 제한 | 출처 |
| --- | --- | --- |
| Play 출시 노트 | 언어마다 유니코드 500자 | [Play Console 고객센터 "Prepare and roll out a release"](https://support.google.com/googleplay/android-developer/answer/9859348): "You can enter release notes using up to 500 Unicode characters per language." |
| TestFlight '테스트할 내용' | 공식 제한 미확인 | Apple 공식 문서(App Store Connect 도움말 "Provide test information", App Store Connect API `BetaBuildLocalization`의 `whatsNew`)에서 글자 수 제한을 찾지 못했습니다. |

스토어 짧은 안내는 2–4줄이라 어느 쪽이든 수백 자 이하입니다.

## 만드는 순서

1. 배포 담당자가 앱 후보를 준비하면서 CHANGELOG를 `## 앱 X.Y.Z`로 옮긴 뒤, 이 문서의 규칙으로 오픈채팅방 공지와 스토어 짧은 안내 초안을 씁니다.
2. 초안을 후보 기록의 `## 테스터 안내` 절에 넣고, 원문을 사용자에게 보여 승인을 받습니다.
3. 사용자가 고친 문구가 있으면 후보 기록을 최종 문구로 고칩니다. 실제로 보낸 문구는 이 절에만 남기고 별도 파일을 만들지 않습니다.
4. 게시(오픈채팅방, TestFlight '테스트할 내용', Play 출시 노트 입력)는 사용자가 합니다. 업로드 도구는 출시 노트를 넣지 않습니다.

## 0.6.0 설명용 예시

설명용 예시이며 실제로 보낸 문구가 아닙니다. CHANGELOG `## 앱 0.6.0` 절의 다섯 항목(추가 하나, 개선 둘, 수정 둘)으로 채웠습니다.

### 오픈채팅방 공지 예시

```text
[허투루 0.6.0 업데이트 안내] 2026-11-14

🆕 새로 생긴 것
- 마이 → 고객지원에 '이용약관 및 개인정보'와 '오픈소스 라이선스'가 생겼어요.

🔧 고친 것
- '문의하기'를 누르면 이메일 주소 안내 대신 문의 폼이 열려요.
- 콘텐츠 상세의 '요약'·'원본 이미지 보기'·'함께 보면 좋은 콘텐츠' 제목과 요약 글씨가 조금 커졌어요.
- 링크를 저장한 뒤 미리보기에 링크와 상관없는 예시 그림이 늘 보이던 문제를 고쳤어요.
- 마이의 '다시 본 콘텐츠'가 글을 열 때마다 늘던 문제를 고쳤어요. 이제 '최근 다시 본 콘텐츠'로, 최근 7일 동안 다시 연 글을 한 번씩만 세요.
제보 감사합니다 🙏

📲 업데이트 방법
- Android: Play 스토어에서 허투루 → 업데이트
- 아직 안 보이면 몇 시간 뒤에 다시 확인해 주세요.

💬 사용하면서 불편한 점이나 좋았던 점이 있으면 이 방에 편하게 남겨 주세요!
```

### 스토어 짧은 안내 예시

```text
0.6.0 업데이트
- 마이 → 고객지원에 '이용약관 및 개인정보'·'오픈소스 라이선스' 추가
- '문의하기'가 문의 폼으로 열리고, 콘텐츠 상세 글씨가 조금 커졌어요
- 링크 저장 미리보기의 예시 그림과 '최근 다시 본 콘텐츠' 숫자 문제를 고쳤어요
```

'최근 다시 본 콘텐츠' 항목은 `[iOS] [Android]`로 두 플랫폼 모두에 해당하므로 두 스토어에 같은 문구를 씁니다.
