# 허투루 백엔드 MVP 진행 현황

## 1. 확인 기준

2026-09-21 기준 로컬 코드(`9fbadd8`)와 API·테스트·CI 구성을 대조했다.
이 문서의 **구현 완료**는 코드가 존재한다는 의미이며, 이번 문서 갱신에서 테스트를 재실행하거나
최신 원격 브랜치·배포 서버를 확인한 것은 아니다.

- 합의한 MVP 핵심 백엔드 API, 통합 테스트와 배포 구성이 구현되어 있다.
- 사용자는 Railway 배포 완료를 알렸다. 공개 URL, 운영 변수, 백업 설정과 실기기 동작은 별도 확인이 필요하다.
- 프론트 담당자가 백엔드 연결을 진행 중이다(사용자 전달). 이 체크아웃의 Flutter 화면은 mock 데이터와 로컬 상태를 사용하며, 실제 연동 완료 여부는 별도 확인이 필요하다.
- 별도 공유 테스트 앱은 제거했다. 이후 공유 흐름 검증은 프론트 앱에서 진행한다.
- 카테고리 개인화·수정·삭제는 MVP에 포함한다. 추가 기능 후보를 확정된 MVP 작업으로 간주하지 않는다.

## 3. 유지해야 할 동작 기준

- 카테고리 추천은 저장 요청 안에서 수행한다. 별도 저장 전 추천 확인 API는 없다.
- 사용자 소유 기본 카테고리도 수정·삭제할 수 있다. 공용 `미분류`와 숨겨진 가입용 템플릿은 수정·삭제할 수 없다.
- 삭제한 기본 카테고리는 재로그인·소셜 전환 시 재생성하지 않는다.
- 카테고리 삭제는 콘텐츠를 보존한다. 다른 분류가 있으면 유지하고, 마지막 분류만 삭제되면 미분류로 이동한다.
- 카테고리별 개수는 현재 콘텐츠 관계 기준이다. 복수 분류 콘텐츠는 각 카테고리에서 집계하므로 합계가 전체 콘텐츠 수와 다를 수 있다.
- 최근 카테고리는 현재 소속 콘텐츠의 원래 `saved_at` 기준이며 미분류·빈 카테고리를 제외한다.
- 마이페이지는 **누적 저장 / 누적 열람**이다. 콘텐츠 삭제 후에도 이벤트 횟수는 유지하며 반복 열람도 각각 센다.
- 상세 GET은 열람 이벤트를 만들지 않는다. 성공한 view POST가 이벤트를 기록하며 중복 제거는 없다.
- 링크 요약은 추출한 설명과 fallback을 사용한다. 별도 AI 링크 요약은 후속 범위다.
- OCR 실패 시 기본 제목·요약으로 저장하고, 직접 지정한 유효 카테고리가 있으면 그 선택을 유지한다.
- 이미지는 LocalStorageClient와 Railway Volume으로 운영한다. 객체 저장소 전환은 MVP 필수 작업이 아니다.
- 개인화 마이그레이션의 downgrade는 지원하지 않는다. 복구 시 호환되는 앱·DB·이미지 백업을 함께 사용한다.

## 5. 다음 진행 순서

1. 프론트의 공개 HTTPS API 주소와 웹 CORS 설정을 확인하고 실제 요청 실패 원인을 해결한다.
2. 실제 Google·Kakao SDK 토큰으로 가입·재로그인·게스트 전환·로그아웃을 검증한다.
3. 실기기에서 공유·직접 링크·스크린샷 저장 → 검색·분류·즐겨찾기 → 재열람·삭제를 연결 검증한다.
4. 재배포 후 이미지·콘텐츠 유지, 운영 백업 활성화와 복구 절차를 확인한다.
5. 외부 metadata·AI·OCR의 실제 성공률과 저장 지연을 관찰하고 발견한 결함을 수정한다.

연동 테스트는 [백엔드 실행·검증 안내](../backend/README.md), 운영 확인은
[Railway 배포·복구 안내](railway-deployment.md)를 따른다. 로컬 통합 테스트는 외부 응답을 대체하므로
운영 공급자 설정과 실기기 검증을 대신하지 않는다.

## 6. 범위 결정 후 진행할 후보

| 후보 | 현재 상태·결정 사항 |
| --- | --- |
| 비슷한 콘텐츠 | 전용 API 없음. 현재 프론트는 로드된 콘텐츠 중 같은 카테고리를 표시한다. 유지 시 추천 기준·개수를 합의한다. |
| 피드 전체 건수 | `total_count` 없음. 검색·즐겨찾기 총 개수 표시가 필요하면 기존 피드 응답 확장을 검토한다. |
| 오늘의 콘텐츠 | 전용 추천 없음. 현재 프론트는 첫 콘텐츠를 연다. 별도 추천이 필요할 때만 선정 기준을 정한다. |
| 알림·리마인드 | 서버 API·발송 구현 없음. MVP 제외 범위이며 서버 푸시와 기기 로컬 알림 중 방식을 먼저 정한다. |
| 계정 수정·탈퇴 | API 없음. MVP 제외 범위이며 데이터·파일·세션 처리 정책을 먼저 정한다. |
| 태그 목록·독립 필터 | 콘텐츠 태그 저장·교체와 피드 텍스트 검색은 구현. 별도 태그 선택 UI가 필요할 때 추가한다. |
| 소셜 전용 가입 | 미적용. 기존 게스트 API·데이터를 유지한다. |
| 공유 플랫폼 확대 | 전용 공유 intake는 Instagram 지원. YouTube·TikTok payload와 정규화는 후속 범위다. |
| 비동기 처리·복수 AI 추천 | 미구현. 실제 지연·추천 품질 검증 후 필요할 때 검토한다. |

최근 검색어, 앱 버전, OS 권한 안내는 현재 요구만으로 서버 API 추가가 필요하지 않다.

## 7. 검증 기준

- 코드 변경 시 관련 서비스·API 테스트와 사용자 격리를 확인한다.
- DB 테스트는 명시적인 `TEST_DATABASE_URL`의 테스트 DB만 사용한다. 미설정 시 skip하며 잘못된 설정은 실패한다.
- CI migration job은 빈 PostgreSQL에 migration을 적용하고 repository·integration 테스트를 실행한다.
- Docker 검증은 API·DB 재생성 및 새 볼륨 복원 후 같은 토큰으로 콘텐츠와 이미지 바이트를 조회한다.
- 통합 테스트는 실제 인증·DB·파일 저장을 사용하며 소셜 공급자·metadata·AI·OCR 응답만 대체한다.
- 구현 상태, 자동 테스트 결과, 운영·실기기 검증 결과를 각각 기록한다. 이전 실행의 통과를 이번 실행 결과로 표기하지 않는다.

지표 정의와 SQL은 [제품 지표 문서](product-metrics-queries.md), 자동 분류 정책은
[카테고리 추천 문서](category-recommendation-policy.md)를 따른다.
