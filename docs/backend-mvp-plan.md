## 1. 확인 기준

PR #31이 머지된 `ee73a68`을 기준으로 태그 동시 수정 문제를 검증·수정한 결과는 10절에 기록한다.
PR #32가 머지된 `f5d3e96`을 기준으로 URL 길이 검증을 수정한 결과는 11절에 기록한다.

- 합의한 MVP 핵심 백엔드 API, 통합 테스트와 배포 구성이 구현되어 있다.
- 사용자는 Railway 배포 완료를 알렸다. 공개 URL, 운영 변수, 백업 설정과 실기기 동작은 별도 확인이 필요하다.
- 프론트 담당자가 백엔드 연결을 진행 중이다(사용자 전달). 이 체크아웃의 Flutter 화면은 mock 데이터와 로컬 상태를 사용하며, 실제 연동 완료 여부는 별도 확인이 필요하다.
- 별도 공유 테스트 앱은 제거했다. 이후 공유 흐름 검증은 프론트 앱에서 진행한다.
- 카테고리 개인화·수정·삭제는 MVP에 포함한다. 추가 기능 후보를 확정된 MVP 작업으로 간주하지 않는다.

## 3. 유지해야 할 동작 기준

- 카테고리 추천은 저장 요청 안에서 수행한다. 별도 저장 전 추천 확인 API는 없다.
- 사용자 소유 기본 카테고리도 수정·삭제할 수 있다. 공용 `미분류`와 숨겨진 가입용 템플릿은 수정·삭제할 수 없다.
- 삭제한 기본 카테고리는 재로그인·소셜 전환 시 재생성하지 않는다.
- 카테고리 삭제는 콘텐츠를 보존한다. 다른 분류가 있으면 유지하고, 마지막 분류만 삭제되면 미분류로 이동한다.
- 카테고리별 개수는 현재 콘텐츠 관계 기준이다. 복수 분류 콘텐츠는 각 카테고리에서 집계하므로 합계가 전체 콘텐츠 수와 다를 수 있다.
- 최근 카테고리는 현재 소속 콘텐츠의 원래 `saved_at` 기준이며 미분류·빈 카테고리를 제외한다.
- 마이페이지는 **누적 저장 / 누적 열람**이다. 콘텐츠 삭제 후에도 이벤트 횟수는 유지하며 반복 열람도 각각 센다.
- 상세 GET은 열람 이벤트를 만들지 않는다. 성공한 view POST가 이벤트를 기록하며 중복 제거는 없다.
- 링크 요약은 추출한 설명과 fallback을 사용한다. 별도 AI 링크 요약은 후속 범위다.
- OCR 실패 시 기본 제목·요약으로 저장하고, 직접 지정한 유효 카테고리가 있으면 그 선택을 유지한다.
- 이미지는 LocalStorageClient와 Railway Volume으로 운영한다. 객체 저장소 전환은 MVP 필수 작업이 아니다.
- 개인화 마이그레이션의 downgrade는 지원하지 않는다. 복구 시 호환되는 앱·DB·이미지 백업을 함께 사용한다.

## 7. 검증 기준

- 코드 변경 시 관련 서비스·API 테스트와 사용자 격리를 확인한다.
- DB 테스트는 명시적인 `TEST_DATABASE_URL`의 테스트 DB만 사용한다. 미설정 시 skip하며 잘못된 설정은 실패한다.
- CI migration job은 빈 PostgreSQL에 migration을 적용하고 repository·integration 테스트를 실행한다.
- Docker 검증은 API·DB 재생성 및 새 볼륨 복원 후 같은 토큰으로 콘텐츠와 이미지 바이트를 조회한다.
- 통합 테스트는 실제 인증·DB·파일 저장을 사용하며 소셜 공급자·metadata·AI·OCR 응답만 대체한다.
- 구현 상태, 자동 테스트 결과, 운영·실기기 검증 결과를 각각 기록한다. 이전 실행의 통과를 이번 실행 결과로 표기하지 않는다.

지표 정의와 SQL은 [제품 지표 문서](product-metrics-queries.md), 자동 분류 정책은
[카테고리 추천 문서](category-recommendation-policy.md)를 따른다.

YouTube의 상태 응답·20분 제한·작업 복구·운영 검증은 [유튜브 요약 문서](youtube-summary.md)를 따른다.

## 8. 2026-09-22 메타데이터 DNS 리바인딩 수정

- `MetadataClient`는 URL 검사에서 확인한 공개 IP로만 연결한다. 검사 뒤 DNS 응답이 내부 IP로 바뀌어도 연결 대상이 바뀌지 않는다.
- 원래 도메인의 Host·TLS SNI·인증서 검증·쿠키 범위·결과 URL을 유지한다. 같은 IP의 다른 도메인 연결을 재사용하지 않도록 keep-alive를 비활성화했다.
- 같은 도메인을 포함한 모든 리다이렉트에서 주소를 다시 검사한다. 연결 실패 시 검증된 나머지 IP만 순서대로 시도하며 전체 제한 시간을 유지한다. 응답 읽기 실패는 재시도하지 않는다.
- 위험한 주소는 직접 입력·공유 API 모두 기존대로 422를 반환하고 저장을 중단한다. API 계약·DB 스키마·프론트 코드는 변경하지 않았다.
- 검증: 기존 코드에서 DNS 검사 후 `127.0.0.1`로 연결되는 회귀 테스트 실패를 재현했고 수정 후 통과했다. 로컬 TLS 서버로 정상 인증서·호스트 불일치·신뢰되지 않은 인증서·같은 IP의 다른 도메인 리다이렉트를 검증했다.
- Python 3.12와 격리된 PostgreSQL 17에서 전체 테스트 **443개 통과**(회귀 테스트 18개 추가). Ruff, compileall, 빈 DB의 `alembic upgrade head`와 `alembic check`도 통과했다. 기존 Starlette/httpx 사용 중단 예정 경고 1건은 남아 있다.
- 이번 검증은 로컬 테스트다. 원격 CI·Docker 배포 검사·Railway 반영·외부 사이트 및 실기기 연결은 실행하지 않았다.

## 9. 2026-09-22 피드 페이지네이션 수정

- 기존 `saved_at DESC, id DESC` 정렬과 ID만 비교하던 다음 페이지 조건의 불일치를 수정했다. PostgreSQL에서 5개 항목을 페이지당 1·2·3개씩 조회할 때 누락·중복되는 실패를 먼저 재현했고 수정 후 통과했다.
- `next_cursor`는 UTC 저장 시각(마이크로초 보존)과 ID를 담은 `v1.` 커서를 반환한다. 다음 페이지도 두 값을 함께 비교하므로 기준 항목 삭제 후에도 이어서 조회할 수 있다.
- 기존 숫자 커서 입력은 현재 사용자 소유 항목의 저장 시각을 조회해 호환한다. 기준 항목의 분류·즐겨찾기가 바뀌어도 동작하며, 삭제·존재하지 않음·타 사용자 소유인 경우 동일한 422를 반환한다.
- 커서는 최대 512자이며 잘못된 버전·인코딩·필드 타입·시간대·ID 범위를 검증한다. 응답 구조·DB 스키마·프론트 코드는 변경하지 않았다.
- 페이지 크기·동일 시각·신규 저장·기준 항목 삭제·여러 태그 검색과 필터 조합·사용자 격리를 서비스 및 실제 API·PostgreSQL 경로에서 검증했다.

## 11. 2026-09-22 URL 길이 검증 수정

- PostgreSQL을 사용하는 API 테스트에서 2,050자 URL을 저장하면 500이 반환되는 실패를 먼저 재현했고, 수정 후 422와 미저장을 확인했다. 기존 `HttpUrl` 입력 제한과 DB의 `VARCHAR(2048)` 제한이 달랐으며, 인코딩·정규화 후 길이가 증가하는 경우도 있었다.
- `original_url`은 인코딩·정규화 후 저장 문자열 기준으로 최대 2,048자이며 OpenAPI에도 제한을 표시한다. 정확히 2,048자는 저장되고, 초과하면 URL을 자르거나 입력 주소로 대체하지 않고 422로 거절한다.
