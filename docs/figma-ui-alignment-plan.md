# Figma 화면 맞춤 계획

현재 디자인 기준·화면 대응·합의 정책과 확인 필요 상태를 관리합니다.
과거 계획·비교·실행 수치·실패·재촬영 기록은 [작업 이력](history/README.md)에 보존합니다.
디자인 대조·실행의 시점과 범위는 개별 작업 이력에서 확인합니다. 현재 기준은 기존 승인 기록을 정리한 것이며 새 Figma 조회·화면 실행 결과가 아닙니다.

<a id="작업-이력-연결"></a>화면별 현재 기준 표의 근거 링크에서 Before/After/Figma 출처·기종/OS·검사 수치·실패·재촬영·미검증 범위를 확인합니다. [전체 이력](history/README.md)과 [정리 전 목록·보존 대조](history/2026-10-22-general-docs-structure.md#followup-docs-finish)를 함께 사용합니다.
과거 비교·빌드·자동 검사의 통과는 새 확대 상태·운영 공급자·실기기의 성공으로 확대하지 않습니다. 홈 북마크 부모 탭 전달, 낮은 소개 viewport 넘침, 원본 누락과 보관 원본 사용·Figma 조회 실패도 각 당시 이력에 보존합니다.

## 상태와 비교 기준

현재 기준은 파일 `svNWsTFh8Ws1Mpt8XQIcrN`의 Page 1 (`0:1`) > `261007` (`111:3379`)입니다.
[현재 섹션](https://www.figma.com/design/svNWsTFh8Ws1Mpt8XQIcrN/?node-id=111-3379)을 사용하며 구현 직전 대상 원본을 다시 확인합니다.
기본 글자 1배율 우선, 기존 OS 안전 영역·콘텐츠 보존·저장 시점과 미확정 디자인 보류 기준을 유지합니다.
확인된 원본의 구현은 현재 로컬 작업 지침을 따르고, 과거 작업의 승인·푸시 예외를 일반 규칙으로 사용하지 않습니다.

처리 중·결과의 스크린샷 썸네일만 상단 정렬하고 크기·위치는 유지한다. 선택 전 미리보기에는 적용하지 않는다.
결정 원문과 작업 기록은 [#235 이력](history/2026-11-05-photo-save-retry.md)에 둔다.

#### 상세·카드

<a id="콘텐츠-삭제-확인-238"></a>**콘텐츠 삭제 확인 (#238).** **F-M06 저충실도 문구 채택·기존 모달 모양 재사용**을 승인된 예외로 적용한다.
기본 참조는 F-M06 `120:4293`이며, 제목 `120:4300`의 “콘텐츠를 삭제할까요?”, 본문 `120:4301`의
“아카이브와 즐겨찾기에서도 삭제돼요. 삭제 후 복구할 수 없어요.”, 버튼 `120:4305`·`120:4307`의 “삭제”·“취소”를 채택한다.
모양은 현재 앱 카테고리 삭제 확인 창(E12 참조 `111:4484`, 기존 DEC-01 예외)을 재사용한다.
왼쪽 취소·오른쪽 삭제, 삭제 배경 `#FFDDDD`·글자 `#FF0000`, Pretendard를 유지하고 미리보기는 넣지 않는다.
F-M06의 검정 버튼·세로 배치·Noto Sans KR·미리보기 자리표시자는 채택하지 않는다.
카테고리의 콘텐츠 보존 안내는 콘텐츠 삭제에 복사하지 않으며, 카테고리 삭제 정책은 유지한다.

취소·바깥 탭·뒤로가기는 삭제 요청 없이 닫는다. 확인 뒤 기존 삭제 상태·실패 표시·성공 후 재조회와 상세 복귀를 유지한다.
별도 스피너·오류 화면·되돌리기는 추가하지 않는다. 원본 없는 대기·실패 상태의 Figma 비교는 제공할 수 없으며 임의 화면으로 채우지 않는다. 경과는 [#238 이력](history/2026-11-06-content-delete-confirm.md)에 있다.

## 기록과 변경 규칙

화면별 변경·Before/After/Figma 출처·플랫폼 결과·실패·한계는 같은 작업 기록에 한 번만 적습니다.
현재 화면 계약이나 확인 필요 항목이 달라질 때 이 문서를 갱신하고 해당 기록을 연결합니다.
이전 Figma 캐시는 현재 원본의 대체 자료로 사용하지 않습니다.
기존 위젯과 ViewModel·Repository 구조를 재사용하고 화면 전체를 일괄 재작성하지 않는다.
새 행은 해당 화면 묶음 표의 끝에 더한다. 어느 묶음인지 애매하면 "공통"에 둔다.
