## Problem Statement

카테고리를 만들거나 수정하는 사용자는 이름을 입력하고 색상을 고른 뒤 저장한다. 현재 입력 시트는 서버의 결과를 기다리지 않고 닫히므로, 저장이 실패하면 작성한 내용을 잃고 처음부터 다시 입력해야 한다. 이름이 서버의 40자 제한을 넘는 경우에도 시트 안에서 수정할 수 있는 안내가 없다.

응답을 받지 못했다고 저장되지 않은 것은 아니다. 서버에 이미 반영됐는데 답만 유실될 수 있으며, 현재 서버는 같은 제출의 처리 결과를 복구할 수 없다. 같은 이름이 있다는 오류나 목록에 보이는 값만으로 원래 제출의 성공을 판단하면 잘못된 안내, 중복 생성, 이후 수정·삭제를 되돌리는 재시도가 발생할 수 있다.

사용자는 입력 초안을 유지한 채 유한한 시간 안에 결과를 확인하고, 명확한 거절과 저장 결과 미확인을 구분하며 같은 제출을 안전하게 이어갈 수 있어야 한다.

## Solution

생성·수정 시트를 저장 성공 확인 전까지 유지한다. 한 번의 저장과 카테고리 저장 재확인은 인증 갱신을 포함해 전체 10초까지만 기다린다. 대기 중에는 편집·추가 제출·시트 닫기를 막되 키보드 숨기기는 허용한다. 명확한 거절은 초안을 유지하고 원인별로 복구하며, 결과 미확인은 입력을 고정한 채 ‘결과 다시 확인’을 제공한다.

서버는 계정에 귀속된 제출 식별자와 최소 처리 결과를 보관한다. 같은 제출이 이미 처리됐다면 기록한 결과를 재사용하고, 처리 중이면 중복 실행하지 않는다. 아직 처리하지 않았다면 원래 제출한 내용의 저장을 진행할 수 있다. 원래 제출이 성공한 뒤 다른 기기에서 수정·삭제한 상태는 재시도로 되돌리지 않는다.

성공하면 시트를 닫고 최신 카테고리 목록을 확인한다. 후속 목록 갱신 실패는 저장 실패와 구분해 기존 스낵바와 목록만 다시 조회하는 행동으로 복구한다. 입력 초안과 클라이언트의 제출 복구는 현재 시트에서만 제공하며, 직접 닫기·앱 종료 뒤 자동 복원·자동 재전송은 추가하지 않는다. 사용자 승인 시안의 문구·배치를 적용하고 기존 콘텐츠 목록·마이 통계·인증 복구를 유지한다.

## User Stories

1. 아카이브에서 카테고리를 만드는 사용자로서, 실제 생성 시트에서 이름과 색상을 제출하고 싶다. 현재 동선 안에서 저장을 완료하기 위해서다.
2. 카테고리 관리 화면의 사용자로서, 같은 입력 보존·복구 동작을 사용하고 싶다. 진입 위치에 따라 실패 처리 방식이 달라지지 않기 위해서다.
3. 카테고리를 수정하는 사용자로서, 현재 저장된 이름·색상으로 시작하고 싶다. 바꾸려는 내용을 확인하며 편집하기 위해서다.
4. 이름을 작성하는 사용자로서, 앞뒤 공백을 제거한 값으로 저장하고 싶다. 기존 이름 처리 규칙을 유지하기 위해서다.
5. 처음 생성 시트를 연 사용자로서, 빈 입력만으로 오류 안내를 받지 않기를 원한다. 작성하기 전부터 잘못 입력했다고 느끼지 않기 위해서다.
6. 편집한 이름을 지운 사용자로서, 빈 이름 안내와 저장 차단을 제공받고 싶다. 이름을 채워야 함을 알기 위해서다.
7. 긴 이름을 붙여넣은 사용자로서, 40자를 넘는 내용도 잘리지 않고 남기를 원한다. 의도한 이름을 직접 고치기 위해서다.
8. 이름이 40자를 넘은 사용자로서, 시트 안에서 제한 안내를 보고 저장이 차단되기를 원한다. 서버 거절 전에 입력을 수정하기 위해서다.
9. 이모지·결합 문자가 있는 이름을 작성하는 사용자로서, 전송할 이름이 서버와 같은 길이 기준으로 검사되기를 원한다. 앱에서 허용한 이름이 길이 차이로 거절되는 일을 줄이기 위해서다.
10. 한글을 입력하는 사용자로서, 조합 중인 글자가 잘리거나 교체되지 않기를 원한다. 자연스럽게 이름을 완성하기 위해서다.
11. 색상을 고른 사용자로서, 저장이 실패해도 선택한 색상을 유지하고 싶다. 같은 선택을 반복하지 않기 위해서다.
12. 저장 버튼을 누른 사용자로서, 성공을 확인하기 전까지 입력 시트를 유지하고 싶다. 결과를 확인하고 같은 자리에서 복구하기 위해서다.
13. 저장을 기다리는 사용자로서, ‘저장하고 있어요.’와 비활성화된 진행 버튼을 보고 싶다. 요청이 진행 중임을 알기 위해서다.
14. 저장 중인 사용자로서, 제출한 이름·색상이 잠시 고정되기를 원한다. 화면의 입력과 서버에 보낸 내용이 달라지지 않기 위해서다.
15. 저장 버튼을 연속으로 누른 사용자로서, 한 제출만 진행되기를 원한다. 중복 저장을 피하기 위해서다.
16. 버튼과 키보드 완료를 함께 누른 사용자로서, 추가 제출이 발생하지 않기를 원한다. 입력 방식이 달라도 같은 저장을 기다리기 위해서다.
17. 저장 중 바깥을 누르거나 시트를 드래그한 사용자로서, 입력 시트가 닫히지 않기를 원한다. 진행 중인 결과 확인을 잃지 않기 위해서다.
18. 저장 중 시스템 뒤로가기를 사용한 사용자로서, 시트 닫기는 차단되되 키보드는 숨길 수 있기를 원한다. 대기를 유지하면서 화면을 확인하기 위해서다.
19. 서버 응답을 기다리는 사용자로서, 한 시도가 전체 10초 안에 끝나기를 원한다. 끝없는 잠금에 머물지 않기 위해서다.
20. 인증 갱신이 필요한 사용자로서, 갱신과 재요청까지 같은 10초에 포함되기를 원한다. 요청 단계가 바뀔 때마다 기다림이 늘어나지 않기 위해서다.
21. 저장이 빠르게 완료된 사용자로서, 10초를 채우지 않고 시트가 닫히기를 원한다. 불필요한 대기를 피하기 위해서다.
22. 저장 후 목록 조회가 늦은 사용자로서, 저장 성공 확인 뒤 시트가 먼저 닫히기를 원한다. 화면 갱신을 저장 대기와 혼동하지 않기 위해서다.
23. 저장 응답을 놓친 사용자로서, 실패로 단정하지 않는 결과 미확인 안내를 보고 싶다. 이미 저장됐을 가능성을 이해하기 위해서다.
24. 결과 미확인 상태의 사용자로서, 제출한 이름·색상을 그대로 보고 싶다. 어떤 저장을 다시 확인하는지 알기 위해서다.
25. 결과 미확인 상태의 사용자로서, 결과가 확정되기 전에는 다른 내용의 저장이 차단되기를 원한다. 두 저장이 모두 반영되는 일을 피하기 위해서다.
26. 카테고리 저장 재확인을 선택한 사용자로서, 같은 제출 식별자로 원래 저장을 이어가고 싶다. 응답 유실 때문에 별개의 저장이 만들어지지 않기 위해서다.
27. 이미 저장된 제출을 다시 확인하는 사용자로서, 기록된 결과를 제공받고 싶다. 저장을 다시 실행하지 않고 완료 여부를 알기 위해서다.
28. 첫 요청이 서버에 도달하지 않은 사용자로서, 재확인으로 원래 제출의 저장이 진행되기를 원한다. 같은 입력으로 저장을 완료하기 위해서다.
29. 서버가 아직 처리 중인 사용자로서, 재확인이 기존 처리를 중복 실행하지 않기를 원한다. 동시에 여러 요청을 보내도 한 결과를 얻기 위해서다.
30. 재확인을 기다리는 사용자로서, 새 10초와 ‘확인 중…’ 표현을 제공받고 싶다. 한 번의 복구 대기가 언제 끝나는지 알기 위해서다.
31. 연결이 돌아온 사용자로서, 내가 행동하기 전에는 백그라운드 재전송이나 화면 전환이 발생하지 않기를 원한다. 복구 시점을 직접 선택하기 위해서다.
32. 이름 중복으로 거절된 사용자로서, 기존 카테고리와 자동 병합되지 않고 이름을 고칠 수 있기를 원한다. 내 의도와 다른 카테고리가 선택되지 않기 위해서다.
33. 입력 오류로 거절된 사용자로서, 초안을 유지한 채 수정하고 새 제출을 하고 싶다. 잘못된 입력을 처음부터 다시 작성하지 않기 위해서다.
34. 수정 대상이 삭제된 사용자로서, 이름·색상과 안내를 보고 목록으로 돌아가고 싶다. 존재하지 않는 대상을 수정하거나 자동 생성하지 않기 위해서다.
35. 원래 저장 뒤 다른 기기에서 이름을 바꾼 사용자로서, 재확인이 새 이름을 덮지 않기를 원한다. 이후의 변경을 유지하기 위해서다.
36. 원래 저장 뒤 다른 기기에서 카테고리를 삭제한 사용자로서, 재확인이 카테고리를 다시 만들지 않기를 원한다. 삭제 의도를 유지하기 위해서다.
37. 성공을 재확인한 사용자로서, 원래 제출의 성공 사실과 최신 목록을 구분해 반영받고 싶다. 과거 결과를 현재 상태로 오해하지 않기 위해서다.
38. 저장 결과 미확인 중 시트를 닫으려는 사용자로서, 닫아도 저장이 완료될 수 있다는 안내와 확인을 받고 싶다. 닫기를 저장 취소로 오해하지 않기 위해서다.
39. 닫기 확인에서 계속 확인하기를 선택한 사용자로서, 같은 초안과 제출을 유지하고 싶다. 복구를 이어가기 위해서다.
40. 직접 시트를 닫은 사용자로서, 다시 생성 시트를 열면 새 입력으로 시작하고 싶다. 버린 초안이 다시 나타나지 않기 위해서다.
41. 수정 시트를 다시 연 사용자로서, 서버 목록을 갱신한 현재 저장값으로 시작하고 싶다. 버린 초안을 저장된 내용으로 오해하지 않기 위해서다.
42. 앱을 종료했다 다시 연 사용자로서, 이전 미확인 제출이 자동으로 재전송되지 않기를 원한다. 새 요청을 내가 선택하기 위해서다.
43. 실제 계정을 바꾼 사용자로서, 이전 시트·초안이 정리되기를 원한다. 서로 다른 계정의 입력과 결과가 섞이지 않기 위해서다.
44. 로그아웃을 완료한 사용자로서, 이전 계정의 늦은 응답이 화면에 적용되지 않기를 원한다. 계정 정보를 분리하기 위해서다.
45. 같은 계정의 인증 갱신을 기다리는 사용자로서, 초안과 같은 제출을 유지하고 싶다. 토큰 교체 때문에 입력이나 저장 의도를 잃지 않기 위해서다.
46. 실제 인증이 만료된 사용자로서, 기존 로그인 복구 절차를 따르고 싶다. 일반 저장 실패와 보안 복구가 섞이지 않기 위해서다.
47. 10초가 지난 뒤 응답이 도착한 사용자로서, 그 응답이 시트를 자동으로 닫거나 현재 복구 상태를 바꾸지 않기를 원한다. 끝난 대기 때문에 화면이 임의로 바뀌지 않기 위해서다.
48. 새 재확인을 시작한 사용자로서, 이전 시도의 성공·실패가 새 시도를 덮지 않기를 원한다. 현재 시도의 결과만 확인하기 위해서다.
49. 저장 후 목록 갱신이 실패한 사용자로서, 저장 완료와 목록 갱신 실패를 구분한 안내를 받고 싶다. 저장을 불필요하게 반복하지 않기 위해서다.
50. 목록을 다시 불러오는 사용자로서, 카테고리 목록만 전체 10초 안에 재조회하고 싶다. 다른 저장이나 조회를 반복하지 않고 목록을 복구하기 위해서다.
51. 목록 갱신이 실패한 사용자로서, 마지막 확인 목록을 계속 보고 싶다. 조회 실패를 카테고리가 모두 사라진 것으로 오해하지 않기 위해서다.
52. 콘텐츠 목록이나 마이 통계를 사용하는 사용자로서, 기존 실패 안내·재시도를 유지하고 싶다. 카테고리 복구 때문에 다른 복구 흐름이 바뀌지 않기 위해서다.
53. 다른 계정과 같은 제출 식별자를 사용한 사용자로서, 내 계정의 처리 결과만 받기를 원한다. 다른 계정의 데이터가 노출되거나 재사용되지 않기 위해서다.
54. 이전 제출이 있는 계정 소유자로서, 같은 식별자에 다른 내용이 들어오면 서버가 거절하기를 원한다. 잘못된 재시도가 새로운 변경을 실행하지 않기 위해서다.
55. 카테고리를 삭제한 사용자로서, 최소 처리 기록은 유지되기를 원한다. 늦은 재시도로 삭제한 항목이 다시 생성되지 않기 위해서다.
56. 계정을 탈퇴한 사용자로서, 계정에 귀속된 제출·처리 기록도 함께 제거되기를 원한다. 계정 삭제 뒤 복구용 데이터가 별도로 남지 않기 위해서다.
57. 기존 버전 앱의 사용자로서, 기존 생성·수정 API를 계속 이용하고 싶다. 서버 기능 추가만으로 기존 앱이 중단되지 않기 위해서다.
58. 작은 화면의 사용자로서, 키보드가 보여도 입력·안내·기본 버튼까지 스크롤로 접근하고 싶다. 복구 행동이 화면 밖에 갇히지 않기 위해서다.
59. 글자를 확대하는 사용자로서, 문구가 잘리거나 글자가 축소되지 않기를 원한다. 안내와 행동을 읽고 선택하기 위해서다.
60. iOS·Android 사용자로서, 정상 시트의 폴더·색상·버튼 표현과 실제 OS 안전 영역을 유지하고 싶다. 기존 디자인 안에서 예측 가능한 복구를 이용하기 위해서다.

## Implementation Decisions

- **범위와 기존 경계:** 아카이브·카테고리 관리의 공통 생성·수정 시트, 카테고리 ViewModel·Action·Repository, API 요청 생명주기와 서버의 카테고리 저장 경계를 수정한다. 기존 의존성 주입과 인증 계층을 사용하며 별도 상태 관리 프레임워크·작업 큐를 추가하지 않는다. 입력 시트의 동기 완료 콜백은 성공·명확한 거절·결과 미확인을 비동기로 구분해 전달하도록 변경한다.
- **입력 검증:** 실제 전송할 trim된 이름을 Unicode code point 기준으로 1~40자 검사한다. UTF-16 단위·보이는 글자 묶음·바이트 수로 대체하지 않는다. 입력 제한기로 자르거나 Unicode 정규화·새 중복 기준을 도입하지 않는다. 서버의 기존 이름·색상·부분 수정 검증을 유지한다. 한글 조합 중 텍스트·선택 영역을 재작성하지 않는다. 초기 빈 생성 시트에는 오류를 보이지 않고, 편집 후 비워진 이름·초과 입력·확인된 중복 원인에 맞춰 안내한다.
- **클라이언트 상태:** 편집 가능, 저장 대기, 확정 거절, 결과 미확인, 재확인 대기, 수정 대상 없음, 성공 종료를 구분한다. 이름·색상 초안, 변경 불가능한 제출 내용, 제출 식별자, 현재 대기 시도와 계정 소유권을 구별한다. 결과 미확인은 실패·취소가 아니다. 확정 거절 뒤 다시 저장하면 내용이 같더라도 새 제출이며 새 식별자를 사용한다. 결과 미확인 중에는 새 식별자를 만들어 우회하지 않는다.
- **시간과 생명주기:** 제출을 시작할 때 인증 갱신·요청 재전송까지 포함한 전체 10초를 시작한다. 재확인 버튼은 같은 제출에 새 10초를 부여한다. 개별 HTTP 단계·인증 갱신마다 예산을 다시 시작하지 않는다. 성공은 즉시 끝내고 후속 조회는 저장 예산에서 분리한다. 한 대기가 끝나거나 계정·시트가 바뀌면 그 시도의 하위 작업과 후속 효과를 무효화한다. 단순히 타이머로 표시만 바꾸고 늦은 응답이 Repository·화면·세션을 변경하게 두지 않는다. 기존 공유 인증 갱신을 함께 쓰는 다른 유효한 요청까지 취소하거나 그 결과를 오염시키지 않는다.
- **시트 잠금:** 저장·재확인 대기 중 이름·색상 편집, 버튼·IME 완료의 추가 제출, 바깥 터치·드래그·뒤로가기에 의한 닫기를 차단한다. 키보드 숨기기는 유지한다. 결과 미확인으로 끝나면 직접 닫기는 허용하지만 편집·새 저장은 계속 차단한다. 명확한 입력·이름 중복 거절은 편집을 허용하고, 대상 없음은 초안과 목록 복귀를 제공한다.
- **기존 API와 요청 식별:** 기존 카테고리 생성 POST와 대상 ID를 지정하는 수정 PATCH에 선택적 UUID 형식의 Idempotency-Key를 추가한다. 새 앱의 생성·수정과 401 뒤의 인증 재요청·수동 재확인은 동일 제출의 같은 키와 내용 스냅샷을 사용한다. 일반 계정 인증을 사용하며 공유 확장 전용 자격 증명을 카테고리 권한으로 재사용하지 않는다. 키를 보내지 않는 기존 요청은 기존 응답 모양·상태 코드·검증 동작을 유지한다.
- **제출의 동일성:** 인증된 계정 ID와 제출 키가 처리 기록의 식별자다. 작업 종류, 수정 대상 ID, 정규화된 전송 이름·색상과 부분 수정 필드의 존재 여부를 포함해 입력을 비교한다. 키는 인증·소유권 검사를 대신하지 않는다. 다른 계정의 같은 키는 별도 제출이다. 같은 계정·키에 다른 작업·대상·내용을 보내면 계약 충돌로 거절하며 새 쓰기를 실행하거나 다른 제출의 결과를 반환하지 않는다.
- **성공·거절 응답 계약:** 키가 있는 성공 응답은 기존 카테고리 응답 필드를 유지하고 submission 메타데이터로 key, status=succeeded, replayed 여부를 제공한다. 생성은 201, 수정은 200을 유지하며 기록된 성공의 재확인도 원래 상태 코드와 결과 스냅샷을 반환한다. 서버가 미반영을 확정한 업무 거절은 기존 HTTP 상태와 detail을 유지하면서 기계 판독 가능한 원인 코드와 status=rejected를 제공한다. 이름 중복·대상 없음·그 밖의 확정 거절을 구별한다. 키·내용 충돌은 이름 중복 코드와 구분하며 원래 제출이 미반영됐다는 증거로 사용하지 않는다.
- **검증 거절과 미확인:** 서버의 표준 입력 검증 422는 쓰기 실행 전에 발생한 입력 거절로 취급한다. 유효한 제출로 수락되지 않은 잘못된 본문·키까지 영수증으로 보관할 필요는 없다. 반면 네트워크 단절, 전체 예산 초과, 5xx, 필수 성공 정보·제출 메타데이터의 누락/불일치, 파싱 불가능한 응답은 저장 결과 미확인이다. 서버가 처리 중임을 별도로 응답한다면 종결 성공·거절과 구분된 pending 상태여야 한다. 임의의 2xx·409, 같은 이름의 존재, 현재 목록만으로 성공이나 원래 제출의 미반영을 추정하지 않는다.
- **최소 처리 기록:** 카테고리 제출을 위한 계정·UUID 복합 유일 키, 작업 종류, 대상 ID, 입력 fingerprint, 종결 결과, 원래 HTTP 상태와 복구에 필요한 결과 스냅샷을 저장한다. 성공 스냅샷에는 원래 제출의 카테고리 ID·이름·색상·기본 여부 등 필요한 응답만 포함한다. 수락된 업무 요청의 확정 거절도 원인과 결과를 재사용할 수 있게 기록한다. 처리 중 상태를 별도 영속 예약으로 구현할 필요는 없지만 같은 키의 미완료 요청을 직렬화해야 한다. 이미지·콘텐츠 본문·인증 토큰은 기록하지 않는다.
- **DB 경계와 동시성:** 여러 서버 프로세스·독립 DB 연결에서도 같은 계정·키의 검사와 실행을 배타적으로 처리한다. 기존 사용자별 이름 충돌 보호와 일관된 잠금 순서를 유지한다. 성공한 카테고리 변경과 성공 기록은 같은 DB 트랜잭션에서 확정한다. 이름 충돌·대상 없음 등 수락된 요청의 확정 거절은 해당 시도의 부분 변경을 되돌린 상태에서 같은 키의 보호를 유지하며 거절 기록을 확정한다. 쓰기와 결과 기록 중 한쪽만 남는 구조를 만들지 않는다. commit 응답 자체를 잃으면 미확인으로 취급하고, 다음 동일 제출이 완료된 트랜잭션의 기록을 먼저 확인하게 한다.
- **재확인의 실행 의미:** 같은 키의 기록이 있으면 원래 결과를 재사용한다. 아직 처리 중이면 결과를 기다리거나 비종결 상태로 알리고 중복 실행하지 않는다. 기록이 없고 이전 처리가 종료돼 미반영임을 배타적 경계에서 확인했다면 원래 내용을 처리할 수 있다. 원래 요청이 서버에 도달하지 않았던 경우도 이 경로로 저장한다. 별도의 요청 상태 조회 API나 내구성 있는 클라이언트 작업 큐는 만들지 않는다.
- **이후 수정·삭제 보존:** 기록된 성공을 반환하기 전에 현재 대상에 원래 쓰기를 다시 적용하지 않는다. 기록에 있는 과거 카테고리를 클라이언트 현재 목록에 무조건 추가·덮어쓰지도 않는다. 재확인 성공 뒤 최신 목록을 조회해 현재 존재·이름·색상을 반영한다. 이후 삭제됐다면 원래 제출은 성공했던 것으로 끝내되 삭제된 현재 상태를 유지한다. 이름 중복이나 현재 값의 일치로 다른 카테고리를 원래 성공 대상으로 대체하지 않는다.
- **기록 보관:** 자동 TTL·정리 작업을 추가하지 않는다. 카테고리를 지워도 제출 기록은 유지하고 계정 삭제 시 함께 제거한다. 대상 삭제로 기록까지 연쇄 삭제되는 외래 키를 두지 않는다. 계정에 대한 기존 삭제 계약에 기록 정리를 연결하며 새 회원 탈퇴 기능을 구현하지 않는다. 이는 현재 시트를 벗어난 클라이언트의 자동 복구를 허용한다는 뜻이 아니다.
- **성공과 후속 조회 분리:** 성공 응답을 확인하면 먼저 시트를 닫고 최신 카테고리 목록을 갱신한다. 원래 기록을 재사용한 응답과 현재 목록 갱신을 별개로 취급한다. 이번 기능의 저장 후·재진입 시 카테고리 조회에는 저장 대기와 별개의 전체 10초를 사용하며 홈 최초 불러오기 등 기존 예산은 변경하지 않는다. 기존 수정 후 콘텐츠 갱신을 유지하되 그 지연·오류가 저장 대기를 연장하거나 성공을 실패로 바꾸지 않게 한다. 화면용 낙관적 이름·색상을 서버가 확인한 원본으로 취급하지 않는다.
- **목록 복구:** 저장 성공 뒤 카테고리 목록 갱신만 실패하면 마지막 확인 목록을 유지하고 기존 스낵바에 ‘저장은 완료됐지만 카테고리 목록을 새로 불러오지 못했어요’와 ‘다시 불러오기’를 표시한다. 이 행동은 카테고리 목록 GET만 인증 갱신 포함 전체 10초로 실행한다. 생성·수정·사용자 정보·통계·콘텐츠 목록을 다시 요청하는 공통 refresh에 그대로 연결하지 않는다. 실패한 조회·스낵바 행동도 현재 계정에 귀속하고 늦은 결과를 차단한다. 콘텐츠 목록은 해당 목록의 기존 복구를, 마이 통계는 통계만 재시도하는 기존 계약을 유지한다.
- **목록 응답 검증:** 카테고리 목록은 계약에 맞는 배열과 항목을 정상 조회로 인정한다. 정상적인 빈 배열은 성공이지만, 비어 있는 HTTP 본문·JSON null·깨진 응답을 빈 목록으로 치환하지 않는다. 이 검증은 카테고리 조회에 한정하고 공통 디코더 변경으로 무관한 요청의 계약을 바꾸지 않는다.
- **닫기·재진입:** 편집·확정 거절의 직접 닫기는 초안 보존을 종료한다. 결과 미확인 중 직접 닫기는 기존 팝업 스타일로 ‘입력 창을 닫을까요?’, ‘닫아도 서버 저장은 완료될 수 있어요. 작성한 내용은 이 창에서 사라져요.’와 ‘계속 확인하기/닫기’를 제공한다. 계속 확인하면 같은 초안·키를 유지하고 닫으면 현재 시트의 복구를 종료한다. 다시 열 때 서버 목록을 갱신하고 생성은 새 입력·수정은 현재 저장값으로 시작한다. 재진입 조회가 실패하면 기존 일반 조회 오류 스낵바인 ‘최신 정보를 불러오지 못했어요. / 다시 불러오기’를 재사용해 카테고리 목록만 복구한 뒤 시트를 새로 연다. 저장 완료가 확인되지 않은 재진입에 저장 완료 문구를 사용하지 않는다. 그 조회에서 보이지 않는다는 이유로 이전 미확인 저장이 추후 반영되지 않는다고 단정하지 않는다. 기기에 초안·제출 키를 영속 보관하거나 앱 종료·재진입·연결 복구로 자동 재전송하지 않는다.
- **계정·인증:** 실제 계정 변경과 로그아웃 완료 때 시트·초안·제출 상태를 정리하고 이전 계정의 결과를 차단한다. 같은 계정의 토큰 갱신은 초안·동일 제출을 보존한다. 기존 인증 갱신의 단일 실행·토큰 저장·최종 만료 복구를 유지한다. 일반 저장 오류·시간 초과만으로 세션을 버리거나 새 게스트를 발급하지 않는다. 클라이언트 요청 취소·시트 닫기·계정 초기화는 서버의 저장 취소를 보장하지 않는다.
- **확정 디자인:** 정상 E10·E11의 폴더·이름·기존 8색·검은 버튼과 노란 글자, 안전 영역을 유지한다. 입력 오류는 이름 아래 8px, 12px·줄 높이 18px다. 저장·결과 안내는 색상 선택 아래 16px에 같은 글자 크기로 표시하고 안내 아래 24px에 기본 버튼을 둔다. 안내 없는 정상 상태의 기존 간격은 유지한다. 대기 버튼에는 진행 문구를 표시하고 비활성화한다. 글자 확대 때 문구·버튼 글자를 축소하지 않고 줄바꿈·높이 확장을 허용하며, 키보드·작은 화면 높이에서 안내와 버튼까지 스크롤로 접근할 수 있게 한다.
- **문서와 배포 순서:** 현재 프론트 동작·실행 안내, 백엔드 API·테스트 안내와 사용자 변경 이력을 구현 결과에 맞춰 갱신한다. 새 처리 기록은 추가형 마이그레이션으로 도입하고 백엔드·마이그레이션을 먼저 준비한 뒤 새 앱을 배포한다. 새 복구 계약을 지원하지 않는 구서버와 새 앱의 조합을 동등한 보장으로 보고하지 않는다. 실제 운영 배포는 별도 작업이다.

## Testing Decisions

- **주 검증 경계는 기존 두 통합 테스트다.** 사용자가 확인한 대로 실제 앱+HTTP 대역+메모리 세션 저장소와 FastAPI HTTP+실제 PostgreSQL 경계를 사용한다. 하나는 실제 입력·화면 복구를, 다른 하나는 DB에 남는 결과·동시성·계정 격리를 입증한다. HTTP 대역만으로 서버의 중복 실행 방지를 입증하거나 모듈별 새 테스트 경계를 늘리지 않는다.
- **좋은 테스트:** 사용자에게 보이는 시트·문구·입력·목록·세션 결과와 HTTP·DB의 외부 계약을 확인한다. 내부 클래스 구조, 비공개 함수 호출 횟수·순서, 특정 잠금 구현을 고정하지 않는다. HTTP에서 관찰하는 쓰기 횟수·동일 키·입력 비교와 DB의 최종 행 수는 중복 실행 방지·조회 전용 재시도 계약을 입증할 때 사용한다.
- **기존 검사 재사용:** 앱의 세션 유지·인증 갱신·홈 복구·마이 통계 통합 테스트에서 사용하는 제어 가능한 HTTP 응답·시간 진행·저장소 대역을 확장한다. 공통 카테고리 시트의 배치·짧은 높이·키보드 왕복·IME 중복 제출 검사도 유지한다. 저장 콜백만 직접 호출하는 검사를 실제 시트 저장 복구의 증거로 삼지 않는다. 서버는 공유 저장 영수증의 HTTP 재시도·독립 PostgreSQL 연결·commit 전후 장애 주입 방식을 참고하되 카테고리 계약으로 검증한다.
- **앱의 핵심 경로:** 아카이브와 관리에서 실제 생성·수정 시트를 열어 이름·색상 선택→지연/거절→초안 보존→수정 또는 재확인→성공 종료를 확인한다. 초기 빈 이름·편집 후 빈 이름·trim 후 정확히 40/41 code point, 단일 이모지·결합 문자·한글 조합·긴 붙여넣기를 포함한다. 자동 절단이 없고 잘못된 입력은 전송하지 않으며 정상 수정 뒤 행동이 활성화되는지 확인한다.
- **전체 시간·잠금:** 제어 가능한 시간으로 10초 직전/도달, 인증 갱신을 포함한 누적 시간, 재확인의 새 10초, 조기 성공을 확인한다. 실제 10초 수면에 의존하지 않는다. 버튼·IME 연속 제출, 편집·색상·바깥 터치·드래그·시스템 뒤로가기 잠금과 키보드 숨기기를 구분한다. 느린 후속 조회가 성공 시트 닫기를 지연하지 않는지도 확인한다.
- **미확인·늦은 결과:** 연결 실패·무응답·5xx·깨진 성공 본문·잘못된 제출 메타데이터가 성공·확정 거절로 바뀌지 않는지 확인한다. 첫 시도의 늦은 성공·실패·인증 응답을 시간 초과·새 재확인·시트 닫기·계정 전환 뒤에 도착시켜 현재 화면·목록·세션이 유지되는지 검증한다. 앱 재진입·연결 복구만으로 쓰기를 다시 보내지 않는지 확인한다.
- **앱의 후속 조회:** 저장 성공 뒤 카테고리 GET만 실패하게 해 스낵바·마지막 목록 보존·조회 전용 재시도를 확인한다. 재시도의 인증 갱신 포함 10초와 계정 전환 뒤 늦은 응답도 검증한다. 마이 통계의 마지막 확인값·로컬 실패 안내·통계만 재시도, 콘텐츠 목록의 기존 복구를 회귀 검증한다. 목록 재조회에 비어 있는 HTTP 본문·JSON null·깨진 응답을 주었을 때 잘못된 전체 부재로 덮지 않는지와 정상 빈 배열의 성공을 구분해 확인한다.
- **서버 재사용·동시성:** 생성·수정 각각 같은 계정·키·내용의 순차/동시 요청, 다른 계정의 같은 키, 같은 키의 다른 종류·대상·내용을 검증한다. 독립 PostgreSQL 연결을 사용해 성공 변경과 처리 기록이 한 번만 확정되는지 확인한다. 키 없는 기존 요청의 응답·이름 충돌·부분 수정·권한 계약도 유지한다.
- **서버의 반영 경계:** commit 전 실패, 실제 rollback, commit 후 응답 유실·확정 응답 손실을 구분해 동일 키 재시도의 결과와 DB 상태를 확인한다. 성공 기록 없는 원래 요청은 재확인으로 저장할 수 있고 완료된 요청은 원래 결과를 재사용해야 한다. 확정 거절도 이후 데이터가 바뀌었다는 이유로 같은 키에서 새 쓰기로 바뀌지 않는지 확인한다.
- **현재 상태와 보관:** 성공 뒤 다른 요청으로 이름·색상을 수정하거나 대상을 삭제한 다음 원래 키를 재시도한다. 원래 성공 결과는 유지되지만 최신 목록·DB의 이후 상태가 되돌아가지 않아야 한다. 카테고리 삭제 후 기록 보존, 계정 삭제 후 기록 제거, 기록에 이미지·콘텐츠 본문·토큰이 포함되지 않는지 확인한다. 추가형 마이그레이션과 기존 데이터·키 없는 API 호환을 검증한다.
- **네이티브 실행·비교:** 구현 전에 변경 전 화면과 기준 Figma 조회 시점·노드를 확보한다. iOS Simulator·Android Emulator 양쪽에서 플랫폼별 동일 기종·크기·데이터·상태·글자 배율·스크롤 위치로 변경 전/후/Figma를 나란히 비교한다. 정상·저장 대기·거절·미확인·재확인·닫기 확인, 키보드·뒤로가기·드래그·작은 높이·글자 확대를 실행한다. 스크린샷과 중요한 이동·드래그·스크롤 영상을 채팅에서 확인할 수 있게 전달하고, OS 안전 영역 차이를 원본 보정 없이 설명한다.
- **완료 검증:** 관련 검사와 전체 프론트·백엔드 검사·빌드·마이그레이션 검사를 수행하고 결과를 기록한다. 실행이 막힌 플랫폼·DB 검사는 이유와 미검증 범위를 명시한다. 문서 작성·HTML 시안·HTTP 대역·로컬 DB·원격 CI·실제 OAuth·운영 서버·실기기 증거를 구분한다. 이 명세 작성 자체는 제품 구현·테스트 실행 완료를 뜻하지 않는다.

## Out of Scope

- 시트를 닫거나 앱을 종료한 뒤 초안·제출 식별자의 영속 저장·자동 복원·자동 재전송, 연결 복구·주기적 재시도.
- 결과 미확인 중 다른 내용으로 새 저장, 카테고리 자동 병합·이름 자동 변경·대상 삭제 후 자동 재생성.
- 다른 기기의 일반 동시 편집을 위한 새 버전 충돌 정책·협업 편집. 이번 재확인으로 이미 완료된 쓰기를 반복하지 않는 보호는 포함한다.
- 카테고리 삭제의 콘텐츠 보존 규칙 변경, 새 자유 색상 선택·정렬·검색·일반 목록 로딩 UX 재설계.
- 다른 종류의 모든 저장에 적용하는 범용 작업 큐·범용 제출 영수증 프레임워크, 새 요청 상태 조회 화면·API.
- 마이 통계·홈 로딩·인증의 기존 정책 재설계, 새 회원 탈퇴 기능·보관 기간 자동 만료·운영 대시보드.
- 이미지 보관 전환 PR의 병합·Bucket·백업 설정, 운영 서버·앱 배포·실기기 검증.
