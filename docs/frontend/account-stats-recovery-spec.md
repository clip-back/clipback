## Problem Statement

마이 화면의 ‘저장한 콘텐츠·다시 본 콘텐츠’는 통계를 아직 확인하지 못했거나 조회에 실패했을 때도 실제 0건과 같은 숫자를 보여준다. 사용자는 기록이 없는 것인지, 연결 문제로 확인하지 못한 것인지 구분할 수 없고 통계만 다시 불러올 수도 없다.

한 번 조회한 숫자가 있어도 이후 조회가 늦거나 실패했다는 표시가 없고, 마이에 다시 들어가는 것만으로는 최신 통계를 확인하지 못한다. 이름·계정 정보 조회가 실패하면 통계 요청이 성공해도 수치를 반영하지 못하는 경로도 있다.

## Solution

마이 통계의 최초 조회 중·최초 실패·마지막 확인값이 있는 재조회 중·재조회 실패·성공을 구분한다. 아직 확인하지 못한 수치는 ‘—’로, 서버가 정상 응답한 실제 0건은 ‘0’으로 표시한다.

마이에 진입하면 통계를 한 번 갱신하고, 실패하면 통계 패널 아래의 ‘다시 시도’로 복구한다. 조회 전체는 인증 갱신 시간을 포함해 10초로 제한한다. 같은 계정의 유효한 조회가 진행 중이면 함께 사용하며 대기 시간을 다시 시작하지 않는다.

같은 계정의 마지막 확인값은 현재 앱 실행 동안 유지하고, 지연·실패 시 그 의미를 안내한다. 사용자 정보와 통계의 조회 결과는 독립적으로 반영한다. 통계의 일반 실패가 홈·나머지 마이 메뉴·유효한 세션 사용을 막지 않도록 한다.

## User Stories

1. 사용자로서, 아직 확인하지 못한 통계가 실제 0건과 다르게 표시되기를 원한다. 그래야 내 기록이 사라졌다고 오해하지 않을 수 있다.
2. 처음 통계를 확인하는 사용자로서, 조회 중이라는 안내를 보고 싶다. 그래야 결과를 기다리는 상황임을 알 수 있다.
3. 처음 통계 조회에 실패한 사용자로서, 확인하지 못했다는 안내를 보고 싶다. 그래야 기록이 없는 상태와 오류를 구분할 수 있다.
4. 조회에 실패한 사용자로서, 통계만 다시 시도하고 싶다. 그래야 앱을 재시작하거나 다시 로그인하지 않고 복구할 수 있다.
5. 실제 기록이 0건인 사용자로서, 정상 조회한 0을 보고 싶다. 그래야 조회 실패와 구분해 결과를 신뢰할 수 있다.
6. 이전 통계가 있는 사용자로서, 다음 조회를 기다리는 동안 마지막 확인값을 계속 보고 싶다. 그래야 수치가 불필요하게 사라지지 않는다.
7. 이전 통계가 있는 사용자로서, 다음 조회가 실패해도 마지막 확인값을 보고 싶다. 그래야 실패가 기록 삭제처럼 보이지 않는다.
8. 이전 통계가 있는 사용자로서, 표시된 숫자가 마지막 확인값이라는 안내를 보고 싶다. 그래야 이후 활동까지 반영한 최신 수치로 오해하지 않는다.
9. 앱을 새로 실행한 사용자로서, 이번 실행에서 통계를 확인하기 전에는 미확인 상태를 보고 싶다. 그래야 영속 보관되지 않은 이전 숫자를 최신 결과로 오해하지 않는다.
10. 계정을 전환한 사용자로서, 이전 계정의 통계가 비워지기를 원한다. 그래야 다른 계정의 기록이 섞이거나 노출되지 않는다.
11. 로그아웃을 완료한 사용자로서, 해당 계정의 마지막 확인값이 비워지기를 원한다. 그래야 이후 세션에서 내 숫자가 잘못 노출되지 않는다.
12. 로그아웃이나 계정 연결을 취소한 사용자로서, 여전히 유효한 같은 계정의 수치가 불필요하게 지워지지 않기를 원한다. 그래야 취소만으로 통계를 잃지 않는다.
13. 이름·계정 정보 조회가 일시 실패한 사용자로서, 통계 조회가 성공하면 숫자는 보고 싶다. 그래야 별개 조회의 실패가 통계까지 가리지 않는다.
14. 통계를 재시도하는 사용자로서, 이름·계정 정보를 다시 불러오는 데 의존하지 않기를 원한다. 그래야 통계 복구가 독립적으로 동작한다.
15. 마이에 진입하는 사용자로서, 통계가 한 번 갱신되기를 원한다. 그래야 다시 방문했을 때 수치를 재확인할 수 있다.
16. 조회가 진행 중인 사용자로서, 진입이나 연속 입력이 중복 요청을 만들지 않기를 원한다. 그래야 불필요한 통신과 겹치는 결과를 피할 수 있다.
17. 연결이 느린 사용자로서, 인증 갱신을 포함해 한 번의 조회를 전체 10초까지만 기다리고 싶다. 그래야 무기한 대기하지 않는다.
18. 실패 후 재시도하는 사용자로서, 새 시도의 대기 시간을 새로 부여받고 싶다. 그래야 정상적인 복구 기회를 얻는다.
19. 마이에 머무는 사용자로서, 실패 후 원치 않는 주기적 재시도가 반복되지 않기를 원한다. 그래야 복구 시점을 내가 선택할 수 있다.
20. 다른 화면으로 이동한 사용자로서, 시작한 통계 조회는 남은 제한 시간 동안 계속 진행되기를 원한다. 그래야 이동만으로 조회 결과를 잃지 않는다.
21. 조회 완료 전에 마이로 돌아온 사용자로서, 진행 중인 조회를 함께 사용하고 싶다. 그래야 요청이나 10초 제한이 새로 시작되지 않는다.
22. 이전 조회가 끝난 뒤 마이로 다시 진입한 사용자로서, 새 조회를 한 번 시작하고 싶다. 그래야 마지막 확인 이후의 수치를 재확인할 수 있다.
23. 새 조회나 다른 계정으로 이동한 사용자로서, 무효화된 이전 응답이 현재 수치를 덮어쓰지 않기를 원한다. 그래야 현재 결과를 신뢰할 수 있다.
24. 제한 시간을 넘긴 사용자로서, 뒤늦은 응답이 수치나 세션을 바꾸지 않기를 원한다. 그래야 종료된 시도가 현재 화면과 인증을 흔들지 않는다.
25. 실제 인증이 만료된 사용자로서, 기존 인증 복구 절차를 따르고 싶다. 그래야 통계 복구가 계정 보안 경계를 우회하지 않는다.
26. 네트워크·서버 오류를 겪는 사용자로서, 그것만으로 유효한 세션이 삭제되지 않기를 원한다. 그래야 통계 오류 때문에 다시 로그인하지 않는다.
27. 홈을 사용하는 사용자로서, 통계가 늦거나 실패해도 필수 목록이 준비되면 홈을 사용하고 싶다. 그래야 부가 정보 때문에 콘텐츠 이용이 막히지 않는다.
28. 마이를 사용하는 사용자로서, 통계 오류 중에도 다른 메뉴를 사용하고 싶다. 그래야 통계 하나의 오류가 마이 전체를 막지 않는다.
29. 기존 화면에 익숙한 사용자로서, 정상 통계 패널의 두 열·라벨·색상이 유지되기를 원한다. 그래야 기존 정보를 익숙한 위치에서 볼 수 있다.
30. 통계 오류를 겪는 사용자로서, 안내와 복구 버튼을 통계 바로 아래에서 찾고 싶다. 그래야 어떤 정보가 실패했는지 알 수 있다.
31. 글자를 확대하는 사용자로서, 안내와 라벨이 줄바꿈되고 높이가 늘어나기를 원한다. 그래야 문구나 수치가 잘리지 않는다.
32. 터치로 복구하는 사용자로서, 충분한 누름 영역을 가진 재시도 버튼을 원한다. 그래야 복구 동작을 쉽게 선택할 수 있다.
33. 누적 기록을 확인하는 사용자로서, 서버의 누적 집계 기준이 유지되기를 원한다. 그래야 이번 개선으로 수치의 의미가 달라지지 않는다.
34. 콘텐츠를 삭제한 사용자로서, 기존 계약대로 누적 기록 수가 유지되기를 원한다. 그래야 현재 보관량과 누적 기록을 혼동하지 않는다.
35. 같은 콘텐츠를 반복 열람한 사용자로서, 기존 계약대로 각각의 재열람 기록이 반영되기를 원한다. 그래야 고유 콘텐츠 수로 의미가 바뀌지 않는다.
36. 콘텐츠를 변경한 사용자로서, 기존 후속 통계 갱신이 계속 동작하기를 원한다. 그래야 새 복구 기능이 기존 갱신 경로를 끊지 않는다.

## Implementation Decisions

### 범위와 서버 계약

- 대상은 마이 통계의 두 수치에 대한 조회 상태·복구다. 현재 정상 라벨 ‘저장한 콘텐츠·다시 본 콘텐츠’를 유지한다.
- 마이 통계는 계정의 누적 저장 기록 수와 누적 재열람 기록 수다. 현재 보관량·고유 콘텐츠 수·불러온 목록 길이로 대체하지 않는다. 반복 열람, 삭제 후 누적 기록 유지, 미기록 과거 자료를 추정하지 않는 기존 계약을 보존한다.
- 인증된 `GET /api/v1/users/me/stats`와 `saved_count`·`reopened_count` 응답 계약을 유지한다. 서버 API·DB 스키마·마이그레이션을 추가하지 않는다.
- 한 번의 정상 응답에서 받은 두 수치를 함께 적용한다. 한쪽을 이전 값이나 임의의 0으로 섞지 않는다. 조회 실패나 잘못된 응답을 0/0으로 변환하지 않는다.

### 상태 소유와 연결

- 기존 사용자 Repository가 계정별 통계의 마지막 확인값, 조회 진행·실패 여부, 진행 중인 조회와 소유권을 관리한다. 마지막 확인값은 같은 계정에서 가장 최근에 정상 조회한 두 수치이며 현재 앱 실행 동안만 보존한다.
- 기존 계정 ViewModel은 통계 상태를 화면에 투영하고, 마이 화면은 상태와 콜백을 사용한다. 화면이 API·세션 저장소에 직접 접근하지 않는다.
- 사용자 프로필을 화면 모델로 변환하는 기존 경로가 통계 미확인을 0으로 덮거나, 프로필 부재 때문에 성공한 통계를 숨기지 않도록 분리한다.
- 기존 최초 부가 조회, 마이 진입, 통계 재시도, 콘텐츠 변경 후 통계 갱신을 같은 계정 통계 상태 계약에 연결한다. 별도 프레임워크나 범용 새 데이터 계층을 도입하지 않는다.
- 새 통계 상태를 연결하면서 기존 콘텐츠 변경의 성공 결과나 공유 수신 복구 절차를 임의로 바꾸지 않는다.

### 조회 시작과 중복 방지

- 다른 화면에서 마이로 진입할 때 통계를 한 번 갱신한다. 같은 화면의 재빌드나 마이에 머무는 시간만으로 새 조회를 시작하지 않는다.
- 마이 진입·재시도가 같은 계정의 유효한 진행 중 조회와 겹치면 그 조회를 함께 사용한다. 중복 통신이나 새 대기 시간을 만들지 않는다. 만료되거나 무효화된 시도는 공유 대상이 아니다.
- 실패 후 통계 전용 ‘다시 시도’가 새 시도를 시작한다. 조회 중 연속 입력으로 중복 실행하지 않는다. 주기적·연결 복구 감지·앱 복귀만을 이유로 한 별도 자동 재시도는 추가하지 않는다.
- 앱 안에서 마이를 벗어나도 시작한 조회는 남은 제한 시간 동안 유지한다. 성공하면 같은 계정의 마지막 확인값을 갱신한다. 다른 화면에 통계 실패 팝업이나 전역 오류를 띄우지 않는다.
- 완료 전에 마이로 돌아오면 진행 중 조회를 함께 사용하고, 완료된 뒤 다시 진입하면 새 조회를 한 번 시작한다. 기존 콘텐츠 변경 후 갱신과 새 결과 우선권은 보존한다.

### 전체 대기 상한과 응답 수명

- 새 통계 조회와 수동 재시도는 인증 갱신·인증 후 재요청을 포함해 한 번의 전체 시도에 10초를 적용한다. 요청 단계마다 10초를 다시 부여하지 않는다.
- 진행 중 시도를 함께 사용하는 화면은 남은 시간만 기다린다. 실패 후 사용자가 새로 재시도하면 새 10초를 부여한다.
- 10초 안에 끝나지 않으면 실패 상태로 전환한다. 마지막 확인값이 있으면 보존하고, 없으면 미확인 수치를 유지한다.
- 기존 요청 수명 관리와 계정·조회 세대 보호를 재사용한다. 만료·계정 전환·후속 조회로 무효화된 응답은 현재 수치·오류·인증 상태를 바꾸지 않는다.
- 종료된 시도가 단독으로 시작한 인증 갱신의 늦은 결과는 토큰 저장·세션 무효화로 이어지지 않는다. 다른 현재 요청이 함께 사용 중인 인증 갱신의 유효한 소유권은 보존한다.
- 홈 필수 목록의 전체 15초와 기존 최소 로딩 표시 정책은 유지한다. 통계 10초를 홈 대기 시간에 합산하거나 전역 API 제한으로 확대하지 않는다.

### 사용자 정보와 통계의 독립 반영

- 현재 계정의 통계 조회가 성공하면 이름·계정 정보 조회가 일시 실패해도 두 수치를 반영한다. 사용자 정보 조회가 진행 중인 상태도 통계 성공 표시를 가리지 않는다.
- 통계 전용 재시도는 통계만 조회한다. 이름·계정 정보의 기존 확인 상태와 조회 흐름을 새로 설계하지 않는다.
- 프로필과 통계가 모두 성공해야 한꺼번에 교체하던 결합을 통계 표시·복구 경로에서 제거하되, 계정 소유권 확인과 실제 인증 실패 처리는 유지한다.

### 표시 상태

| 상태 | 두 수치 | 통계 패널 아래 안내 | 재시도 버튼 |
| --- | --- | --- | --- |
| 첫 조회 중 | 각각 `—` | 통계를 불러오는 중이에요 | 없음 |
| 첫 조회 실패 | 각각 `—` | 통계를 불러오지 못했어요 | 다시 시도 |
| 마지막 확인값이 있는 재조회 중 | 마지막 확인값 | 마지막 확인값 · 새로 불러오는 중 | 없음 |
| 마지막 확인값이 있는 재조회 실패 | 마지막 확인값 | 마지막 확인값 · 새로 불러오지 못했어요 | 다시 시도 |
| 조회 성공 | 서버의 두 수치. 실제 0은 `0` | 위 상태 안내 없음 | 없음 |

- 마지막 확인값이 0/0이어도 성공한 값으로 보존하며, 재조회 중·실패 시 같은 마지막 확인값 안내를 사용한다.
- 재시도 중에는 마지막 확인값 유무에 따라 위 대기 상태로 돌아간다. 성공하면 새 두 수치로 교체하고 대기·실패 안내를 제거한다.

### 승인한 디자인

- 정상 통계 패널은 J01의 두 열·기존 색상·라벨·모서리와 1배율 높이 80px을 유지한다. 375px 기준 프레임에서 패널 너비는 343px이며 기존 화면의 배치 규칙을 따른다.
- 상태 안내는 패널 아래 10px 간격에 12px 보조 글자로 표시한다.
- 실패 시 안내 아래 8px 간격에 왼쪽 정렬의 ‘다시 시도’를 둔다. 글자 14px·모서리 8px·중립색 테두리 버튼으로, 최소 누름 영역은 88×44px이다.
- 성공하면 상태 안내와 재시도 버튼을 숨긴다. 뒤의 관리 메뉴는 기존 세로 흐름을 따르며 다른 마이 메뉴는 계속 사용할 수 있다.
- 글자를 확대하면 라벨·안내의 자연스러운 줄바꿈과 패널·버튼 높이 확장을 허용한다. 두 수치의 세로 위치를 맞추고, 문구를 자르거나 겹치게 하지 않는다.
- 기존 공통 스타일·토큰을 재사용한다. 새 전면 오류 화면·스피너·스켈레톤·브랜드 요소·임의 아이콘을 추가하지 않는다.

### 계정·인증 보호

- 계정 전환·로그아웃 완료·기존 인증 복구의 계정 초기화 경계에서 마지막 확인값과 통계 상태를 비운다. 앱 재실행 뒤 디스크에서 마지막 확인값을 복원하지 않는다.
- 로그아웃이나 계정 연결의 취소·일반 실패만으로 여전히 유효한 같은 계정의 수치를 지우지 않는다. 로컬 세션 삭제 실패 등 기존 보안 복구 경로는 유지한다.
- 네트워크·서버 오류 같은 비인증 실패로 세션을 지우거나 새 게스트를 만들지 않는다. 통계가 지연·실패해도 필수 목록이 준비된 홈과 나머지 마이 메뉴를 사용할 수 있다.
- 현재 유효한 요청의 인증 갱신과 최종 인증 실패, 기존 플랫폼 계정 보안 확인의 우선권을 보존한다. 통계 재시도로 인증 복구를 우회하지 않는다.

## Testing Decisions

### 주 검증 경계

- 사용자가 확인한 주 경계는 기존 **실제 앱 + HTTP 대역 + 메모리 세션 저장소** 통합 테스트다. 앱의 진입·실제 화면 출력·사용자 입력·세션 저장 결과와 HTTP 계약을 함께 관찰한다.
- 기존 앱 시작·세션 복원 테스트를 우선 확장한다. 이 경계에 이미 있는 지연 응답, 가상 시간 진행, 계정 전환, 인증 갱신 대역을 재사용한다. 상태 종류마다 새로운 테스트 전용 구조를 만들지 않는다.
- 좋은 테스트는 사용자가 보거나 수행하는 결과와 외부 계약을 검사한다. 비공개 필드, 클래스 배치, 내부 함수 호출 순서·횟수를 고정하지 않는다. 실제 중복 HTTP 요청이 없다는 검사는 관찰 가능한 중복 통신 계약으로 확인한다.
- 현재 미확인 통계에 0을 기대하거나 프로필 실패 시 성공한 통계를 가리는 기존 기대값은 새 정책으로 바꾼다. 기존 보안·계정 소유권 회귀 보장은 유지한다.

### 필수 통합 시나리오

| 시나리오 | 확인할 외부 결과 |
| --- | --- |
| 홈 부가 조회 중 마이 진입 | 필수 목록이 준비된 홈은 열리고, 마이 통계는 가짜 0 없이 대기 상태를 표시한다. |
| 최초 비인증 실패 → 재시도 → 성공 | `—/—`·정확한 실패 문구·버튼이 표시되고, 재시도 중 대기 상태를 거쳐 새 수치와 정상 패널로 복구한다. |
| 정상 응답의 0/0 | 미확인·실패 안내 없이 실제 0/0을 표시한다. |
| 사용자 정보 실패 또는 보류 + 통계 성공 | 기존 사용자 정보 확인 표현과 독립적으로 성공한 통계가 표시된다. 통계 재시도가 사용자 정보 요청을 새로 시작하지 않는다. |
| 마지막 확인값 유지 | 이전 성공값이 0/0인 경우를 포함해 재조회 지연·실패에서도 두 수치를 보존하고 해당 안내를 표시한다. 재시도 성공 시 함께 교체한다. |
| 진입·연속 입력·중복 소비자 | 같은 계정의 유효한 진행 중 조회를 공유하고 실제 중복 통신을 만들지 않는다. |
| 전체 10초와 인증 갱신 | 인증 갱신과 재요청 시간을 합쳐 10초에 실패한다. 늦게 합류해도 원래 마감이 유지되고 새 수동 재시도에만 새 10초를 부여한다. |
| 마이 이탈·복귀 | 다른 화면에서 조회가 완료되면 같은 계정의 마지막 확인값이 갱신된다. 완료 전 복귀는 공유하고 완료 후 재진입은 새 조회를 시작한다. 다른 화면에 통계 오류를 띄우지 않는다. |
| 실패 뒤 마이에 머무름 | 가상 시간을 진행해도 주기적 재시도를 하지 않는다. 다른 마이 메뉴를 사용할 수 있다. |
| 계정 전환·로그아웃·앱 재실행 | 이전 계정의 값이 지워지고 늦은 응답이 노출되지 않는다. 로그아웃 취소·유효 세션의 일반 실패로 불필요하게 값을 지우지 않는다. 새 앱 실행에는 마지막 확인값이 영속 복원되지 않는다. |
| 만료·이전 세대의 늦은 성공/401 | 새 수치·계정·토큰을 덮어쓰거나 종료된 요청 때문에 추가 인증 갱신·로그아웃을 일으키지 않는다. |

| 일반 오류와 실제 인증 만료 | 네트워크·503 등에서는 세션·홈을 보존하고, 현재 요청의 최종 인증 실패에서는 기존 인증 복구로 이동한다. |
| 기존 콘텐츠 갱신·누적 의미 | 콘텐츠 변경 후 통계 갱신을 유지하며, 페이지 길이나 삭제 후 현재 보관량으로 숫자를 바꾸지 않는다. 이전 결과가 새 값을 되돌리지 않는다. |

### 기존 회귀 검사와 실행 증거

- 기존 사용자 Repository의 계정 초기화·이전 응답 차단 검사, 계정 연결 취소 후 통계 보존 검사, 페이지 개수와 서버 통계의 분리 검사를 유지·보완한다. 주 통합 경계에서 재현 가능한 동작을 불필요하게 하위 테스트로 중복하지 않는다.
- 서버 통계 API의 반복 열람·삭제 후 누적 기록 유지·계정 격리 검사는 기존 계약의 선례다. 서버 동작을 바꾸지 않으므로 새 서버 테스트 구조를 만들지 않는다.
- 구현 시 관련 재현 테스트와 필수 전체 검사를 수행한다. 자동 테스트·정적 검사·빌드 결과는 네이티브 실행 결과와 구분한다.
- 화면 코드를 수정하기 전에 변경 전 화면과 기준 Figma 조회 시점을 확보한다. 변경 후에는 iOS Simulator와 Android Emulator 양쪽에서 상태별 화면·재시도·이탈/복귀·다른 메뉴 이동·글자 배율 1/2·안전 영역·영향받는 스크롤을 실제 실행한다.
- 플랫폼별로 같은 기종·크기·데이터·상태·배율·스크롤 위치를 맞춰 변경 전·후·Figma 기준을 나란히 전달한다. 새 오류 상태의 근거는 사용자 승인 시안이며, 존재하지 않는 Figma 상태 화면이나 변경 전 화면을 만들어 채우지 않는다.
- 기종·OS·시나리오·결과와 플랫폼별 스크린샷을 첨부한다. 재시도 전환처럼 움직임이 필요한 경우 영상도 전달한다. 실행이 막히면 구체적인 이유와 미검증 범위를 기록한다.
- 이 스펙 작성 중 제품 테스트·네이티브 검증을 수행했다는 의미는 아니다. 실제 OAuth·운영 서버·실기기 증거는 별도로 구분한다.

## Out of Scope

- 통계 API·DB 스키마·집계 기준 변경, 기간/고유 콘텐츠 집계 추가, 과거 미기록 자료의 추정·보정.
- 정상 통계 라벨 변경, 마이 전체 개편, 사용자 정보 전용 오류·복구 화면의 새 설계.
- 마지막 확인값의 디스크 보관·오프라인 보장·기기 간 캐시 동기화·확인 시각 표시.
- 주기적 폴링, 실시간 수치 보장, 연결 복구나 앱 복귀만으로 반복하는 새 자동 재시도.
- 홈 최초 불러오기 정책 변경, 전면 오류·스켈레톤 추가, 모든 API에 대한 전역 10초 제한.
- 인증·게스트 연결·로그아웃·네이티브 공유의 별도 제품 정책 변경.
- 이미지 저장소 전환, 인프라·운영 설정 변경, 실기기·실제 OAuth 공급자·운영 서버 검증.
