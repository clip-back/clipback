# 카테고리 생성·수정의 입력 보존과 실패 복구

2026-10-25 설계 인터뷰의 Q18에서 Q1~Q17을 포함한 전체 정책·디자인을 최종 확정했습니다.
제품 구현은 별도 단계이며 아직 적용하지 않았습니다.
조사 기준·코드 근거·Figma 조회·라운드 이력은 [설계 이력](../history/2026-10-25-category-save-recovery-design.md)을 따릅니다.

## 대상

- 카테고리 생성·수정의 입력 검증, 저장 대기, 결과 확인과 실패 복구를 다룹니다.
- 이름과 선택한 색상을 [카테고리 입력 초안](../../GLOSSARY.md)으로 부릅니다.
- 정상 화면은 기존 E10 생성 `111:4376`·E11 수정 `111:4427`을 기준으로 확인합니다.
  새 대기·오류 상태의 문구·배치는 Q16의 사용자 승인 시안을 따릅니다.
- 응답 유실 후 같은 제출을 복구하기 위한 서버 API·DB 지원도 포함합니다.
  선택 이유와 기존 서버만 사용하는 대안의 한계는 [결정 기록](../adr/0001-category-save-retry-results.md)을 따릅니다.

## 합의한 정책

- **Q1:** 생성·수정 모두 저장 결과를 기다리는 동안 현재 입력 시트를 유지합니다.
  성공을 확인했을 때만 시트를 닫으며, 실패하면 작성한 이름과 선택한 색상을 같은 시트에서 유지합니다.
- **Q2:** 입력 초안의 보존 범위는 현재 시트입니다. 사용자가 직접 닫거나 앱을 종료한 뒤 복원하지 않습니다.
  다시 열면 생성은 새 입력으로, 수정은 현재 저장된 값으로 시작합니다.
- **Q3:** 생성·수정의 저장 성공 응답을 받으면 시트를 닫습니다. 후속 목록·통계 갱신만 실패한 경우를
  저장 실패와 구분하며, 그 이유로 저장을 다시 실행하지 않습니다. 후속 조회 실패 안내는 Q15를 따릅니다.
- **Q4:** 저장 대기 중 이름·색상 편집과 버튼·키보드 완료의 추가 제출을 막습니다.
  실패하거나 결과 확인 대기가 끝나면 초안을 유지하고 다음 행동을 선택할 수 있게 합니다.
  결과 미확인 상태의 편집 제한은 Q10을 따릅니다.
- **Q5:** 저장 대기 중 바깥 영역 터치·드래그·뒤로가기로 입력 시트를 닫지 못하게 합니다.
  키보드만 숨기는 동작은 허용합니다. 대기가 끝나면 Q2대로 직접 닫아 초안을 버릴 수 있습니다.
- **Q6:** 생성·수정 한 번의 저장은 인증 갱신·재요청을 포함해 전체 10초까지만 기다립니다.
  요청 단계마다 제한 시간을 새로 시작하지 않으며, 후속 목록·통계 갱신은 이 저장 대기에서 제외합니다.
  대기 상한에 도달하면 시트 닫기 잠금을 풀되, 응답을 받지 못했다는 이유만으로 저장되지 않았다고 단정하지 않습니다.
  이때 이름·색상과 새 저장의 제한은 Q10을 따릅니다.
- **Q7:** 앞뒤 공백을 제거한 전송 이름을 서버와 같은 Unicode code point 기준으로 검사합니다.
  빈 이름과 40자 초과 이름은 저장을 막고 수정 안내를 표시합니다. 초과 입력·붙여넣기를 자동으로 자르지 않으며,
  한글 조합 중인 입력을 훼손하지 않습니다. 정확한 안내 문구·배치는 Q16을 따릅니다.
- **Q8:** 서버가 제출별 식별자와 처리 결과를 보관하도록 확장합니다. 응답을 놓친 같은 제출의 재시도는
  기존 처리 결과를 재사용하고 처리 중인 제출은 중복 실행하지 않습니다. 내용 변경·시트 재진입의 처리 범위는
  Q10·Q11을 따르며 결과 확인 UI는 Q16을 따릅니다.
- **Q9:** 실제 계정이 바뀌거나 로그아웃이 완료되면 입력 시트를 닫고 초안을 비웁니다.
  이전 계정의 늦은 응답은 현재 화면에 반영하지 않습니다. 같은 계정의 인증 토큰 갱신 중에는 초안을 유지하고,
  최종 인증 만료는 기존 로그인 복구 절차를 따릅니다. 시트 닫기를 서버 저장 취소로 취급하지 않습니다.
- **Q10:** 저장 결과 미확인 중에는 제출한 이름·색상을 유지하고 편집과 다른 내용의 새 저장을 막습니다.
  ‘결과 다시 확인’은 같은 제출 식별자를 사용해 한 번에 새 10초까지만 기다립니다. 성공하면 시트를 닫고,
  서버가 저장을 거절했음이 확인되면 입력을 고쳐 다시 제출할 수 있게 합니다. 실패 뒤 백그라운드 자동 재전송은 하지 않습니다.
  저장 결과 미확인 중에도 Q11의 안내·확인 후 시트를 직접 닫을 수 있습니다.
- **Q11:** 같은 제출의 복구는 현재 시트에서 제공합니다. 직접 닫거나 앱을 종료한 뒤 초안·제출을
  자동 복원하거나 재전송하지 않습니다. 결과 미확인 중 직접 닫을 때는 닫아도 서버 저장이 완료될 수 있음을
  안내하고 확인받습니다. 다시 진입하면 서버 목록을 갱신한 뒤 새로 시작합니다. 목록에 아직 없다는 사실만으로
  이전 저장의 추후 반영을 배제하지 않습니다. 기기에 제출 식별자를 영속 보관하는 기능은 첫 구현에서 제외합니다.
- **Q12:** 이름 중복·입력 오류로 저장을 거절당하면 초안을 유지하고 수정할 수 있게 합니다.
  같은 이름이 있다는 이유로 기존 카테고리와 자동 병합하거나 성공으로 처리하지 않습니다.
  서버가 미반영을 확정한 거절 뒤 다시 저장하면 새 제출로 처리합니다. 수정 대상이 삭제됐다면 자동 생성하지 않고,
  이름·색상을 시트에 남겨둔 채 안내와 ‘목록으로 돌아가기’를 제공합니다. 정확한 문구·배치는 Q16을 따릅니다.
- **Q13:** 원래 제출의 성공 기록을 확인하면 시트를 닫고 최신 목록을 불러옵니다. 그 뒤 다른 기기에서
  수정·삭제한 상태를 되돌리지 않으며 원래 쓰기를 다시 실행하지 않습니다. 원래 제출의 성공 사실과
  현재 카테고리 상태를 구분합니다.
- **Q14:** 서버의 제출 식별자와 복구에 필요한 최소 처리 결과는 첫 구현에서 자동 만료시키지 않습니다.
  카테고리를 삭제해도 재실행 방지를 위해 기록은 유지하고 계정 탈퇴 때 함께 삭제합니다.
  이름·색상·처리 결과 등 복구에 필요한 정보만 보관하며 이미지·콘텐츠 본문은 포함하지 않습니다.
  서버 기록 보관은 Q11의 시트 종료 뒤 자동 복구 제외와 구분합니다.
- **Q15:** 저장 성공 뒤 카테고리 목록 갱신만 실패하면 시트는 닫힌 상태를 유지하고 기존 스낵바에
  ‘저장은 완료됐지만 카테고리 목록을 새로 불러오지 못했어요’와 ‘다시 불러오기’를 표시합니다.
  이 행동은 카테고리 목록만 다시 조회하며 인증 갱신 포함 전체 10초로 제한합니다. 저장을 반복하지 않고
  마지막 확인 목록도 비우지 않습니다. 콘텐츠 조회 오류는 각 목록의 기존 복구를, 통계 오류는 마이 통계의 기존 안내·재시도를 유지합니다.
- **Q16:** 아래 시트 디자인의 문구·배치를 확정했습니다. 정상 외형은 유지하며 글자 확대 시 줄바꿈·높이 확장을 허용합니다.
  키보드가 보이거나 높이가 작으면 스크롤로 입력·안내·버튼에 접근할 수 있어야 합니다.
- **Q17:** ‘결과 다시 확인’은 원래 저장 의도를 이어가는 행동입니다. 이미 처리했다면 기록한 결과를 재사용하고,
  서버에 도달하지 않아 아직 처리하지 않았다면 원래 제출한 이름·색상의 저장을 진행할 수 있습니다.
  이미 처리 중이면 중복 실행하지 않고 결과를 기다립니다. 단순한 목록 조회와 구분합니다.

## 구현 명세에서 구체화할 기술 경계

- 서버의 미반영이 확정된 거절과 결과 미확인을 구별하는 응답 계약을 정합니다. 네트워크 단절·성공 본문 파싱 실패·5xx만으로
  미반영을 단정하지 않으며, 현재 카테고리 목록이나 같은 이름의 존재로 원래 제출의 성공을 추정하지 않습니다.
- 계정·작업 종류·수정 대상·제출 내용의 일치 확인, 같은 제출의 동시 실행 방지와 변경·결과 기록의 원자성을 보장합니다.
  기록의 구체적인 스키마·응답 형식은 이 정책을 충족하도록 구현 명세에서 정합니다.
- 기존 앱의 API 호환을 유지하며 제출 식별자를 사용하는 요청에 새 복구 보장을 적용합니다.
  새 회원 탈퇴 기능은 이번 카테고리 복구 범위에 추가하지 않습니다.
- 한 대기 시도의 10초가 끝난 뒤 도착한 응답으로 시트를 자동으로 닫거나 상태를 뒤집지 않고,
  현재 유효한 수동 재확인 시도의 결과만 반영합니다. 계정·닫힌 시트의 이전 응답도 차단합니다.

## 확정한 시트 디자인

Q16에서 사용자 승인한 표현입니다. 표시 검토용 시안을 확인했으며 제품 적용·네이티브 실행 검증 전입니다.

- 정상 시트의 폴더·이름·기존 8색·검은 버튼과 노란 버튼 글자는 E10·E11을 기준으로 유지합니다.
- 입력 오류는 이름 아래 8px에 12px·줄 높이 18px로 표시합니다. 처음 열린 빈 생성 시트에는 오류를 보이지 않고,
  편집한 이름을 비웠을 때 빈 이름 안내를 표시합니다. 초과·중복 오류는 해당 원인이 확인됐을 때 표시합니다.
- 저장·결과 확인 안내는 색상 선택 아래 16px에 12px·줄 높이 18px로 표시하고, 안내 아래 24px에 기본 버튼을 둡니다.
  안내가 없는 정상 상태의 기존 간격은 유지합니다. 대기 중 버튼에는 진행 문구를 표시하고 비활성화합니다.
- 글자 확대 시 안내·버튼 글자를 줄이지 않고 줄바꿈·높이 확장을 허용합니다. 실제 키보드가 보이거나 화면 높이가 작으면
  입력·안내·버튼까지 스크롤로 접근할 수 있어야 하며 기존 키보드 숨기기는 유지합니다.
- 결과 미확인 상태에서 닫기 확인은 기존 팝업 스타일을 재사용합니다. 제목은 ‘입력 창을 닫을까요?’,
  본문은 ‘닫아도 서버 저장은 완료될 수 있어요. 작성한 내용은 이 창에서 사라져요.’,
  행동은 ‘계속 확인하기’·‘닫기’를 사용합니다.

| --- | --- | --- |
| 빈 이름 | 카테고리 이름을 입력해 주세요. | 생성하기/수정하기 비활성 |
| 40자 초과 | 이름은 40자 이내로 입력해 주세요. | 생성하기/수정하기 비활성 |
| 이름 중복 | 같은 이름의 카테고리가 있어요. 다른 이름을 입력해 주세요. | 이름 수정 후 생성하기/수정하기 |

| 결과 미확인 | 저장 결과를 확인하지 못했어요. 이미 저장됐을 수 있어요. 결과를 다시 확인해 주세요. | 결과 다시 확인 |
| 재확인 중 | 저장 결과를 확인하고 있어요. | 확인 중… 비활성 |

| 그 밖의 확정된 저장 거절 | 카테고리를 저장하지 못했어요. 입력은 그대로예요. 다시 시도해 주세요. | 생성하기/수정하기 |
| 성공 확인 | 시트를 닫으므로 별도 성공 화면을 추가하지 않음 | 없음 |
