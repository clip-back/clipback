# 마이 통계의 조회 상태와 복구 정책

2026-10-24 사용자 최종 확인으로 첫 구현의 정책과 화면 디자인을 확정했습니다.
현재는 제품 구현 전입니다. 이 문서는 확정한 정책을 관리하며, 구현 명세나 구현 완료 보고가 아닙니다.
조사 기준과 근거는 [설계 이력](../history/2026-10-24-account-stats-recovery-design.md)을 참고합니다.
구현 계약은 [구현 스펙 #80](https://github.com/clip-back/clipback/issues/80)에 게시했으며 [본문 사본](account-stats-recovery-spec.md)을 보존합니다. 게시·검증 경계 확인은 [명세 작성 이력](../history/2026-10-24-account-stats-recovery-spec.md)을 참고합니다.
구현 티켓은 #80의 하위 이슈로 관리합니다. 승인한 분할과 선행 관계의 검증 결과는 [티켓 작성 이력](../history/2026-10-24-account-stats-recovery-tickets.md)을 참고합니다.

## 합의한 범위

- 첫 구현은 마이 화면의 ‘저장한 콘텐츠·다시 본 콘텐츠’ 두 수치에 대한 조회 대기·실패·복구를 다룹니다.
- 서버 API와 누적 집계 기준은 유지합니다. 정확한 의미는 [용어집](../../GLOSSARY.md)의 마이 통계를 따릅니다.
- 정상 응답의 실제 0건과 아직 확인하지 못한 상태를 구분하며, 조회 실패를 0으로 대체하지 않습니다.
- 같은 계정에서 한 번 정상 조회했다면 다음 조회가 늦거나 실패해도 마지막 확인값을 유지하고 그 의미를 구분해 표시합니다.
- 마지막 확인값의 보존 범위는 현재 앱 실행 동안입니다. 계정 전환·로그아웃 완료 시 비우며 디스크 영속 보관은 포함하지 않습니다.
- 통계의 비인증 실패는 홈 진입을 막지 않습니다. 유효한 최종 인증 실패와 계정 소유권 처리는 기존 인증 복구 정책을 따릅니다.

## 조회와 복구

- 마이 화면에 진입할 때 통계를 한 번 갱신합니다. 다른 화면에서 마이로 돌아오면 다시 한 번 조회합니다.
- 같은 계정의 조회가 진행 중이면 함께 사용하고 중복 요청을 만들지 않습니다.
- 실패하면 사용자가 ‘다시 시도’로 복구합니다. 마이에 머무는 동안 주기적으로 재시도하지 않습니다.
- 기존 콘텐츠 변경 후 통계 갱신은 유지합니다.
- 새 통계 조회와 수동 재시도는 인증 갱신을 포함해 한 번의 전체 조회에 10초를 적용합니다.
- 진행 중인 조회를 함께 사용할 때는 남은 시간만 기다립니다. 수동 재시도는 새 10초를 시작합니다.
- 10초 안에 완료하지 못하면 조회 실패 상태로 전환합니다. 홈 필수 목록의 전체 15초 정책은 유지합니다.
- 앱 안에서 마이를 벗어나도 같은 계정의 진행 중인 조회는 남은 제한 시간 동안 유지합니다. 성공하면 마지막 확인값을 갱신하고, 완료 전에 마이로 돌아오면 같은 조회를 함께 사용합니다.
- 계정 전환·로그아웃 뒤에는 이전 계정의 조회 결과를 반영하지 않습니다. 실패 안내는 통계 주변에만 표시합니다.
- 제한 시간을 넘겼거나 이후 조회·계정 전환으로 무효화된 응답은 수치와 인증 상태를 바꾸지 않습니다. 현재 유효한 요청의 인증 갱신·최종 인증 실패 처리는 기존 정책을 유지합니다.

## 사용자 정보와의 관계

이름·계정 정보의 일시 조회 실패와 통계 조회 결과를 분리합니다.
현재 로그인한 계정의 통계 조회가 성공하면 사용자 정보 조회가 실패했더라도 두 수치를 반영합니다.
통계의 ‘다시 시도’는 통계만 조회합니다. 이름·계정 정보의 기존 확인 상태와 조회 흐름은 유지하며,
실제 인증 만료는 기존 인증 복구 절차를 따릅니다.

## 안내 범위

조회 대기·실패·재시도와 마지막 확인값 안내는 통계 패널 바로 아래에 표시합니다.
기존 검은 통계 패널의 정상 표현을 기준으로 하며 다른 마이 메뉴는 계속 사용할 수 있습니다.
문구와 숫자 표시 규칙은 아래와 같이 합의했습니다. 배치·스타일·확대 표현은 아래 디자인 기준을 따릅니다.

| 상태 | 두 수치 | 안내 | 복구 동작 |
| --- | --- | --- | --- |
| 첫 조회 중 | 각각 `—` | 통계를 불러오는 중이에요 | 조회 완료 또는 제한 시간까지 대기 |
| 첫 조회 실패 | 각각 `—` | 통계를 불러오지 못했어요 | 다시 시도 |
| 마지막 확인값이 있는 재조회 중 | 마지막 확인값 | 마지막 확인값 · 새로 불러오는 중 | 조회 완료 또는 제한 시간까지 대기 |
| 마지막 확인값이 있는 재조회 실패 | 마지막 확인값 | 마지막 확인값 · 새로 불러오지 못했어요 | 다시 시도 |
| 조회 성공 | 서버 응답 수치. 실제 0은 `0` | 위 상태 안내 없음 | 다음 마이 진입 또는 기존 갱신 시 재조회 |

## 디자인 기준

J01의 정상 통계 영역을 기준으로 합니다. 확인한 J01 노드에는 통계 전용 대기·실패·재시도 표현이 없습니다.
새 상태는 대화 내 시안에서 확인한 아래 배치를 첫 구현 기준으로 채택했습니다.
Figma 원본에 새 상태가 추가되었다는 의미는 아니며, [현재 디자인 기준](../figma-ui-alignment-plan.md#figma-current-account-stats)에 승인 범위를 기록합니다.

### 합의한 배치

정상 Figma 패널을 보존하면서 새 상태에 아래 표현을 적용합니다.

- 정상 통계 패널의 두 열·색상·모서리와 1배율 기준 높이 80px을 유지합니다.
- 상태 안내는 패널 아래 10px 간격에 12px 보조 글자로 표시합니다.
- 실패 시 안내 아래 8px 간격에 왼쪽 정렬의 ‘다시 시도’를 둡니다. 글자 14px·모서리 8px의 중립색 테두리 버튼이며 최소 누름 영역은 88×44px입니다.
- 성공하면 안내와 재시도 버튼을 숨깁니다. 뒤의 관리 메뉴는 기존 세로 흐름을 따릅니다.
- 글자 확대 시 안내와 라벨을 자연스럽게 줄바꿈하고 패널·버튼의 높이를 늘립니다. 두 수치의 세로 위치를 맞추고 문구를 잘라내지 않습니다.
- 시안의 218·72는 Figma의 예시 수치입니다. 재시도 동작은 표시 확인용 대역이며 실제 API 요청이나 10초 제한을 구현한 것이 아닙니다.
