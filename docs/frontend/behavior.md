# 프론트 동작과 상태 처리

현재 앱의 세션·저장·탐색·실패 복구와 화면 상태의 기준 문서입니다. 코드 구조·빠른 실행은 [프론트 README](../../frontend/README.md), 설정·검증은 [개발 안내](development.md)를 따릅니다.
일반 수동 저장과 네이티브 공유 저장의 재시도 범위는 각 절에서 구분합니다. 이 문서 이동으로 동작을 바꾸거나 새 검증을 수행하지 않았습니다.
본문의 `lib/`·`test/` 코드 경로는 저장소의 `frontend/` 기준입니다. 저장소 루트 기준 경로는 `frontend/` 접두사를 함께 표기합니다.

## 읽는 순서

- 인증·세션: 초기 복원, 모바일 소셜 로그인, 토큰 저장·동시 갱신
- 콘텐츠: 저장·분류, 원본 이미지, 피드·상세, 변경·삭제 실패 복구
- 플랫폼 공통: 안전 영역·네이티브 공유·백엔드 연결 경계
- 추천: 아래 추천 프론트 연결 계약. 선정 정책은 [콘텐츠 재발견 정책](../content-recommendation-plan.md)을 따릅니다.

## 초기 세션 복원과 재시도

- 앱 시작에는 A01을900ms 표시하면서 세션 복구를 병렬 실행합니다. 이후 복구 완료 시 기존 로그인/홈, 진행/오류 시 기존 복구·재시도 화면으로 이어집니다. 카테고리·피드 조회가 끝나기 전에는 홈·샘플 콘텐츠·저장 기능을 노출하지 않습니다. 공유 준비/안내·UI 효과·최신 저장 실패 배너는 후속 첫 프레임 뒤 재개하며 보안 차단·세션 무효화·Apple credential 확인은 지연하지 않습니다.
- 세션 확보 뒤 홈 최초 불러오기는 한 시도 전체에 최대15초를 적용합니다. 카테고리·홈 목록의 단계 변경과 인증 갱신·재전송도 같은 예산을 사용하며, 토큰 저장소 읽기와 소셜 인증 자체는 포함하지 않습니다. 카테고리와 첫 홈 목록이 준비되면 사용자 정보·통계 완료를 기다리지 않고 홈을 엽니다. 정상적인 빈 목록도 성공이며, 합의한 최소900ms 로딩 표시를 적용합니다. 온보딩·신규 게스트·계정 연결·홈 진입 후 일반 재조회에는 이 전면 로딩을 새로 적용하지 않습니다.
- 최초 홈의 사용자 정보·통계는 최대10초 동안 후속 조회하며, 유효한 결과만 같은 계정에 반영합니다. 콘텐츠 변경 후 새 계정·통계 조회가 시작되면 그보다 먼저 시작한 최초 홈 응답은 반영하지 않습니다. 확인 전에는 기존 ‘계정 정보 확인 중’을 표시하고, 부가 조회의 비인증 오류·무응답 때문에 열린 홈을 전면 오류로 바꾸지 않습니다. 후속 조회 종료·계정 변경·폐기 뒤 늦은 응답은 데이터와 토큰을 바꾸지 못하며, 현재 요청이 공유한 인증 갱신은 유지합니다. 기존 최종401와 Apple 인증 철회 처리도 유지합니다.
- 저장소 읽기 실패, 조회의 403·서버 오류·연결 실패·응답 파싱 실패에는 세션을 보존하고
  “저장한 콘텐츠를 불러오지 못했어요.”와 “다시 시도” 버튼을 표시합니다.
- 필수 조회 실패·전체15초 초과 시 기존 오류 안내와 ‘다시 시도’를 표시합니다. 홈 불러오기 재시도는 현재 메모리 세션으로 카테고리와 첫 홈 목록을 다시 읽는 새로운15초 시도이며, 최소900ms 캐릭터 로딩을 유지합니다. 연속 입력은 한 시도만 시작하고, 시간 경과·연결 회복·앱 복귀만으로 자동 재시도하지 않습니다. 실패·시간 초과한 시도의 필수·부가 조회와 늦은 인증 응답은 복구 화면·다음 시도·현재 데이터와 토큰을 바꾸지 못합니다. 정상 홈 진입 뒤 부가 조회는 별도의10초 범위에서 계속합니다.
- 현재 요청에서 확인된 최종401·Apple 철회는 홈 제한 시간 중 서버 로그아웃·공유 인증 차단이 지연돼도 로컬 접근 차단과 세션 삭제 복구를 따릅니다. 이전 차단 작업이 나중에 완료돼도 새 시도의 세션을 삭제하지 않습니다. 끝난 시도에서 뒤늦게 도착한 SDK 결과는 현재 세션을 무효화하지 않으며, 현재 시도의 Apple 확인과 홈 진입 후 늦게 확인된 Apple 계정의 보안 확인은 유지합니다.
- API의 토큰 갱신·재요청 후에도 최종 401이면 저장소 삭제 성공 후 로그인·게스트 선택으로 돌아갑니다.
  삭제에 실패하면 전환을 중단합니다. 만료된 세션을 새 게스트로 자동 교체하지 않습니다.
- 저장된 세션이 없는 최초 실행은 로그인·게스트 선택을 표시합니다. 사용자가 게스트를 선택해
  발급받은 세션은 조회 실패 후에도 유지합니다.
  프로필·통계의 비인증 오류는 홈 진입을 허용하고, 최종 401은 인증 만료로 처리합니다.
- 저장·조회 중에도 보호 API의 최종 401이면 저장소 삭제 후 로그인 선택으로 돌아갑니다.
  공급자 인증 자체의 401은 기존 게스트 세션 만료와 구분합니다.

## 마이 통계 조회와 복구

- 통계는 서버가 반환하는 누적 저장·재열람 기록 수다. 현재 보관량이나 페이지 길이로 대체하지 않으며, 삭제를 이유로 화면에서 임의로 차감하지 않는다.
- 최초 대기·실패는 `—`로 표시하며, 실제0은 정상 응답 후0으로 표시한다. 이름·계정 정보 조회가 늦거나 실패해도 성공한 통계는 독립적으로 표시한다.
- 탭·계정·공지·시스템 뒤로가기 등 다른 화면에서 실제 마이 진입 시 한 번 갱신한다. 재빌드·탭 재선택·앱 복귀·시간 경과만으로 자동 재조회하지 않는다. 실패하면 통계 아래 ‘다시 시도’를 사용한다.
- 유효한 진행 중 조회는 같은 요청과 남은 시간을 공유한다. 인증 갱신·재요청 포함 전체10초이며, 새 수동 재시도에만 새10초를 부여한다. 마이 이탈만으로 요청을 취소하거나 다른 화면에 통계 오류를 띄우지 않는다.
- 같은 계정의 이번 앱 실행에서 성공한 두 수치는 지연·실패에도 보존하고 ‘마지막 확인값’임을 안내한다. 0/0도 보존한다. 계정 초기화·로그아웃 완료 때 비우며 디스크에 저장하지 않는다. 취소·유효 세션의 일반 오류는 수치를 지우지 않는다.
- 콘텐츠 변경 후 통계도 같은 상태·요청 수명 계약을 사용한다. 성공한 통계는 프로필 완료 전에 반영하되, 기존 공유 수신의 후속 조회 실패·receipt 재시도 판정은 유지한다. 현재 최종401은 기존 인증 복구를 따르고, 종료·무효화된 요청의 늦은 응답은 현재 값·인증을 바꾸지 못한다.
- 정상 J01 통계 패널을 보존하고 안내·실패 시 버튼은 패널 바로 아래에 둔다. 글자 확대 시 줄바꿈·높이 증가·두 수치 정렬을 허용하며 다른 메뉴와 스크롤을 계속 사용할 수 있다. 문구와 치수는 [확정 정책·디자인](account-stats-recovery.md), 실제 검증 범위는 [구현 이력](../history/2026-10-25-account-stats-recovery-implementation.md)을 따른다.

## 모바일 소셜 로그인

Android는 Google·카카오, iOS는 Google·카카오·Apple을 지원합니다. 웹·데스크톱에는 소셜 버튼을
표시하지 않으며 게스트 사용은 유지합니다. 최초 실행·로그아웃 후 로그인 또는 게스트 사용을 선택합니다.
새 게스트·새 소셜 계정은 온보딩으로, 기존 계정·게스트의 소셜 승격은 홈으로 이동합니다.

- 게스트의 계정 연결은 `/auth/social/{provider}/upgrade`를 사용해 기존 콘텐츠를 유지합니다.
  이미 연결된 소셜 계정으로 409가 오면 게스트 데이터를 합치지 않는다는 경고를 표시합니다.
  **기존 계정으로 전환**을 확인한 경우에만 SDK 인증부터 다시 시작합니다. 취소하면 게스트를 유지합니다.
- 계정당 소셜 공급자는 한 종류입니다. 회원 화면에 다른 공급자를 추가 연결하는 기능은 없습니다.
  Apple 계정은 현재 지원 범위에서 iOS로만 로그인할 수 있습니다. 같은 이메일의 Google·카카오 계정을 자동으로 합치지 않습니다.
- 게스트 승격의 401은 일회용 코드를 자동 재전송하지 않고 `/users/me`로 게스트 세션을 별도 확인합니다.
  정상 게스트는 유지하며, 다시 연결하려면 새 SDK 인증부터 시작합니다.
- SDK에서 사용자가 취소하면 화면과 세션을 유지합니다. 카카오톡 취소·동의 거절은 카카오계정 로그인으로
  이어지지 않습니다. 카카오톡 미설치 또는 취소 이외의 실패 때만 계정 로그인으로 진행합니다.
- Google·카카오의 ID token을 백엔드에 전달합니다. 카카오는 OpenID Connect 설정이 필요하며
  `idToken`이 없으면 오류를 표시합니다. access token을 대신 보내지 않습니다.
- Apple은 서버 challenge의 nonce를 네이티브 인증에 전달하고 identity token·authorization code·challenge ID를
  백엔드에 전송합니다. 최초 제공되는 이름만 함께 보냅니다. 재시도와 계정 전환은 새 challenge·code를 사용합니다.
- 성공한 Apple 로그인의 사용자 식별자는 `clipback.apple_user_id`에 별도 저장합니다. 기존
  `clipback.session` JSON 형식은 유지합니다. 앱 복원·포그라운드 복귀·네이티브 취소 알림에서
  Apple credential state를 확인합니다. `revoked`·`notFound`가 확인되면 로그인 선택으로 돌아가고,
  조회 실패·로컬 식별자 없음은 취소로 판단하지 않습니다.
- 일반 로그아웃은 Clipback 세션과 기기 SDK 상태를 정리합니다. Google은 `signOut`, 카카오는
  로컬 token manager `clear`를 사용합니다. 공급자 연결 해제·동의 철회·회원 탈퇴는 하지 않습니다.

소셜 공급자 ID·URL scheme·서명 설정과 검증 범위는 [소셜 개발 설정](development.md#공개-앱-설정)을 따릅니다.

## 갱신 토큰 저장

- 게스트 생성·토큰 갱신·소셜 인증으로 새 세션을 받으면 메모리에 적용한 뒤 바로 저장을 시도합니다.
  토큰 갱신으로 인한 원래 요청의 재시도는 저장 시도가 끝난 뒤 실행합니다.
- 토큰과 만료 정보는 `clipback.session`의 JSON 한 값으로 저장합니다. 새 키가 없을 때만 기존 네 키를
  읽으며, 새 값이 손상됐다면 이전 토큰으로 되돌아가지 않고 초기 복원 오류로 처리합니다.
  기존 세션은 읽기만으로 변환하지 않고 다음 발급·갱신부터 새 형식을 사용합니다.
- 저장과 삭제는 같은 큐에서 순서대로 처리합니다. 삭제는 기존 키들을 먼저 제거하고 새 키를 마지막에
  제거합니다. 저장·삭제 API의 `false` 반환과 예외는 실패로 처리합니다.
- 저장 실패 시 새 메모리 토큰으로 현재 작업을 계속하며 다음 배너와 **다시 저장** 버튼을 표시합니다.
  “로그인 정보를 기기에 저장하지 못했어요. 앱을 종료하기 전에 다시 저장해 주세요.”
- **다시 저장**은 현재 메모리의 최신 세션만 저장합니다. 토큰 갱신·콘텐츠 저장·카테고리 작업은
  반복하지 않으며, 저장 중 중복 실행을 막고 최신 세션 저장 성공 시 안내를 제거합니다.
- 저장 실패를 해결하기 전에 앱을 종료하면 계정 복원이 보장되지 않습니다. 저장 성공은 기기 저장 API의
  성공 응답을 기준으로 하며, 기기 장애나 강제 종료에 대한 영구 보존 보장을 뜻하지 않습니다.

## 동시 인증 오류와 로그아웃

다음 보호는 JSON·multipart 공통 요청 경로와 세션 발급에 적용합니다.

- 같은 API 인스턴스의 인증 요청들이 동시에 401을 받으면 진행 중인 refresh를 공유합니다.
  HTTP 응답부터 새 토큰 저장 시도까지 기다린 뒤 원래 메서드·본문을 유지해 한 번만 재요청합니다.
- 이미 갱신이 끝난 뒤 이전 토큰의 401이 도착해도 추가 갱신 없이 최신 토큰을 사용합니다.
  재요청의 최종 401은 호출자에게 전달하며, 갱신 실패 뒤의 새 요청은 다시 갱신할 수 있습니다.
- 세션을 복원·삭제·교체하면 이전 세션에서 시작한 응답은 새 세션을 덮어쓰거나 다른 계정으로
  재전송하지 않습니다. 이 취소는 인증 만료 401과 구분합니다.
- 로그아웃은 진행 중인 갱신과 저장 시도를 기다린 뒤 최신 메모리 토큰을 사용합니다.
  로그아웃 중 새 갱신·인증 재시도를 막고, 나중에 생성된 세션의 저장값과 화면은 보호합니다.
- refresh HTTP 응답 대기는 10초로 제한합니다. 저장 콜백에는 제한을 적용하지 않습니다.
  갱신 실패에도 현재 토큰으로 로그아웃을 시도하지만, 시간 초과는 서버 요청 취소를 보장하지 않습니다.
  서버에서 이미 토큰이 회전했다면 이전 토큰으로 해당 서버 세션을 해제하지 못할 수 있습니다.

## 스크린샷 저장과 인증 재시도

- 만료된 access token으로 업로드가 401을 받으면 공통 refresh를 기다리고, 갱신 토큰 저장 시도가 끝난 뒤
  같은 계정으로 업로드를 한 번만 재전송합니다. 일반 API 요청과 겹쳐도 하나의 갱신을 공유합니다.
- 파일 바이트·파일명·카테고리·태그를 보존해 매 시도마다 새로운 multipart 요청을 구성합니다.
  복수 카테고리·태그는 각각 반복 form part로 모두 보내며, 빈 목록은 생략합니다.
- 링크·사진 저장의 최종 401은 저장된 세션 삭제 후 로그인 선택으로 돌아갑니다.
  자동 게스트 생성·다른 계정으로 재저장은 하지 않습니다. 인증 오류 이외의 저장 실패는 입력과 선택 사진을 유지합니다.
- 업로드 전송 대기와 응답 본문 수신은 각각 10초입니다. 일반 HTTP 오류·연결 실패·시간 초과에는
  자동 재전송하지 않습니다. 실패 후 사용자가 다시 저장할 수 있으며 저장 중 중복 제출은 차단합니다.
- 시간 초과·연결 종료·세션 변경은 서버 저장을 취소하지 않습니다. 서버에서 이미 저장됐다면 수동 재시도로
  중복 콘텐츠가 생길 수 있으며, 일반 수동 저장에는 서버 중복 저장 방지가 적용되지 않습니다.

## 저장된 스크린샷 원본 조회

- 저장한 사진은 상세의 **원본 이미지 보기**와 원문 창에서 인증된 접근 API로 소유권과 파일 존재를 확인한 뒤 내려받습니다.
  Bucket 원본은 120초 서명 URL로 직접 받고, 기존 로컬 원본은 인증된 자산 API로 받습니다.
  확인창의 선택 사진 메모리에 의존하지 않으므로 앱을 재시작한 뒤에도 조회할 수 있습니다.
- 원본 영역을 열 때마다 기존 표시 바이트를 비우고 온라인 접근 확인을 합니다. 같은 상세에서 동시에 여는
  펼침 영역과 원문 창은 진행 중 요청을 공유합니다. 원래 비율을 유지하고 긴 이미지는 세로 스크롤로 확인합니다.
- 기기에는 OS의 앱 전용 캐시 경로에 원본 바이트만 저장합니다. 서버 환경·서버 사용자 ID·자산 ID·SHA-256으로
  키를 분리하고 서명 URL·토큰·접근 정보는 저장하지 않습니다. 같은 계정의 앱 재실행에서도 현재 권한을 확인한 뒤
  크기와 해시가 일치한 캐시를 재사용합니다. 손상·부분 파일은 다시 받고, 쓰기는 임시 파일을 완성한 뒤 확정합니다.
- 캐시는 기본 최대 100MiB이며, 원본 열람 시 7일 미사용 파일과 용량 상한을 넘는 오래된 파일을 정리합니다.
  기기 캐시 정리는 클라우드 원본·계정 보관량을 바꾸지 않습니다. OS가 캐시를 정리해도 다음 온라인 열람에서 다시 받습니다.
  캐시 경로나 디스크 쓰기가 불가능하면 검증된 다운로드 바이트로 열람하며 오프라인으로 대체하지 않습니다.
- 상세 이탈·다른 콘텐츠/자산·계정 전환 시 표시 바이트를 정리합니다. 로그아웃 시작·계정 변경·세션 무효화는
  이전 캐시의 진행 중 읽기·쓰기도 무효화하고 삭제를 대기열에 넣어 늦은 완료가 다시 만들지 못하게 합니다.
  별도 확대·파일 다운로드·오프라인 보관은 제공하지 않습니다.
- 접근 API와 원본 다운로드의 전송 대기·본문 수신은 각각 10초입니다. 인증 API의 최초 401은 기존 공유 토큰 갱신과 저장 시도를
  기다린 뒤 한 번만 재요청합니다. 인증 API의 최종 401은 로그인 선택으로 돌아갑니다.
  Bucket 요청에는 앱 토큰·쿠키를 넣지 않고 리다이렉트를 따르지 않습니다. Bucket 403은 접근 정보를 한 번 재발급받고,
  Bucket 오류만으로 세션을 갱신하거나 로그아웃하지 않습니다. 크기(최대 10MiB)·MIME·SHA-256이 일치한 원본만 표시합니다.
- 자산 없음·404·통신 오류·이미지 디코딩 실패를 구분해 안내하며, 다운로드/표시 실패에는 **다시 시도**를
  제공합니다. 자동 반복이나 샘플 이미지 대체는 하지 않으며, 이미지 조회만으로 열람·클릭 이벤트를 늘리지 않습니다.
- 시간 초과와 화면 이탈은 서버 전송 취소를 보장하지 않습니다. 원본은 서버의 소유권 검사와 저장 파일에
  의존하므로 삭제되거나 유실된 파일은 다시 표시할 수 없습니다.

## 콘텐츠 저장과 자동 분류

- 저장 화면은 카테고리를 강제 지정하지 않습니다. 링크는 빈 `category_ids` 목록으로,
  사진은 해당 multipart part 없이 보내 백엔드의 자동 분류를 요청합니다.
  카테고리 이름을 태그로 자동 생성하지 않습니다.
- 저장 확인창은 서버가 반환한 카테고리를 표시합니다. 미분류로 저장돼도 콘텐츠 저장은 성공이며,
  응답에 없는 AI 성공 여부나 실패 원인을 추정하지 않습니다.
- YouTube의 `queued`·`processing`은 동영상 정보를 처리 중이라고 안내합니다.
  확인창은 폴링하지 않으며, 다음 상세 조회나 앱 새로고침에서 최종 카테고리를 반영합니다.
  `completed` 상태여도 추천 결과가 없으면 미분류가 유지될 수 있습니다.
- 수동 카테고리 변경은 기존 상세 화면에서 합니다. 생성의 빈 목록은 자동 분류 요청이지만,
  분류 수정 API의 빈 목록은 미분류 지정이므로 저장 직후 별도 분류 수정 요청을 보내지 않습니다.
  명시적 선택과 기존 API의 복수 카테고리·태그 전송 계약은 유지합니다.

## 피드 추가 조회와 상세 탐색

- 아카이브·분류·북마크·검색은 서버 커서로 20개씩 조회합니다. 남은 스크롤이 300px 이하이면
  다음 페이지를 불러오며, 짧은 화면도 레이아웃 후 같은 기준을 확인합니다.
- 홈은 선택한 분류의 최신 카드 4개를 미리 보여줍니다. 최근 저장한 콘텐츠의 더보기로
  같은 분류의 아카이브에 들어갑니다. 검색은 제출 또는 최근 검색어 선택으로 실행합니다.
- 북마크 우선은 서버의 북마크 페이지들을 먼저 조회하고, 끝나면 일반 콘텐츠 페이지로 이어집니다.
  각 구간은 최신순이며, 복수 분류 콘텐츠도 서버가 반환한 해당 분류 목록에 표시합니다.
- 목록의 `불러온 N개`는 현재 내려받은 수입니다. 카테고리 폴더와 작업 메뉴의 개수는 서버 집계를
  사용하며, 폴더는 마지막 저장 시각 내림차순·동일 시각 ID 오름차순·저장 이력 없는 폴더는 마지막입니다.
- 추가 조회 실패 시 기존 카드와 커서를 유지하고 다시 시도할 수 있습니다. 커서가 유효하지 않으면
  처음부터 다시 불러옵니다. 조회의 최종 401은 저장된 세션 삭제 후 로그인 선택으로 돌아갑니다.
- 상세 이전·다음은 진입한 목록의 순서를 따릅니다. 마지막으로 불러온 카드의 다음을 누르면 추가 페이지를
  기다리며, 전체 끝에서는 순환하지 않습니다. 상세에서 돌아오면 목록과 스크롤 위치를 유지합니다.
- 저장·삭제·분류·북마크 변경 성공 후에는 같은 조건의 첫 페이지를 새로 조회합니다. 열린 상세는 유지하지만
  갱신한 목록에 없으면 이전·다음을 사용할 수 없습니다. 현재 콘텐츠 삭제 시 진입 목록으로 돌아갑니다.
- 커서는 요청 사이의 DB 스냅샷을 보장하지 않습니다. 다른 기기에서 추가한 최신 콘텐츠는 다음 새 조회에
  반영됩니다.

## 콘텐츠 변경과 실패 복구

- 북마크·분류·삭제는 같은 콘텐츠에서 한 번에 하나만 실행합니다. 처리 중 카드와 상세에
  **변경 중…** 또는 **삭제 중…**을 표시하고 해당 콘텐츠의 변경 버튼을 잠급니다.
  다른 콘텐츠 변경과 화면 탐색은 계속 사용할 수 있습니다.
- 북마크와 분류는 목록·검색·열린 상세에 즉시 반영합니다. 실패하면 변경한 필드만 함께 복구하며,
  연결 오류·응답 파싱 오류도 안내하고 잠금을 해제합니다. 최종 401은 로그인 선택으로 돌아갑니다.
- 삭제 중에는 항목과 상세를 유지하고 서버 성공 후 제거합니다. 실패하면 원래 화면과 순서를 유지하며,
  성공 시 그 콘텐츠 상세를 보고 있을 때만 진입 목록으로 돌아갑니다.
- 먼저 시작한 조회가 늦게 끝나도 진행 중이거나 완료된 변경을 되돌리지 않습니다. 검색·필터·계정이
  바뀌면 이전 항목을 새 목록에 삽입하지 않으며, 일반 토큰 갱신은 계정 변경으로 취급하지 않습니다.
- 성공 후 같은 조건의 첫 페이지 갱신이 실패해도 성공한 쓰기를 취소하지 않습니다. 목록의 조회 재시도로
  다시 확인할 수 있습니다. 처리와 후속 조회가 끝나면 같은 콘텐츠를 다시 변경할 수 있습니다.
- 연결 종료·응답 파싱 실패는 서버 변경 취소를 보장하지 않습니다. 실패 시 화면은 마지막 확인값으로
  복구하며, 다음 정상 조회에서 서버 상태를 반영합니다. 기존 인증 갱신 외의 자동 쓰기 재시도는 하지 않습니다.

## 카테고리 생성·수정

- 아카이브·관리의 생성·수정 시트는 서버 성공을 확인한 뒤 닫습니다. 이름·색상은 현재 시트에서 유지하며,
  저장·재확인마다 인증 갱신과 재요청을 포함한 전체10초를 적용합니다. 후속 목록 조회는 시트 완료를 막지 않습니다.
- 이름은 앞뒤 공백을 제거한 전송 값의 Unicode code point 1~40자를 검사합니다. 초과 입력과 한글 조합을
  자르지 않으며, 빈 이름·초과·확인된 중복은 같은 입력에서 수정합니다.
- 기다리는 동안 편집·추가 제출·시트 닫기를 막고, 결과 미확인은 입력을 잠근 채 같은 키로
  **결과 다시 확인**을 제공합니다. 네트워크·5xx·파싱 실패만으로 미반영을 단정하지 않습니다.
- 결과 미확인 시 직접 닫기에는 저장이 완료될 수 있다는 확인창을 표시합니다. 시트 종료 뒤 자동 복원·재전송은
  하지 않으며, 끝난 시도의 늦은 응답은 현재 화면·목록을 바꾸지 않습니다. 과거 성공을 재확인해도 이전
  스냅샷을 현재 목록에 삽입하지 않고 최신 목록을 조회합니다. 전체 정책은 [확정 정책](category-save-recovery.md)을 따릅니다.
- 수정은 현재 저장된 이름·색상에서 시작합니다. 대상이 삭제됐다는 확정 거절은 초안과
  ‘이 카테고리가 삭제되어 수정할 수 없어요.’·‘목록으로 돌아가기’를 제공하며 새 카테고리를 만들지 않습니다.
  수정의 성공 재확인은 이후 다른 수정·삭제를 덮지 않고, 콘텐츠 후속 조회도 시트 완료와 분리합니다.
- 실제 계정 전환·로그아웃 완료는 생성·수정 시트와 열린 닫기 확인창을 함께 닫고 초안·제출을 버립니다.
  같은 계정 토큰 갱신과 실패한 로그아웃 시도는 초안을 유지합니다. 이전 계정의 쓰기·조회·인증 응답과
  남은 스낵바 행동은 새 계정의 화면·목록·세션을 바꾸거나 요청을 시작하지 않습니다.
- 저장·재확인·카테고리 GET의 전체10초는 공유 인증 갱신·토큰 저장 대기·401 재요청을 포함합니다.
  카테고리 대기가 먼저 끝나도 다른 유효한 요청이 소유한 갱신은 유지하며, 끝난 카테고리 요청은
  갱신 완료 뒤 다시 제출하거나 늦은 성공을 적용하지 않습니다. 현재 최종401은 기존 로그인 복구를 따릅니다.

## 카테고리 저장 후 목록 복구

- 성공 응답을 확인하면 시트를 먼저 닫고 카테고리 목록을 따로 조회합니다. 최초 후속 조회와 수동 재조회는
  각각 인증 갱신을 포함한 전체10초이며, 저장·홈 최초 불러오기 대기 시간에 합치지 않습니다.
- 조회가 실패하거나 응답이 없으면 마지막 확인 목록을 유지하고 기존 스낵바에
  ‘저장은 완료됐지만 카테고리 목록을 새로 불러오지 못했어요’와 **다시 불러오기**를 표시합니다.
  재시도는 카테고리 GET만 실행하며 생성·수정·프로필·통계·콘텐츠 조회를 반복하지 않습니다.
- 정상 배열과 정상 빈 배열은 반영합니다. 빈 HTTP 본문·JSON null·잘못된 배열/항목은 실패이며
  이전 목록을 빈 목록으로 바꾸지 않습니다. 카테고리 밖의 공통 디코더 계약은 유지합니다.
- 원래 제출의 성공 기록과 현재 목록을 구분합니다. 현재 목록의 존재·이름·색상을 반영하되
  더 오래된 조회나 이전 계정의 응답·재시도는 현재 목록과 처리 중인 변경을 덮지 못합니다.
  콘텐츠의 기존 목록 오류·재시도와 마이 통계의 마지막 확인값·통계만 재시도는 별개로 유지합니다.

## 카테고리 시트 닫기와 재진입

- 편집·확정 거절 시트를 직접 닫으면 이름·색상과 제출 키의 보존을 끝냅니다. 결과 미확인에서는
  ‘입력 창을 닫을까요?’ 확인을 거치며 **계속 확인하기**는 같은 초안·키를 유지하고 **닫기**는 현재 시트의 복구를 끝냅니다.
  닫기·앱 종료는 서버 저장 취소를 뜻하지 않으며 새 앱에서 자동 복원·재전송하지 않습니다.
- 아카이브·관리의 생성·수정 진입은 인증 갱신을 포함한 별도 전체10초 안에 서버 카테고리 목록을 확인합니다.
  생성은 빈 이름·기본 색상, 수정은 해당 ID의 현재 서버 이름·색상으로 시작합니다. 낙관적 표시를 원본으로 사용하지 않습니다.
- 조회 실패는 마지막 목록을 유지하고 ‘최신 정보를 불러오지 못했어요.’·**다시 불러오기**를 제공합니다.
  재시도는 카테고리 GET만 수행하고 성공한 뒤 새 시트를 엽니다. 저장 완료가 확인되지 않은 경우 완료 문구를 표시하지 않습니다.
- 현재 서버 목록에서 수정 대상 ID가 없으면 승인된 대상 삭제 안내와 **목록으로 돌아가기**를 제공합니다.
  같은 이름의 다른 ID를 대신 선택하거나 카테고리를 만들지 않습니다. 이 조회에서 없다고 이전 미확인 저장의 추후 반영을 배제하지 않습니다.
- 새 조회가 대체한 결과, 떠난 화면·이전 계정의 준비/재시도와 닫힌 시트의 늦은 저장 결과는 새 시트를 열거나 닫지 않습니다.
  성공 재확인은 기록된 과거 상태를 쓰지 않고 현재 목록으로 이후 수정·삭제를 유지합니다.

## 카테고리 삭제

- 카테고리를 삭제해도 콘텐츠·북마크·태그·원본 파일은 보존합니다. 다른 분류가 남으면 유지하고,
  마지막 분류가 없어질 때만 미분류로 이동합니다. 콘텐츠의 전체 분류를 보존하며 화면에는 첫 분류를 표시합니다.
- 확인창을 닫고 해당 폴더에 **삭제 중…**을 표시합니다. 응답 전에 항목을 선제적으로 제거하지 않습니다.
  같은 카테고리 수정·삭제와 삭제 중 분류의 새 지정을 막고, 다른 콘텐츠·카테고리 변경과 탐색은 허용합니다.
- 서버 성공 후 카테고리를 제거하고 집계·로드된 목록·열린 상세를 다시 조회합니다. 삭제된 활성 필터만
  전체 콘텐츠로 바꾸며, 사용자가 다른 필터나 화면으로 이동했다면 유지합니다.
- 삭제 실패는 기존 항목·순서·계정을 유지합니다. 성공 후 조회 실패는 삭제를 되돌리지 않으며,
  **다시 불러오기**는 조회만 재시도합니다. 연결·파싱 실패는 서버의 삭제 취소를 보장하지 않습니다.
- 늦은 조회·콘텐츠 변경 응답·실패 복구에서 삭제 성공한 분류 ID를 제외합니다. 같은 이름의 새 ID는 허용하며
  계정 교체 시 보호 상태를 초기화합니다. 공용 미분류는 삭제할 수 없고 사용자 소유 기본 카테고리는 삭제할 수 있습니다.

## 상단 안전 영역과 헤더

일반 화면의 헤더 높이는 `shared/theme/layout.dart`의 `appHeaderHeight`(64 논리 픽셀)를
사용합니다. 시스템 상태바·노치 높이는 이 64px에 포함하지 않습니다. 각 `Scaffold.body`에서
상단 `SafeArea`를 한 번 적용하며, `PhoneFrame`이나 헤더 안에서 중복 적용하지 않습니다.
공통 하단 내비게이션은 시스템 하단 안전 영역을 유지합니다. 저장 버튼은 별도 저장 창 정책의 `32 + max(viewInsets.bottom, viewPadding.bottom)`을 적용하며 검색 화면의 기존 하단 SafeArea는 유지합니다.

전체 화면 저장 창은 별도 Navigator 경로이므로 자체 SafeArea를 가집니다. 하단 시트는 호출부의
`useSafeArea: true`로 최대 높이를 보호하며, 시트 내용에 일반 화면의 64px 헤더를 강제하지 않습니다.
로그인·온보딩·관심사 선택은 기존 배치를 유지합니다. 홈 헤더만 상단 여백 8px + 내부 높이 56px으로 구성하고 본문과 함께 스크롤합니다. 다른 화면의 `appHeaderHeight` 64px은 유지합니다.

랜덤 보기는 기존 단일 Stack·카드 기하를 유지하고 상·하단 안전 영역 내부의 ClipRect로 드래그 중 시스템 영역 침범을 막습니다.

안전 영역 테스트·프리뷰·기기 자동 순회 명령은 [안전 영역 검증 도구](development.md#안전-영역-검증-도구)를 따릅니다. 현재 화면 대응과 디자인 확인 필요 목록은 [Figma 기준](../figma-ui-alignment-plan.md)에 있습니다.

## Backend integration boundaries

Use the backend public HTTPS domain and `/api/v1` exactly once in request URLs.
Protected APIs require the backend-issued Bearer access token. Account data and
statistics should come from `/users/me` and `/users/me/stats`; display statistics as
누적 저장 / 누적 열람, not current content totals.

Today uses the server recommendation response and opens the recommended detail sequence.
Weekly loads server cards, opens the selected category, and records actual visible-card exposures.
Similar content still filters already-loaded items by category. The feed has no total-count field.
Reminder and notification screens retain mock data; see [MVP scope decisions](../backend-mvp-plan.md).

For public URL and web CORS configuration, follow the
[deployment guide](../railway-deployment.md).

## 모바일 공유 저장

시스템 공유 목록에서 **허투루**를 선택하면 링크·이미지와 저장 계정을 확인하고 바로 저장합니다.
iOS는 Swift Share Extension, Android는 Java `ShareActivity`를 사용합니다. 이 경로는 Flutter
엔진을 새로 띄우거나 기존 수동 저장 화면·홈·상세로 이동하지 않습니다. 외부 공유를 닫으면 송신
앱으로, 본앱에서 대기 초안을 재개한 경우에는 본앱의 원래 화면으로 돌아옵니다.

iOS의 공유 메뉴 경로는 Figma `233:3420`/`233:3430`의 **공유 저장 시트**입니다.

- 보던 화면을 검정 50%로 어둡게 하고 손잡이·노란 "저장하기"·"전송한 정보는 AI가 직접 분류해서 저장할게요!"만 있는
  아래쪽 시트를 바로 띄웁니다. 링크·이미지가 같은 시트를 쓰며 미리보기·저장 계정·초안 삭제는 없습니다.
  확장은 뒤 화면을 흐리게 할 수 없어 흐림은 적용하지 않습니다([디자인 확인 필요](../figma-ui-alignment-plan.md#figma-pending-share-backdrop)).
- 공유 내용을 저장 대기 공유로 보관한 뒤 저장 계정을 확인합니다. 그동안과 저장 중에는 모양 변화 없이 "저장하기"만 막아
  연속으로 눌러도 요청은 한 번입니다.
- 저장하면 시트가 내려가고 "✓ 저장 완료!" 토스트를 약 1.5초(임시값) 보여 준 뒤 송신 앱으로 돌아갑니다.
- 손잡이를 끌어내리거나 배경을 누르면(VoiceOver는 닫기 동작) 닫힙니다. 저장 전이면 보관한 공유를 버리고,
  저장 중이면 결과 미확인 저장 대기 공유로 남깁니다. 준비가 끝나기 전에 닫으면 받기를 취소하고 아무것도 남기지 않습니다.
- 비정상 상태는 OS 알림창(`UIAlertController`)에 분류별 제목·문구로 보여 줍니다([디자인 확인 필요](../figma-ui-alignment-plan.md#figma-pending-share-alerts)).
  공유 확장에서 본앱을 여는 공식 API가 없어 [허투루 열기]는 두지 않고, 로그인 필요 문구로 허투루 앱을 열도록 안내합니다.
  - 받기 거절(지원하지 않는 링크·형식, 여러 항목, 10MiB 초과)과 보관 실패(기기 보관 한도, 이미지·상태 파일 쓰기 실패)는
    보관 전 준비 단계에서 [닫기]만 보여 주며 아무것도 남기지 않습니다. 로그인 확인보다 먼저 판단합니다.
  - 로그인 필요는 보관을 마친 뒤 확인합니다. 저장 계정이 없거나 만료됐으면 시트를 내리고 알림창을 띄우며,
    저장 응답 401은 시트 위에 띄웁니다. [닫기]를 누르면 저장 대기 공유로 남습니다.
  - 네트워크 오류·응답 유실·30초 제한·5xx·이미지 저장 일시 중단·400/415/422 등 4xx는 [다시 시도]와 [닫기]를 보여 줍니다.
    [다시 시도]는 같은 `Idempotency-Key`로 다시 보내 중복 저장이 없고, [닫기]는 저장 대기 공유로 남깁니다.
  - 서버 이미지 보관 한도, 저장 계정 변경(전송 뒤 변경 포함)·다른 서버 환경은 [닫기]만 보여 주고 저장 대기 공유로 남깁니다.
    계정·환경이 바뀐 공유는 다시 보내지 않고 원래 계정·환경의 본앱 복구 화면에서 이어 저장합니다.
  - 서버 410(삭제한 콘텐츠)·409(저장 정보 불일치)·413(크기 초과)은 [닫기]를 누르면 남기지 않고 버립니다.

- Android 공유 메뉴(`ShareActivity`)는 보던 화면을 어둡게 하고 그 위에 공유 저장 시트(손잡이·**저장하기**·
  "전송한 정보는 AI가 직접 분류해서 저장할게요!")만 띄웁니다. 링크·이미지 모두 같은 시트이며 미리보기·저장 계정은
  표시하지 않습니다. 공유 내용을 기기에 보관하는 동안과 저장 중에는 모양을 바꾸지 않고 **저장하기**만 막습니다.
  저장하면 시트가 내려가고 `✓ 저장 완료!` 토스트를 약 1.5초 보여 준 뒤 송신 앱으로 돌아갑니다.
  손잡이 끌어내림·배경 탭·뒤로가기로 닫으면 저장 전에는 저장 대기 공유를 남기지 않고, 저장 중에는 결과 미확인으로
  보관하며, 보관이 끝나기 전에는 받기를 취소합니다. 본앱의 대기 항목 재개(`ShareRecoveryActivity`)는 기존 전체 화면과 문구를 유지합니다.
- Android 공유 저장 시트의 비정상 상태는 OS 알림창에 분류별 짧은 제목·문구를 보여 줍니다. 문구표는
  [공유 저장 시트 기록](../history/2026-10-31-share-save-sheet.md#126-android-실패-분류)에 있습니다.
  공유 내용을 기기에 보관한 뒤 로그인을 확인하며, 준비 단계 실패가 로그인 필요보다 우선합니다.
  - 받기 거절(지원하지 않는 입력)·기기 보관 실패: 보관된 것이 없습니다. 기기 보관 한도(10개·100MiB) 초과는 [허투루 열기]를 함께 둡니다.
  - 로그인 필요(자격 없음·만료, 저장 응답 401): 준비 단계에서는 시트를 내리고 알림창을 띄웁니다. 저장 대기 공유로 보관하며
    [허투루 열기]는 본앱을 실행하고 공유 창을 닫습니다.
  - 다시 시도 가능(네트워크·응답 유실·30초 제한·결과 미확인·5xx·이미지 저장 중단·400/415/422와 그 밖의 4xx): [다시 시도]는
    같은 `Idempotency-Key`로 다시 확인해 중복 저장이 없고, [닫기]는 보관합니다. 저장 중 계정이 바뀐 채 실패하면 재시도 대신 아래 분류로 안내합니다.
  - 서버 이미지 보관 한도, 저장 계정 변경·다른 서버 환경: [닫기]만 두고 보관합니다. 계정·환경이 다른 항목은 원래 계정·환경의 본앱에서 이어 저장합니다.
  - 되돌릴 수 없음(410·409·413): [닫기]하면 저장 대기 공유를 남기지 않습니다.
  - 뒤로가기·알림창 바깥 탭·Activity 재생성 뒤 닫기는 [닫기]와 결과가 같습니다.

- 지원: Instagram·YouTube 링크 하나 또는 PNG·JPEG·WebP 한 장(기본 10MiB).
- 원본 이미지의 서버 보관 한도는 계정별 게스트 30MiB·로그인 300MiB이며 본앱과 양쪽 공유 저장을 합산합니다.
  계정 한도 초과와 한 장의 10MiB 초과는 기존 본앱 오류 토스트·네이티브 공유 상태 영역(iOS·Android 공유 메뉴 경로는 OS 알림창)에서 서로 다른 문구로 안내합니다.
  한도 오류는 세션을 지우거나 새 계정을 만들지 않으며 기존 이미지 조회·삭제와 완료된 공유 재전송은 유지합니다.
  여러 장·동영상·HEIC 변환·공유 화면 안의 로그인·분류 편집은 지원하지 않습니다.
- 본앱의 기존 로그인/게스트 선택·세션 복원 후 저장 전용 자격을 준비합니다. 처음 업데이트한 뒤
  본앱을 한 번 열어야 합니다. 자격이 없거나 만료되면 초안을 보관하고 본앱에서 확인하도록 안내하며,
  본앱을 강제로 열거나 새 게스트를 자동 생성하지 않습니다. Android 알림창은 사용자가 고를 때만 [허투루 열기]로 본앱을 엽니다.
- 기기 공유 자격을 읽지 못한 경우 재시도는 공유 자격 차단·재발급을 먼저 시도합니다.
  본앱 로그인이나 보관한 초안을 초기화하지 않습니다.
- 본앱의 대기 항목 안내에서 초안을 선택하면 기존 네이티브 작성기로 재개합니다(공유 저장 시트가 아닌 복구용 화면). 안내의 `나중에`는
  현재 화면만 가리고 있던 안내를 닫습니다. 다음 앱 복귀 때 대기 항목을 다시 확인합니다.
- 초안은 최대 10개·총 100MiB·7일입니다. 한도 초과 시 기존 항목을 임의로 지우지 않습니다.
  이미 전송한 초안은 최초 저장 계정으로만 재시도합니다.
- 요청은 30초 제한이며 응답 유실·전송 후 닫기는 결과 불명으로 보관합니다. 같은 초안의 UUID를
  `Idempotency-Key`로 재사용하므로 새 저장을 반복하지 않습니다. 서버 생성 응답을 받으면 완료이며
  YouTube 요약 완료나 자동 백그라운드 저장을 기다리지 않습니다.

`lib/data/services/native_share_service.dart`의 `com.huturu.app/share` 채널은 자격 준비·차단,
대기 초안·성공 영수증 조회, 네이티브 UI 재개만 연결합니다. 영속 원본은 각 플랫폼 저장소이며
Dart Repository는 같은 데이터를 별도로 저장하지 않습니다. `app/actions/share_coordinator.dart`는
세션 저장 콜백 밖에서 자격을 발급하고, 계정 변경 전에 영속 revision을 올려 이전 자격을 차단합니다.
성공 영수증은 같은 계정·API 환경의 카테고리·활성 목록·통계 갱신 후 소비합니다. 목록은 이미 읽어 둔 범위를
한 번에 갱신해 현재 화면·필터·스크롤을 보존하며, 실패 시 기존 항목·커서로 이어서 조회합니다.
후속 조회 실패는 저장 재전송 사유가 아닙니다.

자격은 `POST /auth/share-credential`에서 발급하며 본앱 access/refresh 토큰과 분리합니다.
네이티브 코드는 공유 토큰으로 `/contents/share`, `/uploads/screenshots`만 호출합니다.
백엔드 migration·권한·중복 방지 계약은 [백엔드 API 계약 안내](../backend/api-contracts.md)를 따릅니다.
백엔드와 migration을 먼저 배포한 후 앱을 배포해야 합니다.

공유 플랫폼 capabilities·API 주소 설정과 로컬 검증은 [공유 개발·검증 안내](development.md#플랫폼-설정)를 따릅니다.

## 추천 프론트 연결 계약

다음은 추천 정책 문서에서 이관한 클라이언트 계약입니다. API 필드·상태·중복 방지 조건은 [추천 HTTP 계약](../backend/api-contracts.md#추천-api-연결-계약)을 따릅니다.

현재 프론트 연결 계약:

- Today 버튼은 서버 추천을 조회해 최대 5개 상세를 순서대로 탐색한다. 버튼·조회·상세 진입을 카드 노출로 기록하지 않는다.
- Weekly는 홈 방문별 최대 2개 서버 카드를 표시하며 선택한 카테고리로 이동한다. 실제 화면에 보이는 카드만 방문·항목별 UUID로 노출을 기록한다.
- 추천 상세 진입은 새 UUID와 추천 항목 ID를 사용하고 재전송에는 같은 UUID를 유지한다. 일반 상세와 추천 유입의 구분을 보존한다.
- 홈 방문·OS 백그라운드 복귀·모달·필터의 경계와 실패·빈 결과 처리는 각 프론트 작업 기록에서 확인한다.
- `frontend/lib/app/clipback_app.dart`가 이동을 조정하고 상세 ViewModel·콘텐츠 Repository가 조회·유입을 처리한다. `frontend/lib/main.dart`는 앱 시작 진입점이다.

추천 API만 구현한 상태와 실제 프론트 노출·상세 진입까지 검증한 상태를 구분해 기록한다.
