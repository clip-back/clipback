# 홈 칩 전환 때 최근 콘텐츠 영역 높이 고정

최초 기록일: 2026-11-03 KST. 이슈 [#216](https://github.com/clip-back/clipback/issues/216)(팀 피드백 시트 39번), 시작 커밋 `2477a99`,
작업 브랜치 `fix/home-chip-switch-height`.

## 문제와 결정

- 홈 "최근 저장한 콘텐츠"에서 칩을 바꾸면 응답이 올 때까지 카드 목록 대신 작은 스피너만 보여 영역이 줄었다가 다시 늘어났다.
  칩 결과가 빈 카테고리는 높이 218px의 다른 빈 화면("<카테고리 이름> 콘텐츠가 없어요"와 "전체보기" 버튼)이 나왔다.
- 2026-11-03 사용자 결정(이슈 본문 '결정' 절): 로딩 중 스피너 영역을 카드 목록 영역(점 표시 포함) 높이로 고정한다.
  기준 높이는 글자 배율에 따라 계산한 카드 목록 영역 높이(1.0배 224px)다. 빈 카테고리는 Figma C02 빈 상태(`111:3711`)에서
  제목만 카테고리 문구로 바꾸고 설명은 C02 그대로, "전체보기" 버튼은 없다. 같은 칩을 다시 누르면 지금처럼 다시 불러온다.
- 사용자 결정 2026-11-03: 제목 2줄 제한·말줄임, 2줄일 때 그림 위 여백 축소.
  리뷰에서 카테고리 이름(최대 40자)이 길면 빈 화면이 고정 높이를 넘친다는 지적이 있어 정했다. 제목은 최대 2줄로 자르고,
  고정 높이 안에 들어가지 않을 때만 그림 위 16px 여백을 넘친 만큼 줄인다. 제목이 1줄이면 C02 여백 16px 그대로다.
- 로딩 중 카드가 사라지는 것 자체, 칩별 결과 캐시, 저장·수정 뒤 다시 불러오기 경로는 이슈의 범위 밖이다.

## 변경 내용

- `frontend/lib/features/home/home_screen.dart`

  - 피드가 로딩 중이면 스피너를 이 높이의 영역 가운데에 둔다. 오류 화면은 그대로다.
  - `HomeFilteredEmptyContent`: 같은 높이 안에 C02 빈 상태 블록을 위쪽 정렬로 그린다. 블록은 `EmptyHomeContent`의 C02 블록을 꺼낸
    `_SavedEmptyMessage`로 함께 쓴다. 제목은 최대 2줄·말줄임이고, 고정 높이일 때 그림 위 여백을 `Flexible`로 두어 모자란 만큼만 줄인다.
- [Figma 화면 맞춤 계획](../figma-ui-alignment-plan.md)의 `figma-current-07`·`figma-pending-07`을 이번 결정에 맞게 고쳤다.

## 시뮬레이터·에뮬레이터 실행 (2026-11-03)

- 환경: iPhone 16 / iOS 18.6 Simulator, Android Emulator `Medium_Phone` / Android 16 / 1080×2400. 한 번에 하나만 띄웠다. 서버·로그인은 쓰지 않았다.
- 실제 루트 앱을 홈 메모리 API(콘텐츠 4개)로 띄우는 임시 진입 파일(커밋하지 않음)로 변경 전(`2477a99`의 `home_screen.dart`)·변경 후를 debug 빌드했다.
  메모리 API에 콘텐츠 없는 40자 이름 카테고리를 더하고, "여행" 피드 응답은 보내지 않고 잡아 두어 로딩 상태를 만들었다.
  칩은 Orca 에뮬레이터 탭으로 눌렀고, 1.3배는 앱 안에서 `MediaQuery` 글자 배율을 바꿨다(OS 설정 아님). 스크롤은 모두 0이다.

  - 변경 후 빈 결과: 미분류는 제목 1줄·그림 위 여백 16, 40자 이름은 1.0배에서 2줄(잘리지 않음)·여백 16, 1.3배에서 2줄 말줄임·여백 11.
- 상단 문구(기존 동작, 이번 범위 밖): 칩 전환 중 로딩과 빈 카테고리에서는 목록이 비어 홈 맨 위 문구가 "나중에 보려던 것들,"에서
  "저장한 정보가 없어요."로 바뀌고, 그 영역이 32 높아져 칩과 패널이 32 아래로 내려간다(1.0배, iOS 칩 위 331→363, Android 296→328).
  응답이 와서 카드가 다시 보이면 원래대로 돌아간다. 변경 전·후 같다. 그래서 패널 높이는 고정됐지만 칩 전환 중 홈 아래 내용의 위치는 이 차이만큼 움직인다.
  후속 작업은 [#217](https://github.com/clip-back/clipback/issues/217)에서 다룬다.
- 화면 크기와 안전 영역: 원본 화면은 iOS 393×852pt, Android 411.4×914.3dp(1080×2400, 2.625배)이고 Figma C01·C02 프레임은 375×910이다.
  Figma 프레임은 상태 표시줄과 홈 표시를 그림으로 포함한다. 앱은 실제 OS 안전 영역을 쓴다. 홈 위쪽은 `SafeArea(bottom: false)`로 상태 표시줄
  (iOS는 Dynamic Island 영역) 아래에서 시작하고, 아래쪽 안전 영역(iOS 홈 표시, Android 제스처 막대)은 하단 탭이 높이에 더한다.
  그래서 폭(18–36 차이)과 세로 위치·하단 탭 위치가 Figma와 다르다. 이 차이는 이번 패널 변경과 무관하며 이미지를 보정하지 않았다.
  측정 JSON의 `viewPadding`이 0인 것은 `SafeArea` 아래 스크롤 위젯에서 읽은 값이라서이며, 실제 OS 안전 영역 값이 아니다(OS 값은 따로 재지 않았다).
- 영상(2026-11-03): 칩 전환의 연속 동작을 변경 전·후로 녹화했다. 같은 임시 진입 파일 방식에서 카테고리 피드 응답을 잡아 두지 않고 2초 늦게 보내도록 바꿔

## 미검증 범위

- 실기기, 실제 서버 응답 속도에서의 화면은 확인하지 않았다.
- OS 글자 크기 설정으로 바꾼 1.3배는 확인하지 않았다(앱 안 배율만 바꿈).
- 저장·수정 뒤 다시 불러오기(`beginRefresh`) 경로의 로딩 높이는 코드로만 같은 분기임을 확인했다.
