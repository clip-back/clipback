## Android Gradle 배포판 체크섬 (#428)

팀 피드백 시트 129(보안). Gradle 래퍼가 내려받은 배포판 zip을 공식 파일과 대조하지 않았다.
release 빌드는 같은 Gradle 프로세스에서 업로드 키 설정 파일을 읽으므로, 바꿔치기된 배포판이 실행되면 업로드 키가 샐 수 있다(위험 낮음).

### 변경 범위

- `frontend/android/gradle/wrapper/gradle-wrapper.properties`: `distributionUrl` 다음 줄에
  `distributionSha256Sum=b84e04fa845fecba48551f425957641074fcc00a88a84d2aae5808743b35fc85` 한 줄을 더했다(`9468e2e`).
  값은 [Gradle 공식 체크섬 페이지](https://gradle.org/release-checksums/)의 "9.1.0 complete ZIP checksum"이다(2026-11-20 조회).
- 래퍼는 설치할 ZIP을 풀기 전에 체크섬을 검증하며, 설치 완료된 배포판은 재사용한다.
  Gradle 버전을 올릴 때는 `distributionUrl`과 함께 이 값도 바꾼다.
- 래퍼 jar·의존성 검증, 체크섬 누락을 막는 release 준비 검사는 넣지 않았다(이슈 Out of Scope).
- 사용자에게 보이는 변화가 없어 CHANGELOG에 넣지 않았다.

### 검증

모두 이 Mac(macOS 26.6.2, arm64)의 로컬 실행이다. 원격 CI·실기기 검증은 이 절에 없다.

- 맞는 값: 빈 임시 `GRADLE_USER_HOME`에서 `./gradlew --version`이 배포판을 새로 받아 Gradle 9.1.0을 실행했다(종료 0).
- 틀린 값: 체크섬 첫 글자를 `b`에서 `c`로 바꾼 사본과 다른 빈 임시 홈으로 같은 명령을 돌리자 종료 1로 멈췄다. 출력:
  `Verification of Gradle distribution failed!`, `Expected checksum: 'c84e04fa…5fc85'`, `Actual checksum: 'b84e04fa…5fc85'`.
  확인 뒤 파일을 되돌렸고 임시 홈은 지웠다.
- Android debug 빌드(`flutter build apk --debug --no-pub`)와 release 빌드
  ([Android Release 서명과 AAB](../frontend/development.md#android-release-서명과-aab) 절의 서명·dart-define 환경변수,
  `flutter build appbundle --release --no-pub`, 버전은 pubspec 값)가 각각 성공했다. release 빌드는 `validateReleaseSigning`을 거친다.
  산출물은 올리지 않고 지웠다.
- 빌드 뒤 추적 파일 변경은 위 한 줄뿐이었다(Flutter가 래퍼 설정을 고쳐 쓰지 않음).
- 로컬 전체 검사(`9468e2e`): `VERIFY result=PASS scope=all checks=12 failed=0`. 서버 pytest `2751 passed, 49 skipped`,
  앱 테스트 `+3943: All tests passed!`. skip 사유는 verify 출력 원문이다.

  ```text
  pytest skip: 48 tests/deployment (RUN_DOCKER_RECOVERY_TESTS=1 and a labelled local image are … 외 6종)
  pytest skip: 1 tests/integration (CLIPBACK_IMAGE_TEST_S3_ENDPOINT is required for the local s…)
  ```

## 쓰이지 않는 옛 알림 시트 정리 (#429)

옛 알림 시트(`NotificationSheet`, 고정 예시 알림 3개)는 앱 어디에서도 열리지 않고 테스트·촬영 스크립트만 참조했다.
`favorite_wording_test.dart` 주석의 정렬 메뉴 폭도 지금 값(149, #423)과 달랐다.

### 변경 범위

- `frontend/lib/shared/widgets/notification_sheet.dart`를 지웠다(`8083852`).
- 알림 시험대 `frontend/test/fixtures/notification_alignment_fixture.dart`: 옛 시트 분기와 예시 값(`notificationExamples`·`legacyRows`·`legacySheet`)을 지우고
  실제 알림 화면(`NotificationListScreen`) 측정만 남겼다. 측정 키·경계와 `presentation: fullScreen`은 그대로다.
  판정은 활성 결과의 `presentation`이 `fullScreen`이 아니면 실패로 남긴다(`25d97e1`).
- 촬영 스크립트 `home_base_alignment_preview.dart`·`notification_alignment_preview.dart`: 옛 시트 경로 판정(`notificationSheet`)을 지웠다.
  실제 알림 화면이 없을 때 OS 뒤로가기로 대신하거나 설정·세션 무효화 검사를 건너뛰던 옛 대체 경로도 지워,
  헤더 탭을 요청하면 헤더를 탭하고 실제 화면이 없으면 실패한다(`25d97e1`).
- `notification_list_figma_test.dart`: 옛 시트 import와 "옛 시트가 없다" 단언 1줄만 지웠다.
- `favorite_wording_test.dart:9` 주석 숫자를 149로, [Figma 화면 맞춤 계획](../figma-ui-alignment-plan.md) bottom-sheet 테마 줄에서 "알림·"을 뺐다.
- 앱 화면·동작 변화가 없어 촬영하지 않았고 CHANGELOG에 넣지 않았다. 옛 기준 커밋 `220f313`의 시트를 측정하는 경로는 지원하지 않는다.

### 검증

모두 이 Mac(macOS 26.6.2, arm64)의 로컬 실행이다. 원격 CI·시뮬레이터·실기기 검증은 이 절에 없다.

- 지운 뒤 `git grep -nE "NotificationSheet|NotificationRow|mockNotifications|notification_sheet|legacySheet|notificationSheet" -- frontend` 결과가 비었다.
- `flutter analyze` 문제 없음. 촬영 스크립트는 정적 분석(`flutter analyze`)만 수행했다.
- 관련 테스트: 알림·홈 시험대를 쓰는 테스트(`notification_list_figma`·`notification_list_content`·`notification_navigation`·`favorite_wording`·
  `home_base_alignment`·`home_panel_background`·`permission_guide_navigation`·`permission_guide_content`·`permission_guide_figma`·`phone_width`,
  검수 뒤 `sort_popup_platform_scale`·`theme_font_root`·`theme_font_overflow` 추가)가 통과했다.
- 판정 변형: 시험대 출력에서 `presentation` 줄을 잠시 빼자 알림 테스트 2개 파일이 `presentation: null != fullScreen`으로 실패했다(종료 1). 확인 뒤 되돌렸다.
- 로컬 전체 검사(`25d97e1`): `VERIFY result=PASS scope=all checks=12 failed=0`. 서버 pytest `2751 passed, 49 skipped`,
  앱 테스트 `+3943: All tests passed!`. skip은 #428 절에 옮긴 `pytest skip:` 두 줄과 같다.
- 최종 리뷰 전체 검사(`e0a2824`, 리뷰어 실행): `VERIFY result=PASS scope=all checks=12 failed=0`. 서버 pytest 2751 passed·49 skipped, 앱 테스트 3943개 통과, skip 줄은 위와 같다.
