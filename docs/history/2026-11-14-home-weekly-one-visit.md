## 문제

- 홈은 상단과 '최근 저장한 콘텐츠'를 먼저 그리고 첫 프레임 뒤에 주간 추천을 요청했다. 응답이 오면 픽 영역(글자 1배 약 204pt)이 끼어들어 아래가 밀렸다.
- 주간 추천 방문이 다른 탭·알림·상세에 다녀올 때마다 새로 시작되어(새 요청·새 묶음) 홈 복귀마다 같은 밀림이 되풀이되고 카드가 바뀌었다.

## 구현

- `HomeWeeklyViewModel`: 방문은 계정 세대가 바뀔 때만 끝난다(`sync`). 홈을 떠나도 카드·노출 기록·미룬 실패 안내를 유지하고, 노출·카드 선택·실패 안내·안내의 다시 시도는 홈이 보일 때만 받는다. 새 로그인 뒤 홈은 지금처럼 첫 프레임 뒤 요청한다.
- `HomeWeeklyViewModel.prepare`: 앱 시작에서 방문을 시작하고 요청한다. 자체 `ApiRequestScope`(15초, 방문 소유 확인) 안에서 기다려 시간 초과 요청과 그 인증 갱신을 끝내고, 시간 초과 뒤에는 방문 토큰을 바꿔 늦은 응답을 버리고 실패 안내를 홈이 보일 때까지 미룬다. 이미 받았거나 실패한 방문은 다시 요청하지 않는다.
- `AppViewModel.restoreSession`(저장된 세션 복원)만 홈 최초 불러오기와 함께 `prepare`를 시작하고, 계정·목록 불러오기 뒤 그 완료(성공·실패·시간 초과)를 기다린 다음 시작 로딩을 닫는다. 소셜·게스트 로그인 뒤(`_reloadAfterAuthentication`)는 바꾸지 않았다.
- 앱 View(`_syncWeeklyHome`)는 홈이 보이면 미룬 실패 안내 표시를 예약한다. 저장소 API·서버·DB는 바꾸지 않았다.
- 첫 구현은 시작 요청을 범위 밖에서 기다려 `share_lifecycle_test` '확인된 최종401은 native 차단 지연 중에도15초에 로컬 세션을 폐기한다'가 실패했다(만료 세션 갱신이 15초 뒤 교체 토큰을 지움). 시작 요청을 위 scope 안으로 옮겨 해결했다.
