# Android 내부 테스트 배포 명세 발행

최초 기록일: 2026-10-28 KST. 기준 소스는
`1bbc423`까지의 `docs/android-release-preparation` 브랜치이며,
[설계 인터뷰](2026-10-28-android-release-design.md)의 7개 합의를 명세로 정리했다.

## 결과

- 공식 명세: [GitHub #112](https://github.com/clip-back/clipback/issues/112)
- 로컬 사본: [Android 내부 테스트 배포 명세](../android-internal-test-release-spec.md)
- 제목: `feat: Android 0.2.0(1) 내부 테스트 배포 준비 및 실기기 검증`
- 상태·라벨: `OPEN`, `ready-for-agent`
- `to-spec` 템플릿의 7개 절, 사용자 스토리 30개, 구현·테스트 결정, 완료 조건과 제외 범위를 작성했다.
- 검증 경계는 설계 인터뷰에서 사용자가 동의한 Play 설치본의 Android 실기기 사용자 흐름을 유지했다.
  기존 배포 후보 CLI와 Flutter·네이티브 공유 테스트를 보조 검증으로 재사용하도록 정리했다.
- 회원 탈퇴·운영 정책·비공개 테스트·정식 출시는 후속 범위로 구분했다.
  실제 키 생성·콘솔 변경·업로드는 이번 명세 발행에 포함되지 않는다.

## 확인한 사항

- Android·안드로이드·내부 테스트 제목으로 기존 이슈를 조회해 중복 명세가 없는지 확인했다.
- `ready-for-agent` 라벨이 저장소에 존재하는 것을 확인하고 적용했다.
- 게시 후 GitHub 본문을 다시 읽어 로컬 명세와 대조했다. CRLF·끝 공백 정규화 후 본문이 같았으며
  정규화 본문의 SHA-256은 `af8f93d9457d27575452f81c58382705181802043a6917bf26b6bb5575011627`이다.
- 원격 이슈의 `OPEN` 상태와 라벨을 재확인했다.
- 구현 결정에 구체적인 파일 경로·코드 조각을 넣지 않았으며, 운영 비밀값·개인 계정 정보도 포함하지 않았다.
- 문서 링크와 `git diff --check`를 확인했다. 문서 작성·게시 작업이므로 앱 테스트·빌드·실기기 실행은
  수행하지 않았으며 과거 통과 결과를 이번 검증으로 사용하지 않았다.

이 기록은 명세가 게시되었다는 증거이며 Android 내부 테스트 배포나 실기기 검증의 완료 기록은 아니다.
