# Android 배포 준비 설계 인터뷰

최초 기록일: 2026-10-28 KST. `ce61aade7ad16cdee2a4ae9f84ef4630770266ab` 기준 코드와
이미 로그인된 Google Play Console의 허투루 화면을 읽어 확인했다.
`grill-with-docs`의 `grilling`·`domain-modeling` 절차를 사용해 7개 결정을 확인한 설계 기록이며,
구현·키 생성·콘솔 설정 저장·업로드 완료를 뜻하지 않는다.

## 확정한 결정

1. **첫 목표는 Google Play 내부 테스트**다. 로그인·공유·저장을 확인한 뒤 비공개 테스트와 정식 출시로 진행한다.
   내부 테스트 제공과 정식 공개는 구분하며 내부 테스트 기간을 비공개 테스트 14일로 계산하지 않는다.
2. **Google이 생성한 앱 서명 키로 Play App Signing을 사용하고 업로드 키를 분리**한다.
   업로드 키·비밀번호는 Git·채팅에 남기지 않고 안전하게 백업한다.
   Google이 생성한 앱 서명 비밀키를 내려받을 수 없으므로, 향후 다른 스토어에 같은 서명으로 배포할 필요가
   생기면 첫 키 설정 전에 이 결정을 재검토한다. 공급자 OAuth에는 실제 설치본의 앱 서명 인증서를 등록한다.

3. **첫 후보는 Android `0.2.0`, 빌드 `1`**로 준비한다. iOS와 사용자 버전만 맞추고 Android 빌드 번호는
   독립적으로 관리한다. 실제 예약 직전 Play 업로드 이력을 다시 확인한다.
4. **운영 서버에 별도 테스트 계정·콘텐츠를 사용**한다. 별도 테스트 서버를 추가하지 않으며 테스트에서
   운영 데이터가 실제 생성되는 것을 전제로 로그인·저장·공유 경로를 확인한다.
5. **업로드 키는 저장소 밖에 두고 암호관리자에 백업**한다. 키 파일 첨부가 가능한 암호관리자에
   키 파일·비밀번호를 보관하며 백업 복구를 확인한다. 사용할 제품·보관 위치는 구현 전에 지정한다.
6. **완료 기준은 Play 설치본의 Android 실기기 핵심 기능 검증**이다. Google·카카오 로그인,
   로그아웃·재로그인, 링크·사진 저장, Android 공유 메뉴에서 저장, 재시작 후 데이터 확인을 포함한다.
   업로드 성공이나 대역 테스트 통과만으로 완료 처리하지 않는다.
7. **첫 내부 테스터는 본인 계정 1명**이다. 설치·로그인 확인 후 팀·지인에게 넓히며,
   비공개 테스트의 12명·14일 참여는 별도 단계로 진행한다.

이는 세 차례 질문에 대한 사용자 확인이며 실제 구현·업로드 실행 요청은 아직 아니다.
일반적인 테스트 트랙·키 용어를 서비스 도메인 용어집에 추가하지 않으며, 통상적인 배포 운영 선택을
별도 ADR로 만들지 않는다.

## 구현 전에 필요한 운영 입력

- 키 파일을 보관할 암호관리자·보관 위치와 백업 복구 확인 방법. 비밀번호는 채팅에 받지 않는다.
- 내부 테스터의 Google 계정, 실제 확인에 사용할 Android 기기와 피드백 연락처.
- 현재 디스크 공간 문제의 해결 범위. 개인 파일 정리·이동·삭제는 별도 승인 없이 수행하지 않는다.
- 계획 확인은 키 생성·설정 변경·업로드·테스터 초대 실행을 의미하지 않는다. 구현·업로드는 별도 요청을 따른다.

## 준비 순서

1. 테스트 목표·후보 버전·서버·키 보관 방법과 성공 기준을 확정한다.
2. 빌드·에뮬레이터 검증에 필요한 디스크 여유를 확보하고, 관련 변경을 배포 기준 소스에 반영한다.
3. 업로드 키와 Release 서명을 준비하고 암호관리자 백업·복구를 확인한다.
4. 확정한 소스·버전·빌드 번호·스토어 이력으로 배포 후보를 기록하고 Release AAB를 생성한다.
   서명·패키지·버전·운영 API·실제 권한·target SDK·네이티브 라이브러리의 16KB 호환을 확인한다.
5. 첫 업로드 과정에서 Google 생성 키로 Play App Signing을 설정하고 앱 서명 인증서를 확인한다.
   `com.huturu.app`과 실제 설치본 서명 기준으로 Google·카카오를 등록한다.
   업로드 키의 인증서와 Play가 배포하는 앱 서명 인증서를 혼동하지 않는다.
6. 내부 테스트 트랙의 AAB·본인 테스터·피드백 경로를 확인하고, 참여 링크를 통해 Play 설치본을 검증한다.
   업로드, 처리 완료, 테스터 제공, 갤럭시 설치·실행, 실제 OAuth·저장은 각각 별도 증거로 남긴다.
7. 비공개 테스트 전 스토어 설명·이미지·지원 연락처·대상 연령·콘텐츠 등급·광고 여부·앱 액세스·
   데이터 보안 정보를 준비한다. 개인정보처리방침과 계정 삭제의 앱 내 경로·웹 요청 경로도 준비한다.
8. 비공개 테스터 12명 이상이 14일 연속 참여하는 테스트를 실제 수행하고 피드백·개선을 기록한 뒤
   프로덕션 액세스를 신청한다. 조건 충족이 자동 승인이나 정식 출시를 뜻하지 않는다.

내부 테스트만 활성화된 앱은 데이터 보안 양식의 예외가 있지만, 이것을 개인정보 처리나 계정 삭제를
검토하지 않아도 된다는 뜻으로 해석하지 않는다. 테스트 참여자의 계정·데이터 처리 범위와 이후 출시
준비를 구분한다. 내부 테스트 참여자는 비공개 테스트로 전환할 때 내부 테스트에서 탈퇴한 뒤 참여한다.

## 문서 확인

설계 기록의 로컬 링크 4개와 `git diff --check`를 확인했다. 이 작업은 문서만 작성했으며 앱 테스트·
빌드·실기기 실행을 수행하지 않았다. 직전 구현의 테스트 수치를 이번 실행 결과로 재사용하지 않았다.
