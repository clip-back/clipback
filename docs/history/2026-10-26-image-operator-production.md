위 재개 기록과 재개 후 검증으로 최종 서비스 정상화를 확인했다.

## 일일 백업 설정과 예약 외 실행

- 서비스: `clipback-backup`, Cron `0 0 * * *` (매일 09:00 KST), Restart Policy `Never`.
- 첫 적용에서 여러 줄 Python 명령이 공백으로 합쳐져 문법 오류가 확인됐다. 당시 Cron 실행 이력과
  일일 완료 지점은 없었다. 한 줄 명령으로 수정하고 문법을 확인한 뒤 사용자의 승인으로 실행했다.
- 시작 명령은 `scripts.image_backup_jobs daily`; 실제 한 줄 명령은 현재 체크리스트에 유지한다.
- 실행 방식: `railway cron run --service clipback-backup --environment production --yes --json`.

기록 시점의 다음 예약은 2026-10-27 09:00 KST다. 이 일일 백업으로 새 격리 복원을 실행하지 않았다.

## 남은 작업과 보류

- 예약 시각 자동 기동·정상 종료·완료 지점 확인.
- 사용자의 요청으로 `maintain` 정기 서비스 설정을 보류했다. 7일 보존·삭제 사본 정리는 자동 실행되지 않는다.
- 실패·기한 초과 감시와 알림 연결, 원본 물리 삭제 재처리 정기 가동, 기존 Volume 이미지 이관은 후속 작업이다.
- 운영 원본·Bucket 복구 지점은 Mac 실행 정리 과정에서 삭제하지 않았다.
- GitHub #97·#102의 완료 여부는 이번 문서 변경으로 처리하지 않았다.

근거는 실제 복원 제어기 보고서, 재개 후 운영 조회, Railway Cron 실행 이력·로그와 백업 객체
해시 검사 결과다. 임시 JSON 파일이나 개인 Mac 경로가 없어져도 결과를 읽을 수 있도록 필요한
비밀값 없는 항목만 본문으로 보존했다. 키·토큰·원본 파일명·사용자 본문은 포함하지 않았다.
