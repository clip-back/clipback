# 화면 문구의 "북마크"를 "즐겨찾기"로 통일

최초 기록일: 2026-11-03 KST. 이슈 [#198](https://github.com/clip-back/clipback/issues/198), 시작 커밋 `c75d806`,
작업 브랜치 `fix/bookmark-to-favorite-wording`. 코드 이름(`bookmark`, `bookmarkedFirst` 등)·API·DB와 과거 이력 문서는 범위 밖이라 바꾸지 않았다.

## 문제와 결정

- 하단 탭과 즐겨찾기 화면은 "즐겨찾기"인데, 아카이브 정렬의 "북마크 우선"과 즐겨찾기 빈 화면의 "북마크한 콘텐츠가 없어요",
  "중요한 정보는 북마크를 통해 저장하세요!"에 "북마크"가 남아 있었다(0.3.0 팀 테스트 제보).
- 2026-11-03 사용자 결정: 화면에 보이는 "북마크" 문구를 모두 "즐겨찾기"로 바꾼다. Figma I02 `111:4103`은 아직 "북마크" 문구라서,
  변경 후 빈 화면은 이 결정에 따라 Figma와 문구만 다르다.
- 티켓 리뷰에서 정렬 메뉴(폭 128px 고정)에 "즐겨찾기 우선"이 선택돼 체크가 보이면 글자 1.1배부터 넘친다는 지적이 나왔다(기존 "북마크 우선"은 1.3배부터).
  2026-11-03 사용자 결정: 이번 작업에서 메뉴 폭을 넓힌다. 기준은 "즐겨찾기 우선"이 선택돼 체크가 보일 때 글자 1.3배까지 넘치지 않는 가장 작은 폭이며,
  메뉴 안 패딩·체크 크기·글자 크기는 바꾸지 않는다. Figma에는 닫힌 정렬 버튼 `111:4123`만 있고 열린 메뉴 원본은 없다
  ([figma-current-36](../figma-ui-alignment-plan.md#figma-current-36)).

## 변경 내용

- `frontend/lib/features/archive/archive_widgets.dart`: 정렬 버튼 이름, 정렬 상태를 글자로 비교하는 곳, 정렬 메뉴 항목, 정렬 선택 시트 항목의
  "북마크 우선"을 "즐겨찾기 우선"으로 바꿨다. 정렬 메뉴 폭을 128에서 145로 넓혔다.
  폭은 실제 위젯의 폭만 바꿔 Pretendard 글꼴·글자 1.3배·"즐겨찾기 우선" 선택 상태로 잰 값이다. 144는 0.246px 넘치고 145부터 넘치지 않았다.
- `frontend/lib/features/archive/bookmark_widgets.dart`: 즐겨찾기 빈 화면의 제목·안내 문구를 바꿨다.
- `frontend/test/favorite_wording_test.dart`(새 파일): 정렬 버튼·메뉴·정렬 시트·빈 화면에 "즐겨찾기" 문구만 보이는지,
  "즐겨찾기 우선"을 고르면 즐겨찾기 우선 정렬이 되고 "최신순"으로 돌아오는지, 글자 1.0·1.1·1.2·1.3배와 두 선택 상태에서 메뉴가 넘치지 않는지 본다.
  앱과 같은 Pretendard 글꼴을 쓴다.
- 기존 테스트·대역의 기대 문구와 현재 안내 문서(`docs/frontend/behavior.md`, `docs/frontend/development.md`, Figma 화면 맞춤 계획)의 정렬 이름 인용을 맞췄다.
  `frontend/test/support/bookmark_preview.dart`의 빈 화면 문구 검사 메시지는 기대값이 I02 원본이 아닌 #198 승인 문구임을 알 수 있게 바꿨다.
- 정렬 선택 시트(`SortSheet`)는 앱 어디에서도 열리지 않는다. 문구는 바꿨지만 화면으로는 확인할 수 없다.

## 시뮬레이터·에뮬레이터 실행 (2026-11-03)

- 환경: iPhone 16 / iOS 18.6 Simulator, Android Emulator `Medium_Phone` / Android 16 / 1080×2400 / 420dpi. 한 번에 하나만 띄웠다. 서버·로그인은 쓰지 않았다.
- 화면: [홈 기본 프리뷰](../../frontend/test/support/home_base_alignment_preview.dart)의 메모리 API(콘텐츠 4개)로 실제 루트 앱을 띄우는
  임시 진입 파일(커밋하지 않음)로 debug 빌드했다. 진입 파일이 하단 탭과 정렬 버튼에 앱 안 포인터 이벤트를 넣어 상태를 만들었다.
  정렬 항목은 변경 전·후에 같은 항목을 누르도록 글자가 아닌 메뉴 값으로 골랐다. 즐겨찾기 빈 화면은 콘텐츠 4개의 즐겨찾기를 모두 끈 데이터다.
- 찍은 상태(모두 글자 1.0배, 스크롤 맨 위): 정렬 메뉴를 연 화면(최신순 선택), "즐겨찾기 우선"을 고른 뒤 메뉴를 다시 연 화면, 즐겨찾기 빈 화면.
  변경 전은 화면 파일 두 개만 `c75d806`로 잠시 바꾼 빌드, 변경 후는 `9709e88` 빌드다. 앱 안에서 읽은 문구는 변경 전 iOS·Android 모두 "북마크" 세 문구,
  변경 후 모두 "즐겨찾기" 세 문구였다. 변경 후 메뉴는 넓어졌고 "즐겨찾기 우선"과 체크가 한 줄에 들어갔다.
- iOS에서는 Orca 에뮬레이터 명령(OS 입력 장치 탭)으로 아카이브 탭 → 정렬 버튼 → "즐겨찾기 우선" → 정렬 버튼을 눌러,
  메뉴가 열리고 선택이 바뀌는 것을 화면 구조(`ax`)로 확인했다. 메뉴 항목 폭은 화면 폭의 0.3486(약 137pt = 145 − 메뉴 안쪽 여백 8)이었다.
- 비교 자료는 저장소 밖 `.utmp/ticket-198-screens/`에 두었다(새 checkout에는 없다). `compare-ios.png`, `compare-android.png`.
  정렬 메뉴 두 상태는 Figma에 열린 메뉴 원본이 없어 변경 전·후 2장, 즐겨찾기 빈 화면은 Figma I02 `111:4103`(2026-11-03 조회)과 3장으로 비교했다.
  Figma 프레임(375×812)과 기기 화면 크기·상태 표시줄의 차이는 보정하지 않았다.

## 미검증 범위

- 실기기, 실제 서버, 글자 확대 상태의 기기 화면은 확인하지 않았다. 글자 1.1–1.3배는 위젯 테스트로만 확인했다.
- 글자 1.3배를 넘는 확대에서는 정렬 메뉴가 여전히 넘칠 수 있다(결정한 기준 밖).
- Android에서는 OS 입력 장치 탭(Orca)을 시험하지 않았다.
