# 상세 "함께 보면 좋은 콘텐츠"를 카테고리가 겹치는 최대 3개로 줄이기 (#310)

2026-11-09, 브랜치 `fix/related-content-and-notice-menu`. 팀 피드백 시트 69번(앱 0.5.0) 대응이다. 커밋 `50fa302`.

## 사용자 결정

- 2026-11-09 "상한+고르는 기준 변경" → "3개·카테고리 하나라도 겹침 (Recommended)": 최대 3개, 첫 카테고리만이 아니라 소속 카테고리가 하나라도 겹치는 콘텐츠를 목록 순서로 고른다. 미분류끼리도 고르고, 모자라면 있는 만큼만 보인다.
- 계정 전체에서 고르기·서버 선정(pending-20, DEC-05)은 정하지 않았다.

## 구현

- `frontend/lib/features/content/detail_screen.dart`: 최상위 함수 `relatedContentsFor(content, contents)`를 두고 상세가 이것으로 연관 카드를 고른다.
  - 후보는 상세를 연 목록에서 지금까지 불러온 항목 중 현재 콘텐츠(같은 `id`)가 아닌 것이다.
  - 카테고리 ID가 둘 다 있고 같으면 겹친다. 미분류는 앱의 기존 관례대로 표시 이름 `catUncategorized.name`으로 알아보며, 미분류끼리는 ID가 없어도(카테고리 목록을 못 받았을 때의 대체 미분류) 겹친다. ID 없는 일반 카테고리는 겹치지 않는다. 이름이 같아도 ID가 다르면 고르지 않는다.
  - 목록 순서 그대로 앞에서 3개까지 고른다. 0개면 기존 빈 안내를 그대로 보인다.
- 카드 모양·섹션 제목·빈 안내 문구·카드 탭 동작·하단 "N / 전체"는 바꾸지 않았다.
- 미리보기 도구 `frontend/test/support/detail_preview.dart`는 같은 함수로 연관 카드를 모은다.

## 테스트

  - 수정 전 코드(`dd34e0e`)에서는 상한(같은 카테고리 8개, 네 번째 겹침), 두 번째 카테고리 겹침, 이름 같고 ID 다른 행 4개가 실패했다.
- `frontend/test/detail_alignment_test.dart`(이슈 허용 범위 안): `_Scene.related`를 새 규칙으로 계산하고, fixture 제목 두 개('두 번째 분류로 겹치는 항목', '세 개를 넘어 제외할 항목')와 테스트 이름(`detail callbacks and capped loaded-order overlap`)을 새 의미에 맞췄다.
