### 11. 2026-09-22 URL 길이 검증 수정

<a id="b-b3d47941bce2e998"></a>

- PostgreSQL을 사용하는 API 테스트에서 2,050자 URL을 저장하면 500이 반환되는 실패를 먼저 재현했고, 수정 후 422와 미저장을 확인했다. 기존 `HttpUrl` 입력 제한과 DB의 `VARCHAR(2048)` 제한이 달랐으며, 인코딩·정규화 후 길이가 증가하는 경우도 있었다.
- `original_url`은 인코딩·정규화 후 저장 문자열 기준으로 최대 2,048자이며 OpenAPI에도 제한을 표시한다. 정확히 2,048자는 저장되고, 초과하면 URL을 자르거나 입력 주소로 대체하지 않고 422로 거절한다.
- 직접 저장, 공유 `url`·`raw_text`, Instagram 주소 정규화, 리다이렉트 결과와 메타데이터 실패 경로를 검증했다. 공유 원문은 기존대로 최대 5,000자이며 추적 파라미터 제거 후 URL이 제한 이내인 공유는 유지한다.
- 내부 URL 검증 오류만 422로 변환한다. 카테고리 추천·DB 변경 전에 최종 URL 길이를 재확인하고, 거절 시 콘텐츠·태그·이벤트·요약 작업이 생성되지 않는지 확인했다. 정상 Instagram·YouTube 및 URL 없는 스크린샷 기존 테스트도 통과했다.
- Python 3.12와 격리된 PostgreSQL 17에서 전체 테스트 **540개 통과**(34개 추가). Ruff, compileall, 빈 DB의 `alembic upgrade head`와 `alembic check`도 통과했다. 기존 Starlette/httpx 사용 중단 예정 경고 1건은 남아 있다.
- DB 스키마·FE·성공 응답 구조는 변경하지 않았다. 외부 메타데이터는 테스트 대역으로 검증했으며, 원격 CI 결과는 PR에서 확인한다. 로컬 Docker 배포 검사·Railway 반영·외부 사이트·실기기 검증은 이번 작업에서 실행하지 않았다.
