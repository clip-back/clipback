# 아이콘 버튼 스크린 리더 이름 (#202)

2026-11-07, 시작 커밋 `ff7e740` 기준으로 구현하고 티켓 리뷰 반영과 전체 검증까지 마쳤다.
코드 커밋은 `02fbbf4`(구현) → `070ede7`(리뷰 S1 반영)이고, 전체 검증의 기준 코드는 `070ede7`이다.
이후 감독이 아래 기기 AX 확인을 추가했다. AX 확인은 실제 VoiceOver·TalkBack 음성 청취를 뜻하지 않는다.

## 구현

- 화면 모양은 바꾸지 않았다. `tooltip`은 길게 누를 때 말풍선이 떠서 쓰지 않고, 아이콘을 `Semantics(label:)`로 감싸 버튼 노드에 이름을 합쳤다.
  `SvgIconButton`에 `semanticLabel`(선택)을 더하고, 아카이브·즐겨찾기·분류 필요·전체보기 카드의 비공개 IconButton 래퍼에도 같은 방식으로 이름을 넣었다.
- 카테고리 행 더보기(`CategoryRow`의 기본·보관 스타일)는 바깥 행 InkWell에 이름이 섞이지 않도록 `Semantics(container: true, button: true, label: '더보기')`로 감쌌다.
  진행 중인 카테고리(`mutationLabel` 있음)에서는 이름은 남고 누르기 동작만 빠진다.
- 붙인 이름

| 화면 | 버튼 | 이름 |
| --- | --- | --- |
| 홈 | 상단 검색 / 알림 | 검색 / 알림 |
| 상세 | 상단 뒤로 / 더보기 | 뒤로가기 / 더보기 |
| 아카이브(카테고리) | 상단 검색 / 톱니 / 폴더+ | 검색 / 카테고리 관리 / 카테고리 추가 |
| 아카이브(카테고리)·카테고리 관리 | 카테고리 행 더보기 | 더보기 |
| 즐겨찾기 | 상단 검색 / 톱니 | 검색 / 카테고리 관리 |
| 분류 필요 | 상단 뒤로 / 검색 / 톱니 | 뒤로가기 / 검색 / 카테고리 관리 |
| 콘텐츠 저장 | 상단 닫기 | 닫기 |
| 콘텐츠 카드(기본·전체보기) | 더보기 | 더보기 |

- "뒤로가기"·"카테고리 관리"·"카테고리 추가"는 기존 화면의 문구(`notification_list_screen.dart`, `category_content_widgets.dart`, `category_management_screen.dart`)를 그대로 썼다.
- 이름을 정해야 해서 붙이지 않은 버튼

| 화면 | 버튼 | 동작 |
| --- | --- | --- |
| 상세 | 날짜 줄 링크 버튼(`detail-original-button`) | 링크 콘텐츠는 원본 링크를 밖에서 열고, 스크린샷은 원본 이미지 시트를 연다 |

| 상세·콘텐츠 카드 | 즐겨찾기 별 | 즐겨찾기 켜기·끄기(켜짐 상태 표현도 정해야 함) |
| 전체 탭·상세 | 하단 중앙 + | 콘텐츠 추가 진입. AX에서 이름 없는 이미지이며 이름 결정 필요 |
| 검색 | 검색어 지우기, 최근 검색어 삭제 | 버튼 역할도 없음 |
| 콘텐츠 저장 | 링크 입력 지우기 | 입력 지우기 |

## 감독 기기 AX 확인

2026-11-07 03:48에서 03:57 KST, 문서 포함 `0dc123c` 트리로 빌드했다. iPhone 16 / iOS 18.6(393×852pt, 상단/하단 안전 영역 59/34pt), Medium_Phone / Android 16 API 36(1080×2400px, 논리 411.43×914.29, 안전 영역 24/24)에서 로컬 메모리 API와 배율 1.0으로 실행했다. 두 기기는 순서대로 사용하고 종료했으며 Android Gradle 데몬도 종료했다. iOS kernel 해시 접두는 `a2efefbab585`, Android APK SHA-256 접두는 `2e05526c393d`다.

`orca emulator ax --json`으로 아래 이름을 각각 확인했다. 탭 이동은 AX frame/bounds의 중심을 사용한 Orca 탭이며, 홈 → 아카이브 전체보기 → 카테고리 → 즐겨찾기 → 링크 상세 → 마이로 실제 이동했다.

| 화면 | 두 플랫폼에서 확인한 이름 |
| --- | --- |
| 홈 | 검색, 알림 |
| 아카이브 전체보기 | 검색, 카테고리 관리, 카드 더보기 |
| 아카이브 카테고리 | 검색, 카테고리 관리, 카테고리 추가, 각 행 더보기 |
| 즐겨찾기 | 검색, 카테고리 관리, 더보기 |
| 링크 상세 | 뒤로가기, 더보기 |
| 마이 | 기존 계정 관리 |

이름 없는 버튼은 홈·즐겨찾기 카드 및 상세의 별 토글, 상세 날짜 옆 원본 열기, 각 탭·상세의 하단 중앙 +였다. 이 이름들은 위 보류 목록에 남겼다. 상세 이전/다음은 이번 단일 콘텐츠 화면에서 비활성 상태였고 이름 검증을 주장하지 않는다. 검색·저장 화면의 보류 목록은 코드 조사 결과로 기기 탐색 결과와 구분한다. 마이의 계정 관리는 이미 이름이 있었으며 추가 무명 상단 버튼은 없었다.

홈 ‘최근 저장한 콘텐츠’는 iOS Image, Android ImageView로 노출됐다. 아카이브 카테고리 행과 마이 메뉴·하단 탭도 이미지 노드와 텍스트가 합쳐져 있었다. 제목 구현을 바꾸는 일은 범위 밖이라 발견만 기록했다.

증거는 `.utmp/ticket-202/screens/`의 `ios-home-ready.ax.json`, `android-home.ax.json` 및 각 플랫폼 `categories`, `bookmarks`, `detail`, `my`, `archive`의 `.ax.json`·`.png`다. 홈 iOS 원본은 `ios-after-normal-top.png`다. 감독은 홈·카테고리·즐겨찾기·상세·마이 원본 PNG를 열어 해당 화면과 버튼이 보이고 키보드·OS 메뉴가 없음을 확인했다. AX 이름 자동 대조는 `screens/ax-check.txt`에 보존했다.

화면 모양 변경이 없는 접근성 수정이므로 새 Figma 기준·변경 전 기기 촬영·3열 비교는 만들지 않았다. 시작 커밋의 이름 누락은 수정 전 실패 테스트로 확인했다. 움직임 결함이 아니므로 영상은 촬영하지 않았다. 홈 `/ready` 조건과 unexpected=[]를 확인했으나 다른 탭의 `/probe`는 홈 전용 스크롤 탐색 때문에 HTTP 500이어서 조건 증거로 사용하지 않았다(오류 파일 보존). 다른 화면의 확인 근거는 OS 스크린샷과 해당 시점 AX다.

프리뷰 준비 중 상대 import 오류와 외부 테스트의 SharedPreferences 설정 누락을 보완해 사전 테스트 2개를 통과했다. 이 보완은 `.utmp` 확인 테스트에 한정됐다. Android 재실행 직후 첫 AX 요청은 종료 1이었고 준비 뒤 요청이 성공했다. 앱 코드 결함으로 단정하지 않았다. 운영·실제 OAuth·실기기·음성 청취·원격 CI 결과는 포함하지 않는다.
