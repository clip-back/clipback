### 12. 2026-09-24 콘텐츠 재발견 추천 DB 준비

<a id="b-ae85c40c9190ff6d"></a>

- 콘텐츠에 열람·추천 집계 필드, 이벤트에 재시도 UUID·당시 카테고리 정수 배열·추천 항목 FK를 추가했다. 추천 배치·항목·노출 테이블과 날짜·대상·순서·이벤트 ID 제약 및 조회 인덱스를 추가했다.
- 마이그레이션 `202609240012`는 기존 `202609220011` 뒤에 적용하며, 현재 콘텐츠와 소유자가 일치하는 열람 이벤트로만 `open_count`를 초기화한다. 과거 카테고리는 NULL로 유지하고 기존 이벤트·누적 통계는 보존한다.
- 대상 삭제 시 추천 항목의 실제 FK만 NULL로 바뀌고 배치·원래 대상 ID·노출·열람 이력은 유지된다. 공개 API·응답·수집 서비스·프론트는 변경하지 않았다.
- 격리 PostgreSQL 17.7에서 빈 DB upgrade·모델 일치, 실제 이전 스키마의 데이터 초기화, 0012 downgrade·재upgrade, 삭제·유일성·값 제약을 검증했다. Python 3.12.7 전체 **578개 테스트 통과**(신규 38개), Ruff·compileall 통과. 기존 Starlette/httpx 경고 1건은 남아 있다.
- 새 인덱스로 반환 순서가 달라진 기존 YouTube 통합 테스트 2개는 이벤트 ID 정렬을 명시해 보완했다.
- 위 결과는 로컬 검증이다. 원격 CI·Docker·Railway·실기기 검증은 미실행이다. 1단계만 운영 배포하지 않으며, 2단계 수집 코드와 함께 기존 쓰기를 중지한 상태에서 마이그레이션·최종 집계 후 새 코드를 시작한다.

### 2026-09-24 1단계 구현·검증

<a id="b-93afc0e6e3b1b97e"></a>

- 콘텐츠 열람·추천 집계 필드, 이벤트 UUID·정수 배열·추천 유입 FK, 추천 배치·항목·노출 모델을 추가했다.
- `202609240012`는 `202609220011` 다음에 적용한다. 현재 콘텐츠와 사용자까지 일치하는 기존 열람 이벤트로만 `open_count`를 초기화하며, 원본 이벤트·마지막 열람 시각·과거 카테고리를 변경하지 않는다.
- 격리된 PostgreSQL 17.7에서 빈 DB `alembic upgrade head`, `alembic check`를 통과했다.
- 신규 DB 테스트 38개를 추가했다. 별도 스키마에 실제 이전 마이그레이션을 적용한 뒤 기존 데이터를 넣어 upgrade, 신규 데이터가 있는 상태의 0012 downgrade, 재upgrade와 원본 보존을 검증했다.
- 대상 삭제 후 배치·항목·노출·스냅샷·누적 통계 유지, UUID·날짜·순서·대상 유일성, NULL과 빈 배열의 차이, 잘못된 값의 DB 거절을 검증했다.
- 새 이벤트 인덱스로 기존 YouTube 통합 테스트의 정렬 없는 조회 가정이 드러났다. 해당 테스트에 `ORDER BY ContentEvent.id`를 명시해 생성 순서를 검증하도록 보완했다. 서비스 동작은 변경하지 않았다.
- Python 3.12.7 전체 테스트 **578개 통과**. Ruff, compileall, Git diff 검사를 통과했다. 기존 Starlette/httpx 사용 중단 예정 경고 1건은 남아 있다.
- 공개 API·응답·실제 이벤트 수집·추천 알고리즘·프론트는 변경하지 않았다. 원격 CI·Docker 검사·운영 배포·실기기 검증은 실행하지 않았다.
