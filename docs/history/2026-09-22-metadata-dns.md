### 8. 2026-09-22 메타데이터 DNS 리바인딩 수정

<a id="b-9d94fdb824ee3ec1"></a>

- `MetadataClient`는 URL 검사에서 확인한 공개 IP로만 연결한다. 검사 뒤 DNS 응답이 내부 IP로 바뀌어도 연결 대상이 바뀌지 않는다.
- 원래 도메인의 Host·TLS SNI·인증서 검증·쿠키 범위·결과 URL을 유지한다. 같은 IP의 다른 도메인 연결을 재사용하지 않도록 keep-alive를 비활성화했다.
- 같은 도메인을 포함한 모든 리다이렉트에서 주소를 다시 검사한다. 연결 실패 시 검증된 나머지 IP만 순서대로 시도하며 전체 제한 시간을 유지한다. 응답 읽기 실패는 재시도하지 않는다.
- 위험한 주소는 직접 입력·공유 API 모두 기존대로 422를 반환하고 저장을 중단한다. API 계약·DB 스키마·프론트 코드는 변경하지 않았다.
- 검증: 기존 코드에서 DNS 검사 후 `127.0.0.1`로 연결되는 회귀 테스트 실패를 재현했고 수정 후 통과했다. 로컬 TLS 서버로 정상 인증서·호스트 불일치·신뢰되지 않은 인증서·같은 IP의 다른 도메인 리다이렉트를 검증했다.
- Python 3.12와 격리된 PostgreSQL 17에서 전체 테스트 **443개 통과**(회귀 테스트 18개 추가). Ruff, compileall, 빈 DB의 `alembic upgrade head`와 `alembic check`도 통과했다. 기존 Starlette/httpx 사용 중단 예정 경고 1건은 남아 있다.
- 이번 검증은 로컬 테스트다. 원격 CI·Docker 배포 검사·Railway 반영·외부 사이트 및 실기기 연결은 실행하지 않았다.
