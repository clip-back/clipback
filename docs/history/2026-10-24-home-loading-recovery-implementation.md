## 구현 전 확인

- 기존 계정 초기화는 카테고리·홈 첫 목록·사용자 정보·통계를 순서대로 기다린다.
  같은 초기화가 온보딩·계정 연결·일반 재조회에도 쓰이므로 최초 홈 전용 동작을 구분한다.
- 기준 코드의 900ms는 시작 스플래시에만 있었고 홈 캐릭터 로딩의 별도 최소 시간은 없었다.
  확정 명세의 ‘기존 최소 900ms’라는 설명과 차이가 있으나, 구현 값은 확정된 최소 900ms를 따른다.
  실제 준비 시간에서 이미 지난 시간을 제외하고 전체 15초 예산을 늘리지 않는다.
- 이전 시도의 최종 401은 Repository에 도착하기 전 API 계층에서 세션을 무효화할 수 있다.
  따라서 화면 대기만 종료하지 않고 요청 수명과 인증 부작용도 검증한다.
- 실행 증거와 대역 제어 스크립트는 `/private/tmp/clipback-home-recovery-native-20261024/`,
  TDD·작업 메모는 `/private/tmp/clipback-home-implementation/`에 둔다.
  임시 경로는 영구 보존을 보장하지 않는다.

구현·검증 진행 중이며 아래 결과는 실제 실행이 끝난 뒤 갱신한다.

## #78 구현과 재현

- `803b548`과 인증 만료 후속 수정 `fd1daf3`을 작업 브랜치에서 통합 브랜치로 fast-forward했다.
- 최초 홈에만 전체 15초 요청 수명을 적용한다. 카테고리→첫 목록의 단계 변경과 인증 갱신·재전송에도
  같은 시도 예산을 사용하며, 로컬 저장소 읽기·소셜 인증 자체의 대기는 포함하지 않는다.
- 무응답 시 14.999초에는 로딩, 15초에는 기존 오류를 기대하는 RED를 먼저 재현했다.
  수동 재시도에는 새 예산을 주고, 연속 입력과 앱 복귀만으로 추가 시도를 만들지 않는다.
- 이전 Apple SDK 확인이 무응답이면 재시도에서도 새 확인을 막던 RED를 재현했다.
  확인별 소유권과 요청 수명으로 다음 시도의 확인을 허용하고, 종료된 확인의 늦은 철회 결과는 무시한다.
- 14초에 철회가 확정된 뒤 서버 로그아웃이나 공유 차단이 지연되더라도, 15초 이후 로컬 접근을
  차단해야 한다. 로컬 토큰 삭제 뒤에도 일반 오류가 남는 추가 RED를 재현하고 로그인 복구를 수정했다.
  실제로 확인된 현재 철회와, 확인 전에 종료된 과거 SDK 응답을 구분한다.
- 공유 준비에 대한 범위 밖 회귀도 재현했다. 토큰 갱신의 저장 알림이 자동 공유 준비를 예약하면
  종료된 HTTP 요청 범위를 상속해 새 공유 자격증명 발급이 생략됐다.
  실제 `AppDependencies`·HTTP·네이티브 채널 대역에서 RED를 확인한 뒤, 자동 공유 준비 예약만
  앱 생명주기의 Zone에서 실행하도록 수정했다. API 콜백·리스너 전체의 실행 범위는 바꾸지 않는다.
- 누적 조회 시간·인증 갱신 포함 시간·재시도 새 예산·이전 categories/feed 200/503/401·refresh 200/401·
