### 13. 2026-09-24 저장·열람 이벤트 수집 확장

<a id="b-3b62dfe4599682ec"></a>

- 저장 시 최종 실제 카테고리를 정렬·중복 제거한 배열로 기록한다. 직접·공유·스크린샷·YouTube 저장 모두 공통 경로를 사용하며 이후 자동 분류·분류 변경·삭제는 과거 스냅샷을 바꾸지 않는다.
- view POST는 선택적 본문으로 필수 UUID와 선택적 추천 항목 ID를 받는다. 같은 사용자·UUID·요청은 한 번만 기록하고 다른 내용으로 ID를 재사용하면 409다. 본문 없음·JSON `null`은 매번 기록한다. 기존 201 응답은 유지한다.
- 행 잠금과 DB 유일 제약으로 신규 이벤트·카운터·동일 UTC 열람 시각을 원자적으로 갱신한다. 추천 유입은 본인 배치·대상 소유권과 현재 콘텐츠/카테고리를 확인하며 노출 선행은 요구하지 않는다. 삭제된 콘텐츠는 재시도도 404다.
- 실제 PostgreSQL의 독립 연결로 중복 요청·다른 ID·다른 콘텐츠 충돌, 롤백 후 대기 요청 성공, 분류 변경·삭제와 열람의 경쟁을 검증했다. API·저장경로·누적 통계 회귀와 스냅샷 보존도 통과했다.
- 추천 항목 ID가 DB 정수 범위를 넘을 때 500이 발생하는 회귀를 재현하고 입력 검증으로 422를 반환하도록 보완했다.
- Python 3.12.7 및 격리 PostgreSQL 17.7에서 전체 **629개 테스트 통과**(51개 증가, DB 테스트 생략 없음). 빈 DB upgrade·모델 일치, Ruff·compileall·Git diff 검사 통과. 기존 Starlette/httpx 경고 1건은 남아 있다.
- 신규 마이그레이션·추천 선정·노출 API·프론트는 이번 변경에 포함하지 않았다. 추천 계획의 2단계까지 완료이며 3~7단계는 미착수다. 저장 요청 자체의 재시도 중복 방지는 미구현이다.
- 로컬 검증만 수행했다. 원격 CI·Docker·운영 배포·실기기는 미검증이며, 운영 반영 시 기존 쓰기 중지 → 1단계 마이그레이션·최종 집계 → 새 수집 코드 시작 → 쓰기 재개 순서를 유지한다.

### 2026-09-24 2단계 구현·검증

<a id="b-fa5bf5bed8b7dadd"></a>

- 공통 저장 경로에서 최종 실제 분류의 정렬·중복 제거 배열을 기록한다. 직접·공유·스크린샷·YouTube 저장과 미분류 ID를 포함하며, 비동기 분류·사용자 변경·카테고리 삭제는 과거 배열을 바꾸지 않는다.
- view POST는 선택적 본문을 받는다. 본문이 있으면 UUID는 필수이며 추천 항목 ID는 선택적 양수 JSON 정수다. 본문 없음·JSON `null`은 기존처럼 매번 기록한다. 응답은 기존 201과 `{content_id, event_type}`을 유지한다.
- 콘텐츠 행 잠금과 지정된 이벤트 유일 제약의 `ON CONFLICT DO NOTHING`으로 동일 요청은 한 번만 기록한다. 새 이벤트만 카운터와 마지막 열람 시각을 갱신하며, 이벤트·스냅샷·갱신은 하나의 트랜잭션이다. ID 재사용 충돌은 409다.
- 추천 유입은 배치·실제 대상의 소유권과 Today 콘텐츠/Weekly 카테고리 일치를 검증한다. 노출 선행은 필요 없고 추천 카운터를 갱신하지 않는다. 성공한 요청의 재시도는 분류 변경 후에도 최초 기록을 보존하며 삭제된 콘텐츠는 404다.
- 새 view API 통합 테스트 37개, 독립 PostgreSQL 연결의 동시성 테스트 10개를 추가했다. 같은 ID·새 ID·다른 콘텐츠/추천 유입 경쟁, 최초 요청 실패 후 대기 요청 성공, 분류 변경·삭제의 양쪽 잠금 순서를 검증했다.
- 기존 저장경로 테스트에 실제 배열과 후속 분류·삭제 시 보존 검증을 추가했다. 이벤트 삽입·카운터 갱신·커밋 실패의 전체 롤백, 누적 통계와 기존 요청 호환을 검증했다.
- 신규 추천 항목 ID가 PostgreSQL INTEGER 범위를 넘을 때 500이 발생하는 실패를 재현하고, 1~2,147,483,647 범위의 JSON 정수만 받아 422로 거절하도록 수정했다.
- Python 3.12.7 및 격리 PostgreSQL 17.7에서 전체 **629개 테스트 통과**(1단계 대비 51개 증가, DB 테스트 생략 없음). 빈 DB `alembic upgrade head`, `alembic check`, Ruff, compileall, Git diff 검사를 통과했다. 기존 Starlette/httpx 경고 1건은 남아 있다.
- 신규 마이그레이션·추천 선정·노출 API·프론트 변경은 없다. 원격 CI·Docker·운영 배포·실기기 검증은 실행하지 않았다. 저장 요청 자체의 재시도 중복 방지는 이번 범위에 포함하지 않았다.
