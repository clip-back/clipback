# 이미지 계정 보관 한도 구현·검증

2026-10-23, 이슈 #66. 기준 main은 `5671e79`, 기능 커밋은 `7a1ceb9`이며
삭제 처리 통합 커밋 `c63f34c`를 작업 브랜치에 병합한 뒤 관련 회귀를 다시 실행했다.
이 기록은 로컬 구현·합성 데이터 검증이며 운영 배포 기록이 아니다.

## 구현

- 본앱·양쪽 네이티브 공유는 같은 업로드 API에서 서버 사용자 ID별 원본 합계를 사용한다.
  게스트 31,457,280바이트, 로그인 계정 314,572,800바이트에 정확히 도달하는 저장은 허용한다.
- `ImageUploadPolicy.authorize`가 사용자 행을 잠그고 현재 DB의 게스트 여부와 원본 합계를 확인한다.
  같은 요청 세션을 콘텐츠 커밋·롤백까지 유지해 동시 요청이 한도를 우회하지 못한다.
  별도 카운터·예약 테이블·마이그레이션은 추가하지 않았다.
- 기존 크기 미확인 원본은 해당 파일 저장소에서 크기를 확인한다. 확인할 수 없으면 503으로
  신규 저장을 막으며 0으로 세지 않는다. 삭제가 커밋되면 살아 있는 콘텐츠 합계에서 즉시 빠진다.
  진행 중 삭제와 겹친 저장이 보수적으로 거절될 수 있으나 삭제 응답 후 새 요청에는 반환 용량을 반영한다.
- 완료된 공유 재전송은 한도 검사 전에 기존 결과를 돌려준다. 계정 승격은 같은 ID와 원본을 유지하며
  한도만 확대한다. 기존 한도 초과 원본의 조회·삭제는 유지한다.
- 계정 한도 오류 `409/image_quota_exceeded`와 한 장 크기 오류 `413/image_file_too_large`를
  Dart·Swift·Java에서 구분하고 기존 오류 토스트·공유 상태 영역을 사용한다.

## 자동 검증

- 최초 API 테스트는 정확히 30MiB 저장 후 추가 요청이 409 대신 201을 반환해 실패했다.
  정책 적용 후 통과했다. Dart API 테스트도 기존 일반/영문 오류를 재현한 뒤 한국어 구분 안내로 통과했다.
- 삭제 처리 병합 후 관련 PostgreSQL API·서비스 검사 **75개 통과**(23.34초).
  30MiB·300MiB 경계, 본앱/공유 합산·재전송·승격·기존 크기 확인·저장 실패·삭제 후 반환을 포함한다.
- 백업 복원 통합 커밋 `cc131bb`까지 병합한 최종 브랜치에서 한도·업로드·삭제 검사
  **41개 통과**(6.42초)로 다시 확인했다. 전체 통합 검증은 후속 #74에서 수행한다.
- 실제 서로 다른 PostgreSQL 연결의 동시 요청은 마지막 한 장만 성공했다.
  사용자 잠금을 잠시 제거한 결함 주입에서는 두 요청이 모두 201로 성공해 해당 테스트가 실패했고,
  잠금을 복원한 최종 코드에서는 다시 통과했다.
- Dart API·실제 저장 위젯의 인증/원본 유지 회귀 **51개 통과**. 변경된 Dart 파일의 정적 분석과
  관련 Python Ruff 검사, 최종 diff 공백 검사를 통과했다.
