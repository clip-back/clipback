# 비공개 Volume 원본 읽기와 원격 백업 검증

기준: #99, 통합 기준 a7adde7, 2026-10-26. 운영 설정·실제 Railway 접속·원본은 변경하지 않았다.

## 구현

명시적 원본 식별 등록과 별도 비공개 원본 읽기 리스너를 제공한다. 운영자 runtime의 local 클라이언트만 원격 읽기로 교체하고 백업 준비·게시 전 과정에서 동일한 어댑터를 사용한다. 자산이 0개인 경우에도 식별을 확인한다. API와 별도 리스너의 시작·종료를 감독하며 운영 앱은 공개 API lifespan을 실행하지 않는다.

현재 실행·설정 안내는 [운영 원본의 비공개 읽기](../backend/image-operator-source.md)에 있다.

## 실제 실행 결과

- 등록/HTTP 첫 실패: 신규 설정 모듈이 없는 기존 코드에서 실패를 확인했다.
- 이전 API 이미지의 Docker 실패: 원본 등록 명령이 포함되지 않아 실패했다.
- 등록·HTTP 경계: 2 passed. 식별 누락/불일치·재등록·권한·경로·symlink·과대/누락 파일·읽기 전용 동작 확인.
- 실제 빌드 API + PostgreSQL18 운영자 + PostgreSQL18 + Moto 분리 컨테이너: 2 passed, 27.78초. API만 원본을 mount하고 운영자에는 빈 경로를 설정한 채 실제 원본을 백업했다. 잘못된 식별·해시·누락·빈 자산·연결 단절, 공개 경로와 잘못된 인증 거절, 두 리스너 종료·시작 실패 전달을 확인했다.
- 기존 직접 create CLI가 원격 설정을 무시하던 경로를 Docker에서 재현한 뒤 명시적 runtime으로 연결했다. 최종 운영자 이미지의 manual·create 원격 백업 시나리오: 1 passed, 25.03초.
- 관련 백업·보존·복원·저장소/신규 HTTP 회귀: 64 passed, 6.36초.
- lint 및 diff 공백 검사 통과.

첫 Docker 검증 뒤 비밀값의 공백/개행 설정 거절을 소폭 보완했고 운영자 이미지는 이후 재빌드해 직접 CLI도 검증했다. 최종 코드의 64개 회귀·lint를 확인했다. API 이미지의 해당 설정 검증 보완과 최종 통합 이미지 검증은 전체 단계에서 다시 실행한다. 이번 실행이 만든 컨테이너·네트워크는 각 테스트 finally에서 정리했다. 테스트 이미지 `clipback-api:ticket99`, `clipback-operator:ticket99`는 후속 통합 검증에 재사용할 수 있다.
