### 16. 2026-09-25 Weekly 집계·카테고리 조회

<a id="b-3caeddb8e011aa1c"></a>

- 인증된 Weekly GET은 200·캐시 금지와 집계 기간·배치 정보·최대 2개 카테고리 카드를 반환한다. 카테고리의 보유 수·마지막 저장일은 현재 관계 기준이며 행동 건수·점수·완성 문구는 공개하지 않는다. Today Stage와 무관하며 결과가 있는 매 요청마다 새 배치·항목을 저장한다.
- 기간은 KST 오늘을 포함한 7개 날짜의 첫날 00시부터 잠금 후 확정한 UTC 시각까지의 `[시작, 끝)`이다. 당시 분류 배열로 저장 이벤트 수와 고유 열람 콘텐츠 수를 각각 집계하며 반복 열람은 최근 시각에 반영한다. 삭제 콘텐츠·미분류·빈 카테고리·타 사용자 데이터는 합의한 기준으로 제외한다.
- MOST_SAVED→MOST_VIEWED→REDISCOVERY 순서로 중복 없이 선정한다. 행동 수→최근 행동→현재 보유 수→완전 동점 랜덤 순으로 비교하며, 재발견은 기간 내 미노출 우선·모두 노출됐으면 가장 오래된 마지막 노출 순이다.
- 사용자→콘텐츠 ID순 SHARE 잠금 이후 시각을 확정한다. 보유·행동 집계는 잠근 콘텐츠 ID만 사용해 동시 신규 저장은 다음 조회부터 반영하며, 조회 자체는 이벤트·카운터·누적 통계를 바꾸지 않는다. 실패하면 배치·항목을 함께 롤백한다.
- 순수 선정 31개·PostgreSQL API/집계 통합 20개·독립 연결 동시성 19개를 추가했다. 실제 잠금 대기, 양쪽 실행 순서, 새 저장 제외, 자정 통과, 실패 후 대기 요청 복구와 반환한 항목의 노출/view 연결을 검증했다.
- Python 3.12.7 및 격리 PostgreSQL 17.7의 전체 검증 전용 DB에서 **857개 테스트 통과**(70개 추가, DB 테스트 생략 없음). Ruff·compileall·별도 빈 DB upgrade/check·Git diff 검사도 통과했다. 기존 Starlette/httpx 경고 1건은 남아 있다. 외부 AI·OCR·메타데이터는 대체하고 YouTube 워커를 비활성화했다.
- 추천 계획은 5단계까지 완료이며 6~7단계는 미착수다. 프론트는 같은 홈 방문에서 받은 항목 ID를 유지하고 노출 재전송에 재사용해야 한다. 신규 마이그레이션·프론트 구현·push·운영 배포는 포함하지 않았으며 원격 CI·Docker·실기기·운영 검증은 별도다. 기존 쓰기 중지→마이그레이션·집계 초기화→새 코드 시작→쓰기 재개 절차를 유지한다.

### 5단계 완료 기록 — 2026-09-25

<a id="b-84740a852455c4af"></a>

- 인증된 `GET /api/v1/recommendations/weekly`를 추가했다. 200·캐시 금지, UTC 집계 기간·배치 정보와 최대 2개의 카드 유형·추천 항목 ID·기존 카테고리 요약을 반환한다. 결과가 있는 매 요청마다 새 배치·항목을 저장하며 이전 이력은 유지한다.
- KST 오늘을 포함한 7개 날짜의 시작부터 잠금 후 확정한 UTC 시각 직전까지 집계한다. 당시 카테고리 배열만 사용해 저장 이벤트 수·고유 열람 콘텐츠 수·해당 행동의 최근 시각을 계산한다. NULL·빈 배열·삭제 콘텐츠·타 사용자 데이터는 행동 집계에서 제외하고, 현재 관계로 과거 행동을 재분류하지 않는다.
- MOST_SAVED→MOST_VIEWED→REDISCOVERY 순서로 중복 없이 선정한다. 행동 동점은 최근 행동→현재 보유 수→랜덤 순서이며, 재발견은 기간 내 미노출을 우선하고 모두 노출됐으면 카테고리별 마지막 노출이 가장 오래된 후보를 선택한다.
- 사용자 잠금→본인 콘텐츠 ID순 SHARE 잠금→기준 시각 확정→별도 집계를 수행한다. 현재 보유 수와 행동 집계 모두 잠근 ID 집합을 사용하므로 이후 저장은 다음 요청부터 반영한다. 빈 응답도 커밋하고 배치·항목·응답 구성·커밋 실패는 롤백한다.
- 순수 선정 31개, PostgreSQL API·집계 통합 20개, 독립 연결 동시성 19개를 추가했다. 과거 스냅샷·자동 분류 완료·반복 열람·배열 중복, 실제 노출/view 연결, 조회 무집계와 이전 배치 보존을 검증했다.
- `pg_blocking_pids()`로 실제 대기를 확인하며 열람·분류·콘텐츠/카테고리 삭제·카테고리 노출의 양쪽 실행 순서, 같은 사용자 별도 배치·다른 사용자 독립 처리, 신규 저장 제외, 자정 통과와 실패 후 대기 요청 복구를 검증했다.
- Python 3.12.7·격리 PostgreSQL 17.7의 전체 검증 전용 DB에서 **857개 테스트 통과**(70개 추가, DB 테스트 생략 없음). Ruff·compileall, 별도 빈 DB `alembic upgrade head`·`alembic check`, Git diff 검사를 통과했다. 기존 Starlette/httpx 경고 1건은 남아 있다. 외부 AI·OCR·메타데이터를 대체하고 YouTube 워커는 비활성화했다.
- 신규 마이그레이션·프론트 연동·원격 push·운영 배포는 포함하지 않았다. 6~7단계는 미착수이며 원격 CI·Docker·실기기·운영 검증은 실행하지 않았다. 프론트는 같은 홈 방문의 항목 ID를 유지하고 노출 재전송에 재사용해야 한다.
