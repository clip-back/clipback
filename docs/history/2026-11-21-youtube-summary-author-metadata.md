# 유튜브 요약에 작성자 제목·설명 활용 (#454)

2026-11-21, 기준 커밋 `fe68575`에서 시작했습니다. 첫 구현 커밋은 `0d39ee7`입니다. [이슈 #454](https://github.com/clip-back/clipback/issues/454)

## 변경

- 공개 영상 전체를 분석할 때 YouTube Data API의 작성자 제목과 설명을 함께 참고합니다. 제목과 설명은 영상과 같은 사용자 데이터 영역에 각각 담고 분석 대상 데이터로 표시합니다.
- 문자열인 설명의 앞 2,200자를 선택한 뒤 공백만 남으면 설명을 생략합니다. 작성자 제목에도 각각 공백 여부를 확인합니다. 전송하는 제목과 설명은 앞뒤 공백을 포함해 선택 범위의 원문을 유지하며, 사전 확인 원문은 서버에 보관하거나 로그에 남기지 않습니다.
- 원래 제목이 있으면 주제를 유지하면서 핵심 대상만 25자 안팎으로 새로 표현하도록 지시합니다. Gemini가 실패하면 기존 정책에 따라 처리하며 영상 없는 별도 호출은 하지 않습니다.

## 검수 판단

- 제목과 설명마다 필드명, 표시 이름, 길이 상한을 한 곳에 뒀습니다. 유튜브 설명의 상한은 이 클라이언트에 둡니다.
- 설명의 첫 2,200자가 공백뿐인 입력과 2,200자 안에 글자가 남는 입력에서 영상과 제목이 각각 보존되는지 실제 직렬화 요청으로 확인했습니다.
- 합성 표식이 든 제목과 설명을 보내고, 표식이 없는 가짜 모델 출력을 사용했습니다. 성공·재시도 가능 오류·영구 오류에서 로그와 공개 응답 전체를 확인했습니다. 실제 모델이 만든 요약은 기존 경로로 처리합니다.

## 검증

- 구현 전에는 선택 범위가 공백인 설명이 요청에 포함되어 경계 테스트 1건이 실패했습니다. 검수 반영 후 로컬 PostgreSQL 부분 검사에서 저장 계약과 저장 기준선 두 파일을 포함해 421건이 통과했습니다.
