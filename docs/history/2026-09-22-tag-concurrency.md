### 10. 2026-09-22 태그 동시 수정 처리

<a id="b-f95757d08c5fa45c"></a>

- PostgreSQL의 서로 다른 연결에서 같은 콘텐츠를 각각 `first`와 `second` 태그로 교체하면 두 태그가 함께 남는 회귀 테스트 실패를 재현했고 수정 후 통과했다.
- `update_tags`는 기존 콘텐츠 행 잠금을 재사용해 최신 태그 조회부터 교체·커밋까지 순차 처리한다. 최종 태그는 잠금 획득 순서상 마지막으로 성공한 요청의 전체 목록이다.
- 변경 없는 요청도 트랜잭션을 종료해 잠금을 해제한다. 실패 시 신규 태그와 관계 변경을 함께 롤백하며, 각 응답은 커밋 전에 만든 해당 요청의 적용 결과를 반환한다.
- `pg_blocking_pids`로 후행 요청의 실제 대기를 확인했다. 빈 목록과 추가의 양쪽 실행 순서, 동일 목록 재요청, 오래된 ORM 관계 갱신, 커밋 실패 후 대기 요청 재개, 다른 콘텐츠의 독립적인 수정과 HTTP 소유권·정규화·롤백을 검증했다.
- Python 3.12와 격리된 PostgreSQL 17에서 전체 테스트 **506개 통과**(14개 추가). Ruff, compileall, 빈 DB의 `alembic upgrade head`와 `alembic check`도 통과했다. 기존 Starlette/httpx 사용 중단 예정 경고 1건은 남아 있다.
- API 계약·DB 스키마·FE 코드는 변경하지 않았다. 위 결과는 로컬 검증이며 원격 CI 결과는 PR에서 확인한다. Docker 배포 검사·Railway 반영·실기기 연결은 이번 작업에서 실행하지 않았다.
