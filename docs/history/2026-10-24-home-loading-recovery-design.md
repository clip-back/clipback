## 확정 명세 게시와 티켓 분할안

- 확정 명세를 [GitHub 이슈 #76](https://github.com/clip-back/clipback/issues/76)에 게시하고
  `ready-for-agent` 라벨을 적용했다. 게시한 본문이 승인된 일곱 섹션·사용자 이야기 27개의 원문과
  일치하고 이슈가 열린 상태이며 댓글이 없음을 다시 읽어 확인했다.
- 사용자가 `to-tickets`를 요청했다. 별도의 선행 리팩터링 없이 기존 앱 흐름·초기화·Repository 경계를
  재사용하고, 아래 두 개의 사용자 동작 단위로 나누는 안을 제시했다. 각 티켓에 통합 테스트와
  iOS Simulator·Android Emulator 실행 검증·필요한 문서 갱신을 포함한다.

| 제안 | 선행 | 독립적으로 확인할 결과 |
| --- | --- | --- |
| 1. 필수 목록 준비 시 부가 조회를 기다리지 않고 홈 진입 | 없음 | 사용자 정보·통계가 늦어도 홈이 열리고 현재 계정의 유효한 후속 정보만 반영된다. 기존 인증 확인을 유지한다. |
| 2. 홈 최초 불러오기 전체 15초 제한과 안전한 수동 재시도 | 제안 1 | 필수 조회 무응답은 기존 오류 화면으로 끝나고, 수동 재시도에 새 예산을 부여하며 이전 응답이 새 시도·계정을 덮어쓰지 못한다. |

- 제안 2는 필수 준비 조건을 분리한 제안 1을 사용한다. 별도의 API·화면·테스트 전용 티켓으로 나누지 않는다.
- 상세 티켓 초안은 당시 `/private/tmp/clipback-home-loading-recovery-tickets-20261024/`의
  `01-required-home-readiness.md`, `02-bounded-recovery-and-retry.md`에 작성했다.
  임시 경로는 영구 보존을 보장하지 않는다.
- `to-tickets`의 분할안 확인 단계가 남아 있어 하위 이슈와 네이티브 선행 관계는 아직 생성하지 않았다.
  부모 명세 이슈의 본문·상태는 수정하지 않았다. 게시 후에도 구현·배포 완료를 뜻하지 않는다.
- 이번 게시·분할안 문서화에서는 변경 문서 3개의 내부 링크 대상 150개, 두 티켓 초안의 템플릿·
  경로/코드 미포함·공백을 검사했다. 누락 링크는 없었으며 최종 diff와 `git diff --check`를 통과했다.
  제품 동작 변경이 없어 앱 테스트·양 플랫폼 실행은 새로 수행하지 않았다.
