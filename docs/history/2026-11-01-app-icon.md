# 앱 아이콘을 허투루 아이콘으로 교체

최초 기록일: 2026-11-01 KST. 시작 소스는 `cb6ca40`, 작업 브랜치는 `feat/app-icon`이다.
별도 이슈·명세 없이 2026-11-01 사용자 요청을 기준으로 했고, 0.3.0 배포 후보에 포함한다.
빌드 번호·배포 기록은 이 작업에서 바꾸지 않았다. 현재 기준은
[Figma 화면 맞춤 계획](../figma-ui-alignment-plan.md#figma-current-app-icon)을 따른다.

## 변경 내용

- iOS `frontend/ios/Runner/Assets.xcassets/AppIcon.appiconset/`의 PNG 15개를 같은 이름·크기로 교체했다.
  `Contents.json`은 그대로다. 모두 알파 채널 없는 RGB PNG이며, 1024도 RGB다(App Store 요구).
- Android `frontend/android/app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher.png`
  5개(48·72·96·144·192px)를 같은 이름·크기로 교체했다. 적응형 아이콘(`mipmap-anydpi-v26`)은 사용자 결정에 따라 추가하지 않았다.
- 새 의존성과 저장소 스크립트는 추가하지 않았다. 생성 명령(저장소 루트 기준, `SRC`는 1024 원본 경로):

```bash
# iOS: 파일명의 크기×배율로 픽셀 크기를 계산하고 RGB로 저장 (Pillow 12.2.0)
cd frontend/ios/Runner/Assets.xcassets/AppIcon.appiconset
python3 -I - "$SRC" <<'EOF'
import os, sys
from PIL import Image
src = Image.open(sys.argv[1])
assert src.getchannel("A").getextrema() == (255, 255)
src = src.convert("RGB")
for name in [f for f in os.listdir(".") if f.endswith(".png")]:
    px = int(round(float(name.split("x")[0].split("-")[-1]) * int(name[-6])))
    (src if px == 1024 else src.resize((px, px), Image.LANCZOS)).save(name, optimize=True)
EOF

# Android: sips로 크기만 줄임 (기존 파일처럼 RGBA, 알파는 전부 불투명)
cd frontend/android/app/src/main/res
for p in mdpi:48 hdpi:72 xhdpi:96 xxhdpi:144 xxxhdpi:192; do
  sips -s format png -z ${p#*:} ${p#*:} "$SRC" --out mipmap-${p%:*}/ic_launcher.png
done
```

- 생성 후 `sips -g pixelWidth -g hasAlpha`로 모든 파일이 기존과 같은 크기이고 iOS는 알파가 없는 것을 확인했다.

## 공유 메뉴 아이콘

- iOS 공유 확장(ShareExtension)은 자체 아이콘 asset이 없고 공유 메뉴에 본앱 아이콘을 쓴다. 변경 후 Safari 공유 메뉴에 새 아이콘이 표시됐다.
- Android 공유 수신 Activity에는 별도 `android:icon`이 없어 `<application android:icon="@mipmap/ic_launcher">`를 따른다.
  변경 후 Chrome 공유 메뉴에 새 아이콘이 표시됐다.

## 시뮬레이터·에뮬레이터 실행 (2026-11-01)

- 환경: iPhone 16 / iOS 18.6 Simulator(글자 크기 기본 `large`, 밝은 모드),
  Android Emulator `Medium_Phone` / Android 16(API 36, google_apis_playstore) / 1080×2400, 글자 배율 1.0.
  시뮬레이터와 에뮬레이터는 동시에 띄우지 않았다. 서버·로그인은 쓰지 않았다(아이콘 표시만 확인).
- 변경 전은 `cb6ca40`의 debug 빌드(`flutter build ios --simulator --debug --no-pub`, `flutter build apk --debug --no-pub`),
  변경 후는 아이콘만 바꾼 같은 명령의 빌드를 기존 설치 위에 덮어 설치했다.
- 촬영 상태: 홈 화면의 아이콘과 이름(home), 다른 앱 공유 메뉴의 허투루 항목(share).
- iOS 조작: 이 Mac에는 Simulator 화면 앱이 없고 클릭 주입 권한도 없어,
  `frontend/ios/ShareVerification`을 저장소 밖으로 복사해 테스트 파일만 바꾼 임시 XCUITest로 홈 화면 이동·
  Safari(`https://example.com`) 공유 버튼 탭과 화면 저장을 했다. 임시 테스트는 커밋하지 않았다.
- Android 조작: `adb`로 홈 화면에 앱을 올리고(변경 전 촬영 직전 한 번) Chrome(`https://example.com`) 메뉴 → Share… →
  시트를 위로 끌어 앱 목록을 펼친 상태를 `screencap`으로 찍었다. Chrome 첫 실행 안내는 "Stay signed out"·"No thanks"로 닫았다.

| 플랫폼 | home (전 → 후) | share (전 → 후) |
| --- | --- | --- |
| iOS | Flutter 기본 아이콘 → 허투루 아이콘(원본 그대로, OS 둥근 모서리) | Safari 공유 앱 줄 3번째 칸, Flutter 아이콘 → 허투루 아이콘 |
| Android | Flutter 기본 아이콘 → 흰 원 안에 작게 줄어든 허투루 아이콘 | Chrome 공유 앱 목록 마지막 칸, 같은 흰 원 안의 작은 아이콘 |

- Android 차이: 적응형 아이콘이 없어 런처가 기존 정사각 아이콘을 흰 원 배경 안에 축소해 넣는다.
  노란 정사각형이 원 안에 작게 보이고 글자가 원본보다 매우 작다. 사용자 결정대로 고치지 않고
  [디자인 확인 필요](../figma-ui-alignment-plan.md#figma-pending-android-adaptive-icon)에 기록했다.
- iOS 홈의 이름 앞 파란 점은 새로 설치한 앱 표시로 변경 전·후 모두 있다.
- Android 변경 후 공유 화면은 Chrome이 탭을 하나 더 열어 툴바의 탭 수가 1 → 2로 다르다. 공유 메뉴 영역은 같다.
- 공유 메뉴의 "Clipback Share Receiver"는 Android 공유 검증용 테스트 패키지 `com.huturu.app.test`로, 이번 범위가 아니다.
- 비교 이미지(변경 전 · 변경 후 · Figma 기준)와 원본 스크린샷은 저장소 밖 `.reports/app-icon/`에 보관했다
  (`compare-ios.png`, `compare-android.png`, `before/`, `after/`). 새 checkout에는 포함되지 않는다.

## 자동 검사

- 이미지만 바뀌어 Dart 코드 변화는 없지만 저장소 규칙대로 전체 검사를 실행했다.
- `(cd frontend && flutter analyze --no-pub)` 문제 없음, `(cd frontend && flutter test --no-pub --concurrency=2)` 2018개 통과.
- 변경 후 `flutter build ios --simulator --debug --no-pub`, `flutter build apk --debug --no-pub` 성공(위 실행에 쓴 빌드).
  Release·AAB·실기기 서명 빌드는 하지 않았다.
- `git diff --check` 통과. 바뀐 파일은 아이콘 PNG 20개와 문서 4개뿐이다.
