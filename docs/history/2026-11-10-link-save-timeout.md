# 본앱 링크 저장 응답이 20초 안에 오지 않으면 지연 안내로 끝내기 (#319)

2026-11-10, 브랜치 `fix/link-save-request-timeout`. #298 후속이다.
시작 커밋 `906d253`, 구현 커밋 `2290275`, main `7da787f`(#318) 병합 커밋 `4eff756`(전체 검증·변경 후 촬영 기준).
이 기록을 더한 커밋은 문서만 바꾼다.

## 문제

본앱 + 저장 화면에서 링크를 저장하는 중 응답이 오지 않으면 "허투루가 정보를 추출 중입니다..."와 꺼진 "닫기"에 머물러
같은 화면에서 다시 저장할 수 없었다. 화면을 닫고 다시 열면 새 제출 키라 서버가 이미 저장했다면 같은 링크가 두 번 저장됐다.
2026-11-09 iPhone 13·TestFlight 0.5.1(12)·운영 서버에서 사용자가 비행기 모드로 재현했다(이슈 본문).

## 사용자 결정

- 2026-11-09 "만들어줘", "추천대로": 저장 버튼부터 요청 전체(401 뒤 인증 갱신·재전송 포함) 20초.
  시간 초과 토스트는 사진 저장과 같은 "서버 응답이 지연되고 있어요. 잠시 후 다시 시도해 주세요.". 화면을 다시 열면 새 키(#298)는 유지.
  제한 시간 전 안내와 공유 준비 실패 띠(①-a)는 디자인이 없어 [디자인 확인 필요](../figma-ui-alignment-plan.md#figma-pending-link-slow)에 기록만 한다.
- 2026-11-10 "추천대로": 공용 저장 안내창(`SaveErrorToast`)의 최대 줄 수만 2에서 3으로 늘린다. 문구·폭·글꼴·색은 그대로다.
  기존 '외형 유지' 결정과 달라진 점은 [디자이너 확인 항목](../figma-ui-alignment-plan.md#figma-pending-toast-lines)으로 남겼다(구현 보류 아님).
- 2026-11-09 "2. 승인": 촬영의 iOS LT-05 주소 입력만 화면 키보드 OS 탭으로 한다. 다른 상태와 Android는 `orca emulator type`.
  iOS 키보드 설정을 촬영 동안 0으로 바꾸고 끝나면 원래값 1로 되돌리는 것도 사용자 승인으로 했다.

## 구현 (`2290275`)

- `ContentActions.saveLink`: `ApiRequestScope(timeout: 20초)`를 저장 요청 시작에 만들고 세션 확인·`content.saveLink`(API 요청·401 갱신·재전송)를 그 안에서 기다린다.
  API의 `_sendWithSessionRetry`와 인증 갱신 합류가 같은 scope를 써서 시간 초과 때 요청을 끊고 늦은 응답을 버린다.
  시간 초과는 사진과 같은 지연 문구의 `ClipbackApiException`으로 바꿔 기존 시트 실패 토스트 경로를 그대로 쓴다.
- 목록 반영·상세 열기(`onSaved`)·목록 새로고침은 scope 밖이라 제한 시간 안에 응답이 끝났을 때만 실행된다. 새로고침은 제한에 넣지 않았다.
  시트를 닫아도 링크 scope는 취소하지 않으므로 제한 시간 안의 응답은 지금처럼 상세를 연다(G2).
- 같은 화면 재저장은 기존 `ContentSaveSubmission`이 같은 키를 쓴다. 자동 재시도는 없다. 사진 저장의 전송·응답 각 10초는 바꾸지 않았다.
- `SaveErrorToast` `maxLines` 2 → 3(링크·사진 공통). 3줄이 필요할 때만 한 줄 높아진다.
- 문서: [프론트 동작](../frontend/behavior.md#콘텐츠-저장과-자동-분류), [Figma 맞춤 계획](../figma-ui-alignment-plan.md#링크-저장-제한-시간-319)(새 절·디자인 확인 필요 3행), CHANGELOG 미배포 수정.

### 실패·재시도

- 변경 전 iOS: 처음에 키보드 최소화 설정(1) 충돌로 멈췄다. 승인 뒤 0으로 바꿔 LT-01–LT-04·영상을 찍었으나 LT-05 첫 시도는 키보드 인셋 0으로 실패했다.

- 변경 전 Android LT-05: 입력 직후 완료 키가 빨라 주소가 `https`만 들어간 첫 실패를 보존하고, 전체 주소 확인을 완료 키 앞에 더해 통과했다.
- 변경 후 iOS LT-05: 첫 시도는 POST 뒤 25.187초에 토스트가 이미 사라져 실패로 남겼다. 촬영 진입 파일의 `/probe` 인위 대기 `_settle(8)`만 빼고
  (`/scale` 대기는 유지, 제품 변경 없음) 빌드 전 확인 13개 + tap_probe 5개 통과 뒤 다시 빌드해 찍었다.
- 변경 후 Android: 첫 설치는 준비 확인 30초를 넘겨(부팅 41.643초) 실패했고 부팅 뒤 재설치했다.
  LT-05 첫 촬영은 종료 코드 141(앞 창 확인 awk의 조기 종료가 pipefail 아래 adb SIGPIPE)로 실패해 로컬 촬영 스크립트가 출력을 끝까지 읽게 고쳤다.
