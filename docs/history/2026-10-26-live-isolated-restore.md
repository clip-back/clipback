## 변경과 경계

점검 전에 입력 권한·복구 지점·로컬 이미지·디스크·연결을 확인하고 저장소 밖의 실행 소유 폴더에
필요한 사본만 준비한다. 실제 점검 run·세대·복원 작업과 직접 DB 연결의 동일성을 확인하고 삭제 기록
shared lock을 유지한 채 별도 프로세스로 기존 Docker 복원 도구를 실행한다.

시간 초과·제어/DB 연결 단절은 실패로 고정한다. 자식 프로세스 그룹과 Docker 데몬 자원의 종료,
잠금 해제·서버 기록 종료를 확인하고 임시 사본을 정리한다. 판단이 불명확하면 journal과 영속 복원
기록을 유지한다. 복원 등록 응답 유실도 권위 있는 서버 상태와 조합하여 복구한다. 서비스 재개는 항상 별도 명시 명령이다.

실제 Docker 복원을 통해 API 이미지에 직렬화된 검증 코드의 import 대상이 빠진 것을 발견해
검증 모듈 패키징을 보완했다. 자식 강제 종료가 남길 수 있는 임시 인증 파일은 실행 소유 폴더 안에
두도록 수정했다. 실제 PostgreSQL에서 다른 DB 터널로 연결해도 이전 코드가 복원을 통과하는 RED를
재현한 뒤, 같은 점검·작업 기록 검증으로 차단했다.

## 검증 기록

공개 CLI의 자격 파일·저장소 내부 폴더 거절, 단순 쓰기 중단 확인 인자의 운영 우회 거절을 RED/GREEN으로
확인했다. 실제 PostgreSQL 18·비공개 HTTP 제어·자식 프로세스·Docker 데몬으로 정상 복원, 전체 시간 초과,
제어 연결 상실, 등록 응답 유실 복구, Docker 정리 실패·재개 차단, DB 잠금 연결 종료, 잘못된 DB 터널을 확인한다.
기존 다중 계정의 삭제 반영·원본 재열람 회귀와 합성 백업·오프라인 복원 호환 검사를 함께 수행한다.

실제 실행 수·최종 결과와 선택형 검사는 통합 검증 이력에 연결하며 실행하지 않은 실제 Railway·Mac SSH
접속·사용자 데이터 복원·배포를 통과했다고 표시하지 않는다. 이번 시험은 합성 데이터와 로컬 Docker를 사용했다.
대용량 사진·영상 대신 비밀값 없는 작은 보고서를 남겼으며 이번 실패 재현으로 생긴 것으로 확인된
합성 임시 인증 폴더도 정리했다. 사용자 입력 다운로드·인증 파일과 운영 원본·백업은 정리 대상이 아니다.
