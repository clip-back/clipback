# 긴 요약 표시 검사와 화면 촬영 (#456)

2026-11-22, 시작 커밋 `419cd1e`의 앱과 백엔드로 요약이 최대 1,000자로 길어져도 배포된 앱 화면이 깨지지 않는지 확인했습니다. 앱 코드와 앱 테스트는 바꾸지 않았습니다(`git diff --stat 419cd1e -- frontend` 비어 있음). 앱 화면이 바뀌지 않으므로 변경 전·변경 후·Figma 3장 비교는 하지 않았습니다.

## 1,000자 표시 검사 (자동, 커밋하지 않은 로컬 위젯 테스트)

- 합성 요약은 서버의 요약 연결 형식과 같게 핵심 한 줄 40자와 `• ` 요점 10개(각 93자)를 줄바꿈으로 이은 1,000자입니다. 서버 연결 단계에는 요점별 길이 상한이 없어 80자를 넘는 요점으로 잡았습니다.
- 메모리 대역 API의 가장 최근 링크 콘텐츠에 이 요약을 넣고 실제 루트 앱을 띄웠습니다. 글꼴은 앱 자산 Pretendard를 올렸습니다. 세 위치의 요약 글자는 모두 Pretendard를 직접 지정하고(`inherit: false`) 테마를 물려받지 않습니다.
- OS 글자 배율 1.0·1.3, 화면 iPhone 16(393×852)·Medium_Phone(411.43×914.29)에서 장면·배율·화면마다 테스트를 따로 두어 12건과 합성 요약 형태 검사 1건, 모두 13건이 통과했습니다. 넘침 오류는 0건이었습니다.

## 기기 촬영 (로컬 백엔드, 실제 HTTP)

- 서버: `419cd1e`의 backend를 로컬 PostgreSQL 17(Alembic head `202611170023`)과 함께 띄웠습니다. AI·외부 키 없이 실행했고 유튜브·인스타그램 자동 요약은 꺼 두었습니다. 실제 모델 호출은 0회입니다.
- 데이터: 로컬 게스트 계정에 #455의 가장 긴 실제 요약(유튜브 R2, `gemini-3.5-flash-lite`, 요약 458자·9줄, 제목 19자)을 직접 입력한 링크 콘텐츠 1건을 저장했습니다(HTTP 201, 상태 `not_requested`). 다시 조회한 제목·요약이 원본과 같았습니다.
- 앱: 촬영용 진입 파일(저장소 밖)이 앱의 `/api/v1` 요청만 로컬 서버로 실제 HTTP로 넘기고, 다른 호스트·API 밖 경로·리다이렉트는 거부합니다. 실제 HTTP를 쓰는 진입 파일이라 빌드 전 위젯 확인은 건너뛰었고, 대신 로컬 서버에 대한 전달 확인 5건(전달·요약 해시 일치·다른 호스트 거부·경로 거부·비2xx 기록)이 통과했습니다.
- 받은 데이터 대조: 두 플랫폼 모두 앱이 받은 요약은 458자이고 SHA-256 앞 16자리 `edafb36e2e5683de`로 원본과 같았습니다. 앱 요청은 플랫폼마다 홈 촬영 실행 6건(촬영 도구가 사진을 찍고 앱을 종료함)과 다시 띄운 상세·아카이브 촬영 실행 10건, 합계 16건이며 모두 2xx, 거부·실패 0건이었습니다. 서버 접근 기록에서도 플랫폼마다 같은 16건이 모두 2xx로 남았습니다. 이 수에는 콘텐츠 저장, 별도 전달 확인, 서버가 떠 있는지 손으로 본 요청을 넣지 않았습니다.
