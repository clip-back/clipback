# 카테고리 자동 추천 정책 및 구현 상태

2026-09-21 로컬 코드 대조 기준. 링크·스크린샷 추천과 카테고리 개인화는 구현되어 있다. 운영 공급자 품질과 실기기 검증은 별도다.

## 1. 문서 목적

허투루에 저장되는 콘텐츠를 AI가 사용 가능한 카테고리 안에서 자동으로 분류하는 정책과 백엔드 구현 범위를 정의한다.

이 정책의 목표는 저장 과정의 입력 부담을 줄이면서도 콘텐츠가 분류되지 않은 채 방치되는 것을 방지하는 것이다. AI가 적절한 카테고리를 찾지 못하거나 추천 과정에 실패하더라도 콘텐츠 저장은 중단하지 않고 `미분류` 카테고리에 할당한다.

## 2. MVP 정책 요약

1. AI는 서비스 기본 카테고리와 현재 사용자가 만든 카테고리만 추천 후보로 사용한다.
2. `미분류`는 일반 추천 후보에서 제외하고 fallback 용도로만 사용한다.
3. AI는 MVP에서 콘텐츠당 카테고리 1개를 추천한다.
4. 사용자가 카테고리를 직접 지정했다면 사용자 선택을 AI 추천보다 우선한다.
5. 적합한 후보가 없거나 추천이 실패하면 `미분류`를 할당한다.
6. AI는 새로운 카테고리를 자동으로 생성하지 않는다.
7. 추천 실패 때문에 콘텐츠 저장 자체가 실패해서는 안 된다.

현재 데이터 모델은 콘텐츠에 여러 카테고리를 연결할 수 있지만, 자동 추천 정책은 MVP에서 1개 할당을 기준으로 한다. 복수 카테고리 추천은 실제 사용성과 정확도를 확인한 뒤 후속 검토한다.

## 3. 카테고리 구분

### 3.1 기본 카테고리

- 가입 시 사용자마다 복사되는 서비스 제공 카테고리이며, 본인만 수정·삭제할 수 있다.
- 사용 가능한 기본 카테고리는 `user_id`가 현재 사용자 ID이고 `is_default`가 `true`이다.
- `user_id=NULL`인 원본은 가입용 템플릿으로만 유지하며 추천·선택 대상에서 제외한다.
- 삭제한 기본 카테고리는 재로그인 또는 소셜 계정 전환 시 다시 생성하지 않는다.
- 현재 기본 카테고리는 취업, 공부, 업무 팁, 생활 꿀팁, 장소, 제품 추천이다.

### 3.2 사용자 카테고리

- 사용자가 직접 생성한 개인 카테고리이다.
- 해당 사용자의 콘텐츠에만 추천하고 할당할 수 있다.
- 다른 사용자가 만든 카테고리는 후보에 포함하거나 할당해서는 안 된다.

### 3.3 미분류 카테고리

- 서비스가 제공하는 전역 기본 카테고리이다.
- AI가 적합한 후보를 찾지 못했을 때 사용하는 fallback이다.
- 일반 추천 후보 목록에서는 제외한다.
- 이름은 `미분류`, `user_id`는 `NULL`, `is_default`는 `true`인 레코드를 사용한다.

## 4. 추천 대상과 우선순위

### 4.1 추천 후보

추천 시점의 후보 목록은 다음 두 집합을 합친 결과이다.

- 현재 사용자가 소유한 기본 카테고리
- 현재 사용자가 만든 카테고리

AI 응답은 후보 목록에 포함된 카테고리 ID 또는 `null` 중 하나여야 한다. 후보 밖의 카테고리 ID나 이름을 반환한 응답은 유효하지 않은 것으로 처리한다.

### 4.2 사용자 선택 우선

저장 요청에 사용자가 직접 선택한 유효한 `category_ids`가 포함되어 있으면 AI 추천을 실행하지 않고 해당 선택을 사용한다.

MVP 자동 추천은 1개 카테고리를 기준으로 하지만, 기존 API와의 호환을 위해 사용자 직접 선택은 현재의 `category_ids` 형식을 유지한다. 사용자가 지정한 카테고리의 소유권과 접근 가능 여부는 기존과 동일하게 검증한다.

### 4.3 자동 추천

저장 요청의 `category_ids`가 비어 있으면 AI 추천을 실행한다.

1. 현재 사용자가 이용 가능한 추천 후보를 조회한다.
2. 콘텐츠에서 추천 입력 텍스트를 구성한다.
3. 후보 카테고리의 ID와 이름을 AI에 전달한다.
4. AI가 후보 중 하나를 반환하면 해당 카테고리를 할당한다.
5. AI가 `null`을 반환하거나 결과가 유효하지 않으면 `미분류`를 할당한다.

## 5. 추천 입력

추천에는 저장 과정에서 확보할 수 있는 다음 정보를 사용한다.

우선순위는 다음과 같다.

1. 추출된 콘텐츠 제목
2. 추출된 설명 또는 요약
3. 공유된 원문 텍스트
4. 출처 플랫폼
5. 원본 URL

공유 원문 텍스트는 추천 처리 중에만 사용하고 현재 개인정보 처리 원칙에 따라 그대로 저장하지 않는다.

링크에서 제목이나 설명을 추출하지 못하고 공유 원문에도 분류할 정보가 충분하지 않다면 AI가 임의로 추측하지 않고 `null`을 반환하도록 한다.

스크린샷은 구현된 OpenAI OCR의 제목·요약·추출 텍스트를 추천에 사용한다. OCR 실패·텍스트 부재 시 fallback을 적용하되 유효한 사용자 직접 선택은 유지한다.

## 6. fallback 조건

다음 중 하나라도 해당하면 `미분류`를 할당한다.

- 이용 가능한 추천 후보가 없다.
- 콘텐츠에서 추천에 사용할 텍스트를 확보하지 못했다.
- AI가 적합한 카테고리가 없다고 판단해 `null`을 반환했다.
- AI가 후보 목록에 없는 카테고리를 반환했다.
- AI 응답 형식이 올바르지 않다.
- AI 호출이 timeout 또는 오류로 실패했다.
- 추천 결과 카테고리가 저장 시점에 삭제되었거나 접근 불가능해졌다.

fallback은 정상적인 저장 결과이며 API 오류로 취급하지 않는다.

`미분류` 카테고리 자체가 DB에 없다면 시스템 설정 오류이므로 저장을 실패시키고 운영 로그를 남긴다. 이 경우 임의의 카테고리를 대신 선택하지 않는다.

## 7. 저장 처리 흐름

### 7.1 링크 공유 및 직접 입력

1. URL을 검증하고 정규화한다.
2. 링크에서 제목과 설명을 추출한다.
3. 사용자가 직접 선택한 카테고리가 있는지 확인한다.
4. 사용자 선택이 없으면 AI 추천을 실행한다.
5. 추천 성공 시 해당 카테고리를, 실패 시 `미분류`를 할당한다.
6. 콘텐츠와 생성 이벤트를 하나의 트랜잭션으로 저장한다.

MVP에서는 저장 요청 안에서 추천을 처리한다. 외부 호출에는 timeout을 적용하고 실패 시 즉시 `미분류`로 전환하여 저장 완료가 과도하게 지연되지 않도록 한다.

### 7.2 스크린샷

1. 이미지 형식·크기를 검증하고 OCR에서 텍스트·제목·요약을 추출한다.
2. 이미지 파일을 저장한다.
3. 사용자 직접 선택을 우선하며 선택이 없으면 동일한 AI 추천 절차를 적용한 뒤 콘텐츠·자산·이벤트를 저장한다. DB 저장 실패 시 이미 쓴 파일을 제거한다.
4. OCR 실패는 기본 콘텐츠로 저장하며 추천 입력이 없으면 미분류로 처리한다.

## 8. API 정책

기존 요청 필드인 `category_ids`를 유지한다.

| 요청 상태 | 처리 방식 |
| --- | --- |
| 유효한 `category_ids`가 있음 | 사용자 직접 선택으로 저장하고 AI 추천 생략 |
| `category_ids`가 빈 배열 | AI 자동 추천 실행 |
| AI가 유효한 후보를 반환 | 추천 카테고리로 저장 |
| 적합한 후보 없음 또는 AI 실패 | `미분류`로 저장 |
| 접근할 수 없는 카테고리 ID가 포함됨 | 기존 정책대로 요청 오류 반환 |

응답은 기존 `ContentRead.categories`를 통해 최종 할당된 카테고리를 반환한다. MVP에서는 별도의 추천 결과 응답 모델을 추가하지 않는다.

## 9. AI 연동 계약

AI에는 자연어 카테고리 이름만 반환하게 하지 않고, 후보 ID와 이름을 함께 전달한 뒤 아래와 같은 구조화된 결과를 받는다.

```json
{
  "category_id": 3
}
```

적합한 후보가 없으면 다음과 같이 반환한다.

```json
{
  "category_id": null
}
```

백엔드는 AI 응답을 신뢰하지 않고 반환된 ID가 현재 사용자의 후보 목록에 포함되는지 다시 검증한다.

AI에게 전달하는 핵심 지침은 다음과 같다.

- 반드시 제공된 후보 중 하나만 선택한다.
- 새로운 카테고리 이름을 만들지 않는다.
- 억지로 가장 가까운 후보를 고르지 않는다.
- 분류 근거가 부족하거나 적합한 후보가 없으면 `null`을 반환한다.

## 10. 기록과 측정

콘텐츠 생성 이벤트의 메타데이터에 다음 값을 기록한다.

- 카테고리 할당 방식: `user`, `ai`, `uncategorized`
- AI가 선택한 카테고리 ID 또는 `null`
- 추천 실패 사유: `no_match`, `insufficient_input`, `timeout`, `invalid_response`, `error`

공유 원문이나 AI 프롬프트 전체는 이벤트 메타데이터에 저장하지 않는다.

후속 분석에서는 다음 지표를 확인한다.

- AI 추천 카테고리 유지율
- 사용자가 추천 카테고리를 변경한 비율
- `미분류` 할당 비율
- 기본 카테고리와 사용자 카테고리의 추천 비중
- 추천 방식별 콘텐츠 재열람률

카테고리 변경 API와 전후 ID 이벤트 기록은 구현되어 있다. 유지율·변경률의 집계 기간과 정의, 분석 화면은 별도 합의가 필요하다.

## 11. 구현 설정과 검증 범위

링크·스크린샷 추천, 개인화 카테고리 수정·삭제, 분류 변경 이벤트 기록이 구현되어 있다.

- 기본 모델: `gpt-5.4-nano-2026-03-17`
- 호출 방식: 비동기 OpenAI Responses API와 Pydantic Structured Outputs
- 기본 제한: timeout 2초, 재시도 없음, reasoning effort `none`, 최대 출력 64토큰, `store=false`
- 검증 대상: 직접 선택 우선, 정상 추천, fallback, 타인 카테고리 차단, 추천 도중 후보 삭제, 미분류 누락 오류
- 회귀 대상: 링크·Instagram 공유·스크린샷 저장, 피드 필터와 상세 조회

설정과 테스트 코드는 저장소 기준이며 실제 운영 설정·공급자 품질을 보장하지 않는다.
이번 문서 정리에서는 테스트나 실제 공급자 호출을 재실행하지 않았다.

진행 현황과 후속 범위는 [MVP 현황](backend-mvp-plan.md), 수정·삭제 API 계약은
[백엔드 README](../backend/README.md), 지표 정의는
[제품 지표 문서](product-metrics-queries.md)를 참고한다.

## 12. 후속 검토

- 콘텐츠당 복수 카테고리 자동 추천 여부
- 현재 자동 저장 후 수정 방식을 저장 전 확인 방식으로 변경할 필요가 있는지
- 추천 신뢰도 점수를 별도로 저장할지 여부
- 비동기 추천과 저장 후 카테고리 갱신 방식 도입 여부
- 사용자 카테고리 설명이나 예시를 추천 입력에 추가할지 여부
