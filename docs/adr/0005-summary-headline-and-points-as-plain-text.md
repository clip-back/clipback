# 자동 요약은 모델에게서 핵심 한 줄과 요점을 따로 받아 서버가 평문 요약 하나로 합친다

유튜브·인스타그램 자동 요약은 모델의 구조화 출력에서 요약을 핵심 한 줄과 요점 목록(1–5개)으로 따로 받고,
서버가 "핵심 한 줄, 줄바꿈, `• 요점` 줄들"의 평문으로 합쳐 기존 `summary` 문자열에 저장한다. API 응답은 바꾸지 않는다.
운영 요약이 명사형 조각을 한 문단에 이어 붙인 모양이라 읽기 어렵다는 0.3.0 실기기 보고(2026-11-03)에 따라
2026-11-03 회의에서 합의했으며, 구현·배포 완료를 뜻하지 않는다.

모양을 모델에 맡기지 않고 서버가 합치는 이유는 글머리 기호·줄바꿈·요점 수를 서버가 늘 같게 만들고 검사할 수 있어서다.
API를 그대로 두는 이유는 이미 배포된 앱(iOS 0.3.0(8), Android 0.3.0(4))이 새 빌드 없이 줄바꿈을 그대로 그려
서버 배포만으로 적용되고, 목록 모양의 디자인이 아직 없어서다.

## 검토한 대안

- **프롬프트로만 평문 모양을 지시**: 바꿀 곳은 가장 적지만 모델이 기호를 빼거나 마크다운을 섞는 등 모양이 흔들리고,
  서버가 형식을 검사하기 어렵다.
- **API에 핵심 한 줄·요점 필드를 따로 내려주기**: 앱이 목록을 제대로 그릴 수 있지만 앱 모델·화면 변경과 새 빌드 배포가 필요하고,
  그릴 디자인이 없다. 디자인이 확정되어 앱이 목록 모양을 그리게 되면 이 대안을 다시 검토한다.

## 결과

- 앱은 요약을 일반 글자로 그리므로, 두 줄 이상인 요점의 다음 줄은 글머리 기호 아래로 들여쓰기 되지 않는다.
  목록 모양(내어쓰기·요점 간격·카드 표시)은 디자인 확인 필요로 남긴다.
- 이미 저장된 요약은 다시 요약하지 않는다. 배포 뒤 저장한 링크부터 새 모양이며 옛 모양과 섞여 보인다.
- 사용자가 직접 입력한 요약은 이 모양을 따르지 않으므로, 앱은 요약 문자열이 늘 이 모양이라고 가정하지 않는다.
