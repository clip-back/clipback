# 회원 탈퇴는 즉시 삭제하고, 공급자 철회 실패와 무관하게 진행하며, 복원 때 다시 지운다

회원 탈퇴는 유예 기간 없이 요청이 성공한 자리에서 계정과 그 계정의 서비스 데이터를 지운다.
유예를 두면 "탈퇴 대기" 상태, 예약 삭제 작업, 복구 화면이 새로 필요하고, 스토어 정책도 즉시 삭제를
문제 삼지 않기 때문이다. 실수 방지는 탈퇴 화면(사유 선택 필수)으로 대신한다.

삭제 전에 Apple 토큰 철회와 카카오 연결 끊기를 먼저 시도하되, 실패해도 데이터 삭제는 끝까지 진행하고
실패는 서버 로그로만 남긴다. 철회 실패로 탈퇴를 막으면 Apple 키 설정 하나가 틀려도 모든 사용자의 탈퇴가
막히고, Apple 기술 문서(TN3194)도 토큰이 없어도 삭제는 해야 한다고 한다. 철회를 DB 삭제보다 먼저 하는 이유는
DB를 먼저 지우면 저장된 Apple 토큰도 함께 사라져 철회할 수 없기 때문이다. 그래서 철회 뒤 DB 삭제가 실패하면
공급자 연결만 끊긴 채 계정이 남을 수 있고, 이 결과는 되돌리지 않는다(데이터는 그대로라 다시 시도하면 된다).

백업(복구 지점)은 탈퇴 때 손대지 않고 최대 7일 보존 정리에 맡긴다. 대신 이미지 삭제에 쓰는 삭제 장부에
"계정 탈퇴" 기록(계정 번호만)을 남기고, 복원할 때 그 계정 전체를 다시 지운다. 지금 장부는 이미지가 있는
콘텐츠 삭제만 기록하므로, 이것이 없으면 7일 안의 복원이 탈퇴한 계정과 링크 콘텐츠를 되살린다.
장부 기록은 복원 시 재삭제를 위해 계속 보관한다.

2026-11-06 설계 인터뷰에서 합의했으며, 구현 완료를 뜻하지 않는다.

## 검토한 대안

- **유예 기간(7일·30일) 뒤 삭제**: 실수로 탈퇴해도 되살릴 수 있지만, 위의 상태·작업·화면이 늘고
  복구 화면 디자인도 없다.
- **철회 실패 시 탈퇴 전체 중단**: "연결은 끊겼는데 계정이 남는" 경우는 줄지만, 공급자 장애나 설정 오류가
  탈퇴 자체를 막는다.
- **백업은 자연 소멸에만 맡기고 복원 때 운영자가 수동 처리**: 구현은 없지만, 수동 처리에도 누가 탈퇴했는지
  기록이 필요하고 "삭제 뒤 복구·재생되지 않도록 관리"하라는 개인정보 기준을 사람 기억에 맡기게 된다.
