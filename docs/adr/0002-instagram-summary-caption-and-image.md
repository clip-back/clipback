# 인스타그램 자동 요약은 공개 페이지의 캡션과 대표 이미지만 GPT로 분석한다

인스타그램 릴스·게시물의 자동 요약은 공개 게시물 페이지의 메타데이터가 제공하는 캡션과 대표 이미지 1장만
요약 근거로 쓴다. 분석은 OpenAI GPT로 한다. 영상·음성은 내려받거나 분석하지 않는다. 캐러셀의 대표 이미지가
몇 번째 장인지는 보장하지 않는다. 그래서 릴스 요약을 영상 요약이라고 부르지 않는다.
공유할 때 받은 텍스트는 요약 입력으로 쓰지 않는다. 비동기 요약에 쓰려면 DB에 임시로 보관해야 하는데,
기능 중지와 백업 때문에 보관 기간을 통제하기 어렵고, 인스타그램 앱이 URL 외 텍스트를 넘기는지도 확인되지 않았다.
2026-10-31 설계 인터뷰 Q7·Q13~Q15·Q19와 명세 검토 R1·R4에서 합의했으며, 구현·배포 완료를 뜻하지 않는다.

## 배경과 선택 이유

2026-10-31 조사([정리](../research/2026-10-31-instagram-summary-sources.md))에 따르면,
타인의 게시물 내용을 URL로 가져올 수 있으면서 약관상 문제없는 공식 경로는 없다.
Basic Display API는 종료됐고, 현재 API는 username 기준 Business Discovery로만 타 계정을 조회할 수 있으며,
oEmbed는 캡션을 주지 않고 임베드 표시 외 용도를 금지한다.
공개 페이지 메타데이터 수집은 인스타그램 이용약관의 자동 수집 금지에 해당할 소지가 있다.
그러나 서비스는 이미 저장 시점에 같은 메타데이터를 수집하고 있어, 이 방식이 새로 늘리는 위험이 가장 작다.
이 위험을 알고 받아들이는 대신, 원본 캡션·이미지는 보관하지 않고(OpenAI에도 보관하지 않도록 요청한다),
유튜브와 별도인 스위치를 기본값 꺼짐으로 두어 언제든 인스타그램 요약만 중단할 수 있게 한다.

GPT를 쓰는 이유는 다음과 같다. Gemini의 장점인 유튜브 URL 직접 분석이 인스타그램에는 해당하지 않는다.
또한 이미지·텍스트 분석은 이미 운영 중인 OpenAI 연동(스크린샷 OCR·카테고리 추천)과 키를 재사용할 수 있다.
요약 모델은 카테고리 추천과 별도로 설정할 수 있게 한다.

## 검토한 대안

- 영상 내려받기 후 분석: 요약 근거는 가장 풍부하지만, 자동 수집 금지와 다운로드 보호 우회에 해당할 소지가
  가장 크다. 최신 릴스와 저작권 음원 릴스는 영상 주소가 없는 경우가 많아 안정성도 낮다.
- 공식 API(Business Discovery): 약관 위험은 낮지만, URL로 게시물을 찾을 수 없고 개인 계정을 다루지 못한다.
- 공유 시트 텍스트만 사용: 위험은 없지만 대부분 URL만 넘어와 요약할 내용이 거의 없을 것으로 본다.
  실기기에서 캡션이 함께 넘어오는 것이 확인되면 보관 기간 규칙과 함께 다시 검토한다.
- 보류: 기능 가치를 포기하는 선택이라 채택하지 않았다.

## 재검토 조건

인스타그램이 서버 요청을 차단하거나, 약관 변경(2027-01-20 시행 예정 개정 포함)이나 권리자 요청이 있으면
스위치로 중단하고 이 결정을 다시 검토한다.
