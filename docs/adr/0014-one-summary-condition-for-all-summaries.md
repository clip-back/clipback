# 유튜브·인스타그램 자동 요약과 사진 요약은 하나의 요약 조건을 함께 쓴다

같은 작성자가 같은 내용을 유튜브와 인스타그램에 올렸는데 두 요약의 자세함과 제목이 크게 달랐고(팀 피드백 시트 135),
레시피 요약은 재료와 순서를 빠뜨렸다(시트 136). 2026-11-21 회의에서 사용자는 "모든 요약이 일관된 게 중요하다"며
사진(OCR) 요약까지 같은 조건을 쓰기로 정했다. 그래서 요약 지시(문체, 핵심 한 줄·요점의 목표 길이와 개수, 레시피 같은 순서 안내에서는
재료와 단계를 빠뜨리지 않는다는 지시)를 한국어 문장 하나로 한 곳에 두고 세 요약이 함께 쓴다. 서버의 정리·상한 처리(요점 앞 10개,
합친 요약 1,000자, 넘치면 맨 뒤 요점부터 빼기)도 같은 함수를 쓴다. 종류마다 다른 것은 무엇을 근거로 보는지 설명하는 문장뿐이다.
[ADR 0005](0005-summary-headline-and-points-as-plain-text.md)의 "핵심 한 줄과 요점을 서버가 평문 하나로 합친다"는 그대로 유지한다.
구현·배포 완료를 뜻하지 않는다.

## 일부러 남긴 차이

- 사진은 글이 짧으면 요점 0개를 허용한다. 링크는 최소 1개다. 억지로 요점을 지어내지 않게 하려는 것이다.
- 사진 요약은 저장 중에 만들어지므로 요약이 잘못돼도 저장을 막지 않는다. 그래서 제목이 120자를 넘으면 자르고, 핵심 한 줄이 비면
  기본 문구를 쓴다. 링크는 이런 경우 요약만 실패한다.

## 결과

- 사진 요약도 길어지므로, 사진을 저장할 때 기다리는 시간이 늘고 시간 제한(운영 15초)에 걸릴 수 있다. 실제 모델 표본에서
  걸린 시간을 재고, 시간 초과가 나오면 시간 제한을 늘릴지, 사진만 숫자를 줄일지(이 결정의 예외)를 그때 정한다.
- 한 종류의 프롬프트를 고치면 다른 종류의 요약도 함께 바뀐다. 실제 모델 확인도 세 종류를 함께 해야 한다.
- 이미 저장된 요약은 다시 만들지 않는다. 배포 뒤 새로 저장한 것부터 새 조건을 따른다.
