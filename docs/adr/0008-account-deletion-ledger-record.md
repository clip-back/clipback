# 계정 탈퇴는 삭제 장부에 한 건으로 기록하고, 계정 번호와 생성 시각이 맞을 때만 다시 지운다

[0007](0007-account-deletion-immediate-and-replayed.md)은 탈퇴 때 삭제 장부에 "계정 탈퇴" 기록을 계정 번호만으로 남기고,
복원할 때 그 계정을 다시 지운다고 정했다. 이 결정은 그 기록의 내용과 방식을 넓힌다.

- 기록에 계정 생성 시각을 함께 넣고, 계정 번호와 생성 시각이 둘 다 맞는 계정만 지운다. 이메일·이름은 넣지 않는다.
  복원하면 계정 번호 순번도 백업 시점으로 돌아가므로, 복원 뒤 새로 가입한 사람이 탈퇴한 계정과 같은 번호를 받을 수 있다.
  번호만 맞추면 다음 복원 때 옛 탈퇴 기록이 그 사람의 계정을 지운다. 이미지 삭제 기록이 저장 시각으로 같은 문제를 막는 것과 같은 방식이다.
- 탈퇴 한 번에 장부 기록 하나만 쓰고, 그 안에 그 계정 이미지 콘텐츠들의 기존 삭제 정보(콘텐츠 번호·저장 시각·원본 위치·해시)를 묶는다.
  지금처럼 이미지 콘텐츠마다 장부를 따로 쓰면 콘텐츠당 장부 저장소를 십여 번 읽고 써야 해서, 이미지가 수백 개인 계정은
  탈퇴 요청 하나가 수십 초에서 수 분 걸릴 수 있다(추정). DB 삭제, 원본 정리 작업, Bucket 원본 삭제는 기존 이미지 삭제와 같다.
- 장부 기록 뒤 DB 삭제가 실패하면 그 기록을 확정된 탈퇴 요청으로 본다. 그 순간 응답은 실패이고 계정은 남지만,
  사용자가 다시 시도하면 같은 기록을 재사용하고, 운영자 재시도 명령과 복원은 남은 계정을 마저 지운다.
  기록을 DB 삭제 뒤에 쓰면 반대로 계정은 지워졌는데 기록이 없어 복원 때 되살아날 수 있다.

새 기록은 기존 장부의 같은 순번 체인에 새 종류로 들어간다. 이 기능 이전 서버는 이 기록을 읽지 못해 이미지 삭제와 백업이
장부 검증에서 멈추므로, 탈퇴가 한 번이라도 일어난 뒤에는 이 기능 이전 서버로 되돌리지 않는다. 이 비용을 받아들인다.
되돌리기가 필요하면 이 기능을 끈 새 버전을 앞으로 배포한다.

이 기능 이전에 만든 복구 지점의 복원은 계속 지원한다. 복원 때 삭제 기록 반영은 백업 시점의 옛 API 이미지 안에서 현재 반영 소스로
돌기 때문에([0004](0004-recovery-point-manifest-single-standard.md)), 반영 소스는 계정 탈퇴 기록을 옛 이미지의 장부 검증이나
새 모듈 없이 스스로 처리한다.

2026-11-06 스펙 작성 중 사용자 결정("탈퇴 스펙 : 모두 추천대로")과 스펙 리뷰 결정("추천대로")으로 합의했으며,
구현 완료를 뜻하지 않는다.

## 검토한 대안

- **계정 번호만 기록하기(0007 문구 그대로)**: 기록이 가장 작지만, 위의 번호 재사용 때 다른 사람의 계정을 지울 수 있다.
- **이미지 콘텐츠마다 장부를 쓰고 계정 기록을 따로 하나 더 쓰기**: 기존 이미지 삭제 경로를 그대로 쓰지만, 이미지가 많은 계정은
  탈퇴 요청이 앱 대기 시간 안에 끝나지 않을 수 있다.
- **계정 탈퇴만 별도 장부에 쓰기**: 이 기능 이전 서버가 기존 장부를 계속 읽을 수 있어 되돌리기는 남지만, 백업 manifest와
  복원이 장부 두 개의 시점을 함께 잡고 검증해야 해서 복구 지점 형식(0004)까지 바뀐다.
