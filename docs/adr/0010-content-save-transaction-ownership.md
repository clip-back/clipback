# 콘텐츠 저장의 재시도와 트랜잭션 확정은 한 module이 책임진다

일반 링크·공유 링크·스크린샷 저장의 재시도 준비는 서로 다른 호출부에 있고,
`ContentService._save`가 커밋 시도 상태를 바꾸며 업로드 호출부가 그 상태로 원본 정리 여부를 판단한다.
일반 링크 저장까지 재시도 기록을 사용하게 된 #298 이후, 호출자가 알아야 하는 순서와 가변 상태가
세 저장 경로에 걸쳐 있다. 저장 흐름 module이 잠금·기존 결과 확인·저장 확정·실패 후 원본 정리 판단을
책임지고, 호출자는 입력과 저장 결과만 다루도록 한다. 2026-11-09 구조 회의 Q1–Q4에서 합의했으며,
구현·검증·배포 완료를 뜻하지 않는다.

## 책임과 기존 결정의 관계

- 콘텐츠·이벤트·자동 요약 작업·재시도 기록을 함께 확정하는 저장 트랜잭션의 커밋과 롤백도
  저장 흐름 module이 소유한다. 기존 module은 저장할 내용을 준비하고 DB에 반영하며,
  호출자가 `commit_attempted` 같은 내부 상태를 직접 바꾸거나 해석하지 않는다.
- URL 추출·OCR·파일 저장의 실제 implementation은 기존 module에 두고 호출한다.
  [ADR 0009](0009-content-save-entry-points.md)의 링크·스크린샷별 준비 정책과 사용자 입력 판정은 유지한다.
  이 결정은 저장 트랜잭션 확정의 책임을 추가로 정하며, 조회·수정·삭제의 트랜잭션에는 적용하지 않는다.
- 일반 링크·공유 링크·스크린샷을 함께 다루되, 거절 결과까지 보관하는
  [카테고리 제출 재확인](0001-category-save-retry-results.md)은 통합하지 않는다.

## 보존할 계약

요청·응답·상태 코드·오류·저장 데이터·DB 스키마를 바꾸지 않는다. 같은 제출의 재시도는 과거 응답
스냅샷이 아니라 현재 콘텐츠를 반환하고, 다른 입력과의 키 충돌은 409, 이미 삭제한 콘텐츠는 410을
유지한다. 키 없는 요청의 기존 동작과 각 경로의 입력 검증 순서도 보존한다.

스크린샷은 커밋 결과가 불확실할 때 기존 재확인과 원본 보존 판단을 유지한다. 다른 재시도가 먼저
성공했더라도 실패한 시도의 원본과 성공한 시도의 원본을 구분해야 한다. 원본 정리 판단을 옮기는
과정에서 원본을 잘못 지우거나 고아 파일을 남기지 않는지가 핵심 검증 대상이다.

## 검토한 대안

- **공통 함수만 추출하고 호출부가 순서를 관리하기**: 변경량은 작지만 잠금·커밋·원본 정리의 순서와
  내부 상태를 여러 호출부가 계속 알아야 하므로 locality가 개선되지 않는다.
- **커밋을 기존 콘텐츠 저장 module에 남기기**: 저장 흐름 module이 전체 순서를 책임진다고 해도,
  업로드가 커밋 결과를 별도로 해석하는 책임 분리가 남는다. 저장에 한해 커밋과 롤백도 함께 옮긴다.

기존 HTTP 동작 고정 테스트와 동시성·커밋 응답 유실 테스트를 보존하고, 동일한 고정 테스트로
기준 커밋과 변경 후를 비교한다. 코드 구조에 맞추기 위해 기존 동작의 기대값을 바꾸지 않는다.
